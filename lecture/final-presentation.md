# 15주차: 기말 발표 안내

## 발표 개요

| 항목 | 내용 |
|---|---|
| 주제 | 기말 프로젝트 결과 발표 |
| 발표 시간 | 1인당 5분 (발표 5분 + 질문 별도) |
| 발표 형식 | 슬라이드, Notebook, 코드 실행 화면 중 자유 선택 |
| 평가 비중 | 기말 프로젝트 30% |

## 발표 구성

발표에 포함해야 할 8가지 항목은 다음과 같다.

### 1. 문제 정의 (30초)

- 무엇을 예측하거나 분류하는가.
- 왜 이 문제를 선택했는가.
- 한 문장으로 요약한다.

예시: "음식 사진을 한식, 중식, 양식으로 분류하는 모델을 만들었다."

### 2. 데이터 (30초)

- 데이터가 몇 개인가.
- 어떤 특성이 있는가.
- 합성 데이터인가, 실제 데이터인가.
- 데이터를 어디서 가져왔는가.

다음을 포함한다.

| 항목 | 내 프로젝트 |
|---|---|
| 데이터 수 |  |
| 특성 수 |  |
| 클래스 수 |  |
| 합성/실제 |  |
| 출처 |  |

### 3. 모델 (30초)

- 어떤 모델을 선택했는가 (로지스틱 회귀, MLP, CNN 등).
- 왜 그 모델을 선택했는가.
- 모델의 구조를 간단히 설명한다.

### 4. 결과 (1분)

- 기준선 정확도와 모델 정확도를 함께 보여준다.
- 혼동행렬을 보여주고 어떤 오류가 많은지 설명한다.
- 훈련 정확도와 테스트 정확도를 비교해 과적합 여부를 설명한다.
- 가능하면 데모를 실행해 보여준다.

### 5. 실패 사례 (30초)

- 모델이 틀린 사례를 최소 1개 보여준다.
- 왜 틀렸을지 한 문장으로 설명한다.
- 틀린 사례를 숨기지 않는다.

### 6. AI 활용 (30초)

- 어떤 AI 도구를 사용했는가.
- AI가 도와준 부분은 무엇인가.
- 내가 직접 수정하거나 검증한 부분은 무엇인가.
- AI가 만든 코드 중 이해하지 못한 부분이 있으면 솔직히 말한다.

### 7. 위험 점검 (30초)

다음 중 최소 2개를 점검하고 결과를 보여준다.

| 위험 항목 | 점검 질문 |
|---|---|
| 개인정보 | 데이터에 실제 개인정보가 포함되지 않았는가 |
| 보안 | 코드에 파일 삭제, 외부 전송, 비밀키 노출 위험이 없는가 |
| 편향 | 데이터가 특정 그룹에 편향되지 않았는가 |
| 성능 과장 | 정확도만 보고 모델이 좋다고 단정하지 않았는가 |
| AI 의존성 | AI가 만든 코드를 이해하고 있는가 |
| 출처 | 데이터, 코드, 설명의 출처를 확인했는가 |

### 8. 한계와 개선 방향 (30초)

- 이 모델의 한계는 무엇인가.
- 다음에 시도해 볼 수 있는 개선 방향은 무엇인가.
- 이 모델을 실제 서비스에 바로 쓸 수 있는가. 쓸 수 없다면 왜인가.

## 평가 기준

| 평가 항목 | 비중 | 기준 |
|---|---:|---|
| 실행 가능성 | 20% | 코드가 실행되고 결과를 보여주는가 |
| 결과 해석 | 20% | 정확도, 혼동행렬, 실패 사례를 함께 해석하는가 |
| 개념 연결 | 15% | 딥러닝 개념 2개 이상을 프로젝트와 연결했는가 |
| AI 활용 기록 | 15% | AI 도구 사용 과정을 프롬프트와 함께 기록했는가 |
| 위험 점검 | 15% | 최소 2개 위험을 점검하고 결과를 설명하는가 |
| 발표 구성 | 15% | 8가지 항목을 포함하고 시간을 지켰는가 |

### 감점 대상

- 코드가 실행되지 않는다.
- AI가 만든 코드를 이해하지 못한 채 제출한다.
- 실패 사례가 없다고 주장하거나 숨긴다.
- AI 사용 여부를 기록하지 않는다.
- 출처 없는 설명이나 허구의 참고자료를 사용한다.
- 개인정보, API 키, 비밀번호를 코드나 발표 자료에 포함한다.

### 가산점 대상

- 다른 학생이 따라할 수 있을 정도로 실습 과정이 잘 정리되어 있다.
- AI 답변의 오류를 발견하고 수정한 기록이 있다.
- 모델의 한계를 구체적으로 설명하고, 실제 사용 시나리오를 구분했다.

## 제출물

| 제출물 | 설명 | 제출 시점 |
|---|---|---|
| 최종 코드 | GitHub 저장소 또는 Colab 링크 | 발표 전일까지 |
| 실행 로그 또는 데모 화면 | 코드가 실행되었음을 보여준다 | 발표 전일까지 |
| 발표 자료 | 슬라이드, Notebook, 또는 코드 실행 화면 | 발표 당일 |
| 프로젝트 위험 점검표 | 최소 2개 위험 점검 결과 | 발표 전일까지 |

## 발표 일정

- 발표 순서는 수업 시간에 추첨으로 정한다.
- 5분을 초과하면 발표를 중단할 수 있다.
- 발표 후 질문은 교수자와 학생 모두 할 수 있다.
- 질문에 "모르겠다"고 답해도 감점하지 않는다. 모르는 것을 아는 것도 학습이다.

## 핵심 정리

- 발표 시간은 5분이다. 8가지 항목을 빠짐없이 포함한다.
- 정확도만 보여주는 발표가 아니라, 실패 사례와 한계를 함께 보여주는 발표가 좋은 발표다.
- AI 도구를 사용할 수 있지만, 사용 기록과 검증 과정을 함께 제출한다.
- 위험 점검은 최소 2개 항목을 수행한다.
- 코드가 실행되지 않으면 좋은 점수를 받기 어렵다. 14주차에 반드시 실행을 확인한다.
