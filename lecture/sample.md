# 1장 공간 데이터 과학과 GeoAI, 무엇이 다르고 어떤 결정으로 이어지나

> - 이 장에 나오는 국가 수, 좌표계, 분석 결과 수치는 모두 `lecture_practice/chapter1/`의 코드를 실제로 실행해 얻은 값
> - 예시를 위해 지어낸 숫자는 없음

## 1. 이 장의 핵심 질문

- 위성이나 지도에서 어떤 패턴을 "발견했다"는 것과, 실제로 "어디부터 손댈지 정했다"는 것은 왜 다른 일일까?
- GIS와 GeoAI는 둘 다 공간 데이터를 다루는데, 무엇이 같고 무엇이 다를까?
- 같은 지도를 놓고 시청은 "어디가 위험한가"를 묻고 편의점 본사는 "어디에 낼까"를 물음
- 두 질문은 얼마나 같고 어디서 갈라질까?

- 이 장은 GeoAI를 화려한 최신 기술로 소개하는 장이 아님
- 오히려 정반대
- 먼저 **공간 데이터를 보고 질문하는 기본 틀**이 무엇인지, 그리고 그 틀 위에 AI가 어디에 올라가는지를 차분히 정리하는 장
- 이 순서를 놓치면 뒤의 장에서 나오는 위성영상, 머신러닝, 정책 평가, 입지 분석이 모두 따로 노는 지식이 되기 쉬움

- 핵심은 다음 한 문장으로 요약됨
- **GeoAI는 지도를 더 똑똑하게 보는 기술이지만, 그 가치가 생기는 순간은 결국 누군가의 결정을 바꿀 때**
- 그 결정이 예산 배분이면 공공이고 출점이면 비즈니스인데, 거기까지 가는 계산은 놀랄 만큼 많이 겹침

## 2. 직관적 비유

- **GIS = 공간을 보는 현미경**
- 어디에 무엇이 있는지, 얼마나 떨어져 있는지, 무엇과 무엇이 겹치는지를 확인함
- **GeoAI = 현미경에 자동 패턴 인식 기능을 붙인 것**
- 사람이 규칙을 하나씩 만들지 않아도, 데이터에서 패턴을 스스로 학습함
- **결정 = 현미경으로 본 결과를 바탕으로 실제 행동을 정하는 단계**
- 예산을 어디에 먼저 쓸지, 어느 구역을 우선 점검할지, 어떤 위험을 먼저 알릴지를 정함
- 기업이라면 어느 자리에 매장을 열지, 어디까지 배달할지를 정함

- 이 비유를 더 길게 밀어 보면 GeoAI는 3층 건물처럼 이해할 수 있음

- **1층**: 공간 데이터 과학 기초
- 좌표계, 지도, 거리, 면적, 중첩, 공간 단위, 공간 통계, 공간 ML
- **2층**: GeoAI
- 딥러닝으로 위성영상 분류, 시공간 예측, 패턴 학습
- **3층**: 의사결정
- 공공에서는 우선순위·자원 배분·효과 평가·책임성, 기업에서는 입지 점수·투자 판단·경쟁 검토

- 1층이 없으면 2층은 붕 뜸
- 2층이 있어도 3층으로 올라가지 못하면 "멋진 분석 결과"에서 멈춤
- 이 책은 바로 이 세 층을 함께 보려는 책

- 여기서 미리 알아 둘 것이 하나 있음
- **1층과 2층은 공공이든 기업이든 거의 같음**
- 지역을 어떤 칸으로 나눌지, 그 칸에 어떤 숫자를 붙일지, 예측이 진짜인지 어떻게 확인할지는 시청에서도 프랜차이즈 본사에서도 같은 방식으로 함
- 갈라지는 곳은 3층
- 무엇을 잘못하면 더 아픈지, 결과를 누가 받아 무엇을 결정하는지가 다름
- 이 책 전체가 이 구조를 따라감

## 3. 핵심 개념 5가지

1. **GIS는 소프트웨어 이름이 아니라 공간 의사결정 체계**
   - QGIS나 ArcGIS만 뜻하는 것이 아니라, 데이터를 모으고, 정리하고, 분석하고, 해석하고, 공유하는 전체 흐름을 뜻함
2. **공간 데이터는 서로 다른 모양으로 들어옴**
   - 점·선·면으로 표현되는 벡터, 픽셀 격자로 표현되는 래스터, 3차원 점들의 집합인 포인트 클라우드가 대표 사례
3. **GeoAI는 GIS를 대체하지 않음**
   - GIS 위에 학습 기반 분석을 덧붙이는 방식에 가까움
4. **이름은 여러 개인데 기준은 세 개**
   - 공간 데이터를 다루는 말이 많아 헷갈리지만, 서로 싸우는 말이 아니라 서로 다른 기준으로 붙은 이름(9절)
5. **GeoAI의 목표는 정확도 점수 자체가 아니라, 더 나은 공간 판단**
   - "얼마나 잘 맞혔는가" 못지않게 "그래서 무엇을 결정할 수 있는가"가 중요함

## 5. 실제 사례로 먼저 보기

- `lecture_practice/chapter1/results/1-1-geoai-tools-preview.log`의 실제 실행 결과를 보면, GeoPandas로 Natural Earth 국가 경계 데이터를 읽었을 때 다음이 나옴

- 전체 국가 수: `177`
- 좌표계(CRS): `EPSG:4326`
- 기하 유형: `MultiPolygon`, `Polygon`
- 경계 상자: 경도 `-180.00 ~ 180.00`, 위도 `-90.00 ~ 83.65`

- 또 아시아 국가만 필터링했을 때:

- 아시아 국가 수: `47`
- 데이터 형태: `(177, 169)`
- 메모리 사용량: `356.4 KB`

- 이 숫자들이 중요한 이유는 "멋진 결과"라서가 아님
- 오히려 반대
- GIS 작업은 대개 이렇게 담백한 확인에서 시작함

- 몇 개의 객체가 들어 있는가
- 좌표계는 무엇인가
- 점·선·면 가운데 무엇인가
- 대륙이나 국가 같은 속성이 붙어 있는가

- 즉 1장은 처음부터 "AI 모델 성능"을 보는 장이 아니라, **공간 데이터를 읽는 습관**을 만드는 장

- 실행 로그 마지막에는 아주 중요한 경고도 나옴
- 경위도 좌표계에서 면적을 계산하자, 결과가 부정확할 수 있다는 경고가 발생함
- 이 경고는 뒤의 2장으로 이어짐
- 1장에서는 이 사실만 먼저 기억하면 됨
- **공간 데이터를 읽는 일은 파일을 여는 것과 끝나지 않음**

- 이 결과가 어떻게 나왔는지 감을 잡기 위해, 본문에는 핵심 코드만 먼저 확인함
- 전체 실행 코드는 `lecture_practice/chapter1/code/1-1-geoai-tools-preview.py`에 있음

```python
import geopandas as gpd

url = "https://naciscdn.org/naturalearth/110m/cultural/ne_110m_admin_0_countries.zip"
countries = gpd.read_file(url)

print(len(countries))
print(countries.crs)
print(countries.geom_type.unique().tolist())

asia = countries[countries["CONTINENT"] == "Asia"].copy()
print(len(asia))
print(countries.shape)
print(countries.total_bounds)
```

- 이 짧은 코드에서 읽어야 할 세 가지 핵심

- `gpd.read_file(url)`만으로도 원격 ZIP 안의 벡터 데이터를 바로 읽을 수 있음
- `len(countries)`(행 개수, 즉 국가 몇 개가 들어 있는지), `crs`(좌표계), `geom_type`(점·선·면 중 어떤 기하 유형인지), `total_bounds`(전체 데이터가 차지하는 좌표 범위)를 확인하면 이 데이터가 어떤 공간 객체인지 기본 성격이 드러남
- 아시아만 필터링하는 한 줄은 GIS가 결국 "필요한 공간 범위를 골라 읽는 작업"이라는 점을 보여 줌

- 이 코드의 출력에서 먼저 확인할 세 가지 항목

- 전체 국가 수가 몇 개인지 확인함
- 파일이 실제로 잘 읽혔는지 확인하는 가장 기본적인 신호
- 좌표계가 `EPSG:4326`인지 확인함
- 뒤에서 거리와 면적 계산을 할 때 왜 주의가 필요한지 여기서 출발함
- 기하 유형이 `Polygon`, `MultiPolygon`인지 확인함
- 이 데이터가 점 데이터가 아니라 국가 경계 면 데이터라는 사실을 바로 보여 줌

## 6. GIS는 무엇을 하는 체계일까

### 6.1 GIS를 "지도 그리는 프로그램"으로만 보면 부족하다

- GIS를 처음 배울 때 가장 흔한 오해는 "지도 프로그램" 정도로 이해하는 것
- 물론 지도는 중요함
- 하지만 GIS는 지도를 예쁘게 만드는 도구보다 훨씬 넓음

- GIS가 하는 일은 보통 네 단계로 정리할 수 있음

1. 데이터를 수집함
2. 데이터를 맞춤
3. 공간 관계를 분석함
4. 결과를 해석하고 공유함

- 어떤 동네의 침수 위험을 분석하는 상황
- GIS는 단순히 물 색깔을 파랗게 칠하는 프로그램이 아님
- 다음 같은 질문을 실제로 처리함

- 어느 지역이 하천에 가까운가
- 어떤 도로가 침수되면 우회가 어려운가
- 어느 건물이 저지대에 몰려 있는가
- 어느 행정동에 위험이 집중되는가

- 즉 GIS는 "공간 데이터를 통해 질문하고 답하는 체계"에 더 가까움

### 6.2 John Snow 사례를 실제로 읽어 보기

- London Museum의 John Snow 자료를 보고 있는 상황의 가정
- 지도 자체의 모습보다 **지도에 무엇이 함께 찍혀 있는가**가 핵심

- 콜레라 사망 위치
- Broad Street 펌프 위치
- 특정 지역으로 몰리는 패턴

- 이 사례는 공간 분석의 고전으로 자주 언급되지만, 핵심은 의외로 단순함
- Snow는 "사망자가 많다"는 사실만 본 것이 아니라, **사망 위치가 어디에 몰려 있는가**를 확인함
- 그리고 그 공간적 패턴을 바탕으로 오염된 펌프 손잡이를 제거하게 만듦

- 이 흐름을 세 단계로 적을 수 있음

- **데이터**: 누가 어디서 사망했는가
- **지도/분석**: 사망 위치가 특정 펌프 주변에 집중되는가
- **행동/정책**: 해당 펌프의 사용 중단

- 이 구조는 지금도 똑같음
- 데이터 유형과 계산 방식만 더 복잡해졌을 뿐

## 7. 공간 데이터는 어떤 모양으로 오는가

### 7.1 벡터: 경계가 있는 객체를 표현하는 방식

- Natural Earth ZIP 파일을 열어 읽은 이번 실습은 **벡터 데이터**를 다룬 예
- 벡터 데이터는 점, 선, 면처럼 경계가 비교적 분명한 대상을 표현하는 데 적합함

- 점: 병원, 버스정류장, 민원 발생 위치
- 선: 도로, 철도, 하천
- 면: 행정경계, 공원, 학교 부지

- 국가 경계 데이터가 `Polygon`과 `MultiPolygon`으로 읽힌 이유가 바로 여기에 있음
- 국가는 면으로 표현되기 때문

- 벡터 데이터의 강점은 해석이 쉽다는 점
- "이 건물은 어느 행정동에 속하는가", "이 도로는 어느 구역과 겹치는가" 같은 질문을 처리하기 적합함

### 7.2 래스터: 연속적인 현상을 픽셀로 표현하는 방식

- 위성영상은 보통 **래스터 데이터**
- 래스터는 바둑판처럼 잘게 나눈 격자에 값을 채워 넣는 방식
- 각 칸을 **픽셀**이라고 부름

- 픽셀 하나마다 기록될 수 있는 값은 다양함

- 빛의 반사량
- 온도
- 고도
- 수분량

- 즉 래스터는 "여기부터 저기까지 연속적으로 변하는 현상"을 표현하기 적합함

### 7.3 포인트 클라우드: 3차원 구조를 보는 방식

- 포인트 클라우드는 3차원 점들의 집합
- 라이다 자료가 대표 사례
- 도시를 평면이 아니라 입체적으로 보고 싶을 때 강함

- 입문 단계에서는 세 가지 차이만 기억하면 충분함

- 벡터: 경계가 분명한 객체
- 래스터: 연속적인 표면
- 포인트 클라우드: 입체 구조

- 이 구분은 뒤 장들에서 계속 반복됨

## 8. GeoAI는 GIS와 무엇이 다른가

### 8.1 GIS 위에 학습이 올라간다

- GIS가 규칙 기반 질문에 강하다면, GeoAI는 데이터에서 패턴을 학습하는 데 강함

- 건물을 찾는 문제의 검토

- 전통 GIS나 규칙 기반 접근은 색, 모양, 크기 같은 규칙을 사람이 비교적 직접 정함
- GeoAI는 건물로 라벨된 예시를 많이 보고, 어떤 패턴이 건물인지 스스로 학습함

- 이 차이가 중요한 이유는 데이터 규모가 커질수록 드러남
- 위성영상 수천 장, 수만 장을 사람이 하나하나 규칙으로 처리하기는 어려움
- 그래서 학습 기반 접근이 힘을 가짐

### 8.2 실제 자료로 보는 GeoAI의 감각

- Microsoft Global ML Building Footprints 저장소를 보고 있는 상황의 가정
- 이 자료는 전 세계 건물 형태를 대규모로 자동 추출해 공개한 사례

- 학생이 읽어야 할 세 가지 핵심

- 건물을 사람이 모두 손으로 그린 것이 아니라는 점
- 위성영상 같은 대규모 공간 데이터를 모델이 읽었다는 점
- 결과가 다시 건물 레이어라는 공간데이터로 돌아온다는 점

- 즉 GeoAI는 공간 데이터를 입력으로 받아, 다시 공간 판단에 쓸 수 있는 결과를 내놓음
- 이 때문에 GIS와 끊어진 별개 분야가 아니라, GIS 위에서 진화한 흐름으로 이해하는 편이 더 정확함

### 8.3 왜 Earth Engine 같은 플랫폼이 중요해졌을까

- Google Earth Engine 소개 페이지를 보면 "multi-petabyte" 같은 표현이 눈에 들어옴
- 이 말은 데이터가 너무 커져서, 개인 노트북에 전부 내려받는 방식으로는 다루기 어려워졌다는 뜻

- 즉 GeoAI의 등장에는 세 가지가 함께 있음

- 더 많은 데이터
- 더 강한 알고리즘
- 더 큰 계산 인프라

- 그래서 GeoAI는 단순히 "AI가 유행해서" 등장한 것이 아니라, **공간 데이터의 규모 자체가 사람 손만으로 다루기 어려운 수준으로 커졌기 때문에** 등장한 흐름으로 이해하는 편이 맞음

## 9. 이름은 여러 개인데, 기준은 세 개다

### 9.1 같은 말이 다른 것을 가리킬 때

- 세 장면의 설정
- 셋 다 실제로 벌어지는 일

- 첫째, 어느 회사가 "GeoAI 기반 상권 분석 시스템"이라는 제안서를 냄
- 열어 보니 지도 위에 지점별 매출을 색으로 칠하고 반경 500m 원을 그린 화면
- 쓸모 있는 도구지만 학습하는 모델은 어디에도 없음

- 둘째, 어떤 학생이 위성영상을 받아 랜덤 포레스트를 돌려 놓고 "GeoAI 과제"라고 제출함
- 그런데 돌려 보니 좌표를 지워도 결과가 똑같이 나옴

- 셋째, 한 회의에서 도시계획 담당자는 "공간 분석"을 도시 현황 진단으로 알아듣고, 마케팅 담당자는 매장 자리 고르기로 이해함
- 한 시간을 이야기하고 서로 다른 결론을 들고 나옴

- 세 장면의 공통점은 하나
- **같은 낱말이 다른 것을 가리키고 있는데 아무도 눈치채지 못했음**
- 그리고 이건 말싸움으로 끝나지 않음
- 이름이 예산 항목을 정하고, 평가 기준을 정하고, 누가 그 일을 맡을지를 정함
- "AI 사업"으로 분류되면 붙는 돈과 채점표가 달라짐

### 9.2 이름을 세 줄로 갈라 놓기

- 이름이 많아 보이는 이유는 사실 단순함
- **서로 다른 기준으로 붙은 이름들을 한 줄에 세워 놓았기 때문**
- 기준을 갈라 놓으면 관계가 쉬워짐

- **무엇을 다루는가**(분야): 지리공간 분석, GIS, 원격탐사, 공간 통계, 공간 데이터 과학
- **어떻게 다루는가**(방법): GeoAI
- **무엇을 위해 쓰는가**(용도): 위치 인텔리전스

- 기준이 다르면 서로 배타적이지 않음
- 옷을 두고 "면 소재인가, 셔츠인가, 출근용인가"를 묻는 것과 같음
- 셋 다 맞을 수 있고, 실제로 그런 경우가 정상

- **지리공간 분석**은 가장 넓은 말
- 공간 데이터를 다루는 모든 분석이 여기 들어감
- **GIS**는 공간 데이터를 모으고 저장하고 분석하고 그리는 통합 체계
- 공간 데이터 과학의 기반
- **원격탐사**는 직접 만지지 않고 센서로 지표를 관측하는 기술
- 위성영상을 만들어 주는 앞 공정
- **공간 통계**는 "가까운 것끼리 닮는다"는 성질을 정면으로 다루는 통계 이론
- 이것도 1층
- **위치 인텔리전스**는 위치 데이터로 사업 판단을 돕는 일을 가리킴
- 여기만 **용도**로 정의된 명칭
- **GeoAI**는 공간 데이터에 AI를 쓰되, **공간의 구조를 모델 안에 넣는** 방법을 가리킴

- 위치 인텔리전스만 성격이 다르다는 점
- 나머지는 "무엇을 다루는가" 또는 "어떻게 다루는가"로 정의되는데, 위치 인텔리전스는 "무엇을 위해 쓰는가"로 정의됨
- 그래서 옛날 방식 GIS로도 되고 최신 GeoAI로도 됨
- 지도에 매출을 색칠하는 것도 위치 인텔리전스이고, 새 매장이 기존 매장 손님을 얼마나 빼앗을지 계산하는 것도 위치 인텔리전스

### 9.3 판정 연습: 이건 GeoAI인가

- 정의를 외우는 것보다 애매한 사례를 직접 판정해 보는 편이 빠름
- 다섯 사례의 채점표 작성

| 분석 사례 | 지리공간 분석 | GeoAI | 위치 인텔리전스 | 왜 그렇게 판정하나 |
|-----------|:---:|:---:|:---:|------------|
| 지도 위에 지점별 매출을 색으로 칠한 화면 | ○ | ✗ | ○ | 학습 모델 부재. 시각화는 분석이지만 AI는 아님 |
| 위성영상을 CNN으로 토지피복 분류해 도시계획에 씀 | ○ | ○ | ✗ | AI 사용 및 이웃 픽셀 관계의 모델 반영. 공공 부문의 활용 |
| 상권 데이터를 랜덤 포레스트로 예측하되 이웃 정보와 공간 교차검증을 씀 | ○ | ○ | ○ | 셋이 다 성립하는 자리 — 비즈니스 GeoAI |
| 관측소 자료를 보간해 기온 지도를 만듦 | ○ | ✗ | ✗ | 공간 구조를 직접 다루지만 학습 모형이 아닌 통계 모형 |
| GIS로 정리한 뒤 좌표를 빼고 표에 랜덤 포레스트를 돌림 | ○ | **✗** | 쓰는 곳에 따라 | 공간 정보의 모델 미반영. 'GIS + 머신러닝'에 해당하며 GeoAI는 아님 |

- 마지막 줄이 가장 흔한 오판
- 공간 데이터를 입력으로 썼다는 사실만으로는 부족함
- 판정 질문 한 가지: **모델은 그대로 두고 데이터에서 공간 정보만 빼도 결과가 같은가?**
- 결과가 같다면 공간을 쓰지 않은 모델

- 네 번째 줄도 짚어 둘 가치가 있음
- 기온 보간은 "가까운 곳끼리 닮는다"는 성질을 정면으로 쓰므로 공간을 확실히 다루지만, 예시를 보고 배우는 모형은 아님
- 그래서 GeoAI가 아니라 1층의 공간 통계로 분류함
- **공간을 모델에 넣었는가**와 **데이터에서 배우는가**, 두 조건이 함께 맞아야 GeoAI

### 9.4 하나의 분석이 이름 셋을 동시에 갖는다

- 기준이 다르면 배타적이지 않다고 했음
- 뒤에서 다룰 "서울 행정동별 카페 기대 공급량 예측"의 세 기준별 판정

- **무엇을 다루는가**: 점포 위치와 생활인구 같은 공간 데이터 → **지리공간 분석**
- **어떻게 다루는가**: 랜덤 포레스트 사용, 이웃 정보와 공간 교차검증 포함 → **GeoAI**
- **무엇을 위해 쓰는가**: 출점 후보 축소 → **위치 인텔리전스**

- 셋 다 맞음
- 그러니 "이건 GeoAI야, 위치 인텔리전스야?"라는 질문 자체가 잘못 세워진 질문
- 옳은 질문: **"어느 기준에서 무엇이라 부르는가"**

- 구분해서 얻는 두 가지 실익
- 첫째, GeoAI가 아닌 것을 GeoAI라 부르는 혼동을 막음
- 전통 GIS로 충분한 문제에 AI를 얹으면 비용과 불투명함만 늘어남
- 둘째, 같은 파이프라인이 공공에서 쓰일 때와 기업에서 쓰일 때 무엇이 달라지는지를 또렷하게 볼 수 있음
- 그 이야기가 11절

## 10. GeoAI의 두 분석 축: 무엇을 읽고, 어디를 판단하는가

- 이 책은 GeoAI를 두 가지 축으로 설명함

### 10.1 영상·래스터 기반 축

- 이 축에서는 주로 물음

- 무엇이 어디에 있는가
- 무엇이 변했는가
- 피해 범위가 어디까지인가

- 대표 예시는 다음과 같음

- 위성영상에서 침수 픽셀 찾기
- 산불 흔적 찾기
- 토지피복 분류하기

### 10.2 공간단위 기반 축

- 이 축에서는 주로 물음

- 어느 지역이 취약한가 (기업이라면: 어느 지역이 유망한가)
- 어디에 자원을 먼저 배분해야 하는가 (기업이라면: 어디에 먼저 투자할까)
- 정책 효과가 어디에서 나타나는가 (기업이라면: 그 매장을 연 효과가 얼마인가)

- 대표 단위는 다음과 같음

- 행정구역
- 격자
- 필지
- 건물
- 도로망
- 생활권

- 이 책의 중심은 둘째 축
- 이유는 단순함
- 결정은 결국 행정구역, 생활권, 격자 같은 **공간단위**에서 내려지기 때문
- 예산도 행정동 단위로 배분되고, 매장도 어느 한 자리에 열림
- 픽셀 단위로 내리는 결정은 없음

### 10.3 왜 "픽셀을 잘 맞혔다"에서 끝나면 안 될까

- 홍수 분석 상황의 가정
- 위성영상에서 침수된 픽셀을 잘 찾는 것은 중요함
- 하지만 정책은 거기서 끝나지 않음

- 그 다음 질문이 뒤따름

- 침수된 건물이 몇 개인가
- 어떤 도로가 끊겼는가
- 어느 생활권이 고립되는가
- 어느 행정동을 먼저 지원할 것인가

- 즉 영상 분석은 출발점이고, 판단은 공간단위로 집계된 뒤에야 가능해짐
- 이 차이를 처음부터 머리에 넣고 가야 이후 장들이 연결됨

## 11. 같은 지도, 다른 결정 — 공공과 비즈니스

### 11.1 홍수 지도 하나를 두 사람이 본다

- 침수 위험 지도 한 장을 만든 상황
- 건물마다 물에 잠길 위험이 얼마인지 색으로 칠해 놓은 지도

- 이 지도를 시청 재난 담당자가 확인함
- 그는 위험이 높은 순서로 목록을 만들어 대피소를 어디에 둘지, 어느 동네부터 배수로를 손볼지 정함

- 같은 지도를 보험사가 확인함
- 그는 위험이 높은 순서로 보험료를 다르게 매기고, 어떤 건물은 아예 인수를 거절함

- **지도를 만든 계산은 똑같음**
- 위성영상을 읽고, 지형과 하천 거리를 재고, 이웃 정보를 넣어 예측하고, 그 예측이 믿을 만한지 확인하는 과정 전부가 같음
- 그런데 지도가 나간 뒤에 벌어지는 일이 전혀 다름
- 한쪽에서는 위험한 사람이 도움을 먼저 받고, 다른 쪽에서는 위험한 사람이 돈을 더 냄

- 이것이 이 책이 3층을 "정책층"이 아니라 **의사결정층**이라 부르는 이유
- 1층과 2층은 공유되고, 3층에서 갈라짐

### 11.2 무엇이 같고 무엇이 다른가

- 공공과 비즈니스의 공통점부터 확인
- 지역을 어떤 칸으로 나눌지, 그 칸에 거리·밀도·접근성 같은 숫자를 어떻게 붙일지, 예측 성능을 정직하게 재려면 어떻게 나눠서 검증해야 할지, 어떤 변수가 결과를 밀어올렸는지 어떻게 읽을지 — 여기까지는 공공이든 기업이든 그대로 사용함
- 4장에서 배울 한 벌의 절차가 복지 사각지대 예측에도 상권 입지 점수에도 똑같이 적용됨

- 다른 것은 표로 보는 편이 빠름

| | 공공 | 비즈니스 |
|---|---|---|
| 핵심 질문 | 어디가 취약한가 | 어디가 유망한가 |
| 결과물 | 우선순위 표 → 예산 배분 | 입지 점수 → 출점·투자 결정 |
| 틀렸을 때의 손해 | 놓친 사각지대 → 도움이 안 감 | 잘못 연 매장 → 묻힌 돈 |
| 자료 출처 | 행정 통계, 공공 센서 | 휴대폰 위치, 상점 정보, 결제 자료 |
| 무엇을 잘하려 하나 | 예산 안에서 공평하게 | 남는 장사, 그리고 경쟁 반응까지 |
| "효과가 있었나"를 어떻게 아나 | 법·조례 시행일이 자연스러운 기준선이 됨 | 잘될 것 같은 자리에 열기 때문에 훨씬 어려움 |

- 마지막 줄이 특히 중요함
- 조례가 3월 1일부터 시행됐다면, 그 전과 후를 비교하는 일에 꽤 그럴듯한 근거가 생김
- 시행일은 그 동네 사정을 보고 정해진 게 아니기 때문
- 기업은 **매출이 오를 것 같은 자리에 매장을 개설함**
- 그러니 "매장을 열었더니 매출이 올랐다"는 관찰에서 매장 덕분인 부분만 떼어내기가 훨씬 어려움
- 이 문제는 8장과 15장에서 본격적으로 다룸

### 11.3 "공공은 취약, 기업은 유망"은 절반만 맞다

- 위 표를 외우기 좋게 줄이면 "공공은 취약한 곳을 찾고 기업은 유망한 곳을 찾는다"가 되는데, 편하지만 정확하지는 않음

- 기업도 **수요는 있는데 공급이 없는 곳**을 찾음
- 그게 곧 빈 시장이기 때문
- 공공도 **사람이 몰리는 곳**에 자원을 더 넣음
- 공공이 말하는 "사각지대"와 기업이 말하는 "미개척 시장"은 계산해 보면 구조가 닮음
- 12장에서 복지 사각지대를 찾는 방법과 동물병원 자리를 고르는 방법이 어떻게 갈라지고 어디서 만나는지를 나란히 보게 됨

- 그러니 이 대비는 외울 공식이 아니라 **처음 방향을 잡는 손잡이** 정도로 쓰는 게 적합함

### 11.4 AI를 쓰지 말아야 할 때

- 명확히 할 원칙 한 가지
- **AI를 붙이는 게 늘 나은 것은 아님**

- "우리 동네에서 가장 가까운 병원까지 몇 분 걸리는가"는 도로망과 위치만 있으면 계산으로 정확히 나옴
- 여기에 학습 모델을 얹으면 정확한 답을 부정확한 추측으로 바꾸는 셈

- 그래서 어떤 분석을 GeoAI라고 부르려면 최소한 이걸 통과해야 함

1. 옛날 방식 GIS로 충분한 문제인지 **먼저** 따져 봤는가
2. AI가 필요한 이유를 댈 수 있는가 (영상이 너무 크다, 글자 자료라 규칙을 못 만든다, 시간에 따라 복잡하게 번진다 등)
3. 모델이 공간 구조를 실제로 쓰고 있는가 (9.3의 판정 질문)
4. 그 결과가 누군가의 **결정을 바꾸는가**
5. 편향, 개인정보, 낙인 같은 문제를 함께 살폈는가

- 4번이 3층이고, 5번은 이 책이 마지막 질문으로 계속 되돌아오는 지점
- 지도가 사람을 도울 수도 있고 해칠 수도 있기 때문

## 12. 활동 / 토론

- 이번 장의 활동은 읽은 내용을 상상해 보는 것이 아니라, **내 컴퓨터에서 직접 해 보는 것**
- 실습은 AI 코딩 에이전트와 함께 각자의 컴퓨터에서 진행함
- 실행 오류를 확인하고 해결하는 과정도 실습에 포함

- **활동 1 (25분) — 실습 환경 준비하기**
  - `lecture_practice/README.md`를 따라 파이썬, VS Code, 가상환경, 패키지를 설치함
  - 다 됐으면 `python lecture_practice/check_env.py`를 실행함
  - "모든 항목 통과"가 나오면 종료
  - 한 번에 통과하지 못해도 정상
  - 컴퓨터마다 막히는 지점이 다름
  - 윈도우와 맥이 다르고, 같은 윈도우끼리도 다름
  - 화면에 나온 문장을 AI 에이전트에 그대로 붙여넣고 시킨 대로 한 뒤, 진단을 다시 돌려 그 항목이 사라졌는지 확인함
  - **오류를 직접 진단하고 수정하는 과정도 실습에 포함**
  - 같은 곳에서 30분 넘게 막히면 질문할 시점
  - 자세한 순서는 `lecture_practice/README.md`의 "그래도 안 될 때"에 있음

- **활동 2 (15분) — 기준값과 맞춰 보기**
  - `python lecture_practice/chapter1/code/1-1-geoai-tools-preview.py`를 실행하고 화면의 값을 5절의 값과 대조
  - 전체 국가 수 `177`, 아시아 국가 수 `47`, 데이터 형태 `(177, 169)`가 그대로 나왔는가
  - 5절의 값은 다른 컴퓨터에서 실행해 얻은 결과
  - **운영체제도 파이썬 버전도 다른데 숫자가 같아야 함**
  - 값이 같아야 하는 이유와 값이 다를 때 먼저 의심할 항목을 한 문장으로 작성
  - 이어지는 질문에 스스로 답하기
  - **이 데이터가 점·선·면 가운데 무엇이고, 어떻게 그렇게 판단했는가?** 화면에 나온 값 하나를 근거로 대야 함

- **활동 3 (15분) — 이상한 결과를 찾아내기**
  - 같은 실행 결과에 "아시아 면적 상위 5개국"이 나옴
  - 그 목록에는 중국, 카자흐스탄, 인도, 몽골, 사우디아라비아가 들어 있음
  - 세계지도를 떠올리며 이 순서가 타당한지 검토
  - 실행 화면에는 경고 문구도 함께 떠 있다(위치는 컴퓨터마다 다를 수 있다)
  - 경고가 가리키는 문제와 목록의 관계를 한 문장으로 작성
  - **오류가 아니라 경고라서 코드는 끝까지 돌았다는 점**이 핵심
  - 결과가 나왔다고 맞는 것이 아님

- **활동 4 (20분) — AI 에이전트에게 처음 물어보기**
  - `lecture_practice/chapter1/README.md`의 4번 대화 순서를 따라 에이전트에게 질문함
  - 답을 받아 적기만 하면 안 됨
  - 최소 한 번은 되물어야 함
  - "방금 설명에서 내가 모를 만한 단어를 하나 골라 다시 쉽게 설명해줘"
  - "그 말이 맞는지 내가 직접 확인하려면 무엇을 보면 돼?"

- **토론 1:** "이 문제는 전통 GIS만으로 충분해서 굳이 AI를 안 쓰는 편이 낫다"고 말할 수 있는 상황은 언제일까?
- **토론 2:** 활동 3에서 본 것처럼, 결과가 그럴듯하게 나왔지만 틀린 경우를 사람이 알아채려면 무엇을 알고 있어야 할까?
- 에이전트가 대신 코드를 써 주는 시대에 이 질문이 왜 더 중요해질까?

- 시청이 쓰면 도움이 먼저 가고, 보험사가 쓰면 보험료가 올라감
- 같은 지도를 만든 사람에게 두 번째 쓰임까지 책임이 있을까?

## 14. 과제

- 이번 장의 과제는 **직접 돌려 보고, 그 결과로 판단하는 것**
- 명령 한 줄이면 제출할 파일이 생성됨

```bash
python scripts/submit.py 1 --id 학번 --name 이름
```

- 이 명령이 대신 처리하는 작업: 실습 데이터 생성, 대표 실습 `1-1-geoai-tools-preview.py` 실행, 제출용 파일 생성
- 저장소를 내려받아도 데이터 파일은 들어 있지 않으므로 첫 단계가 꼭 필요함
- 그래서 처음 돌리는 장은 조금 더 걸림

- 끝나면 `submissions/` 폴더에 `제출_1장_학번.md` 파일이 생김
- 열어 보면 실행 결과가 이미 붙어 있음
- **눈여겨볼 곳은 국가 수, 좌표계, 기하 유형, 그리고 마지막에 뜨는 경고**

- 맨 아래 빈칸 세 개만 채우면 됨

1. 눈에 띈 숫자 하나를 그대로 옮겨 적고, 왜 눈에 띄었는지 한 문장으로
2. 그 숫자가 왜 그렇게 나왔는가
3. **이 결과는 컴퓨터가 달라도 똑같이 나와야 한다. 왜 그런가? 만약 달랐다면 무엇을 먼저 의심하겠는가?**

- **3번이 이 과제의 핵심**
- 1·2번은 결과를 들여다보면 답이 나오지만 3번은 그렇지 않음
- 과제의 핵심은 숫자 산출이 아니라 그 숫자를 근거로 판단하는 능력

- 채운 파일 **하나만** 올리면 제출이 끝남

> - **막혀도 제출함**
> - 실행이 도중에 실패하면 오류 메시지가 그 파일에 자동으로 담기고, 질문이 "어디서 막혔나"로 바뀜
> - 어디서 왜 막혔는지 적은 제출도 온전한 제출
> - 실행 성공 여부로 점수를 매기지 않음

> - **이 장은 난수를 쓰지 않음**
> - 그래서 교재에 적힌 값이 그대로 나와야 정상이고, 옆 사람 결과와도 같음
> - 다른 결과가 나왔을 때 차이를 찾는 과정까지 과제에 포함
