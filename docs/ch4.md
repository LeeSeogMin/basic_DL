# 제4장 머신러닝 첫걸음 — 규칙을 쓰지 않고 분류하기

---

## [전반부] 이론 강의
---

### 학습 목표

- 사람이 규칙을 직접 쓰는 방식과 모델이 데이터에서 규칙을 찾는 방식이 어떻게 다른지 설명한다
- 분류와 회귀를 자기 주변의 예로 구분한다
- 훈련 데이터와 테스트 데이터를 왜 나누는지 설명한다
- 기준선 모델을 만들고, 새 모델을 기준선과 비교한다
- 정확도 하나만 보면 왜 속는지, 혼동행렬이 무엇을 더 보여주는지 설명한다

지난 3주 동안 데이터를 표로 만들고 그림으로 그렸다. 이번 장에서는 그 표를 컴퓨터에게 주고 판단 기준을 찾게 한다. 딥러닝도 머신러닝의 한 갈래다. 신경망으로 들어가기 전에 "모델이 데이터를 보고 기준을 찾는다"는 생각부터 손으로 확인한다.

### 1. 규칙을 직접 쓰면 어디서 막히는가

#### 1-1. 사람이 규칙을 쓰는 방식

컴퓨터에게 일을 시키는 가장 오래된 방법은 사람이 조건문을 쓰는 것이다.

```python
if score >= 60:
    result = "합격"
else:
    result = "불합격"
```

이 방식은 강력하다. 기준이 분명하고, 왜 그렇게 판정했는지 한 줄로 설명할 수 있고, 데이터가 한 건도 없어도 돌아간다.

문제는 기준을 말로 쓸 수 없을 때 생긴다. 고양이 사진과 강아지 사진을 가르는 규칙을 조건문으로 써 보면 금방 막힌다. 귀가 뾰족하면 고양이라고 쓰면 뾰족한 귀를 가진 강아지에서 틀린다. 수염을 세면 사진마다 수염이 다르게 찍힌다. 조건을 하나 더할 때마다 예외가 두 개씩 늘어난다.

#### 1-2. 모델이 규칙을 찾는 방식

머신러닝은 순서를 바꾼다. 사람은 규칙 대신 **예시**를 준다. 예시에는 입력과 정답이 함께 들어 있다. 모델은 그 둘의 관계를 보고 판단 기준을 스스로 만든다.

![규칙 기반 방식과 머신러닝 방식의 흐름 비교](../practice/chapter4/results/fig4-1-rule-vs-learning.png)

**그림 4.1** 두 방식의 차이 — 규칙이 사라진 것이 아니라, 규칙을 쓰는 주체가 사람에서 모델로 바뀐다

여기서 오해를 하나 정리한다. 머신러닝은 규칙 없이 판단하는 방법이 아니다. 모델도 결국 어떤 기준선을 긋는다. 다만 그 선을 사람이 문장으로 쓰지 않고, 데이터를 보며 찾을 뿐이다. 실습 4.1에서 모델이 찾은 선을 숫자로 뽑아 볼 텐데, 그 선은 사람이 손으로 그은 선과 같은 종류의 식이다.

**표 4.1** 두 방식 비교

| 구분 | 규칙 기반 방식 | 머신러닝 방식 |
|---|---|---|
| 사람이 하는 일 | 규칙을 직접 쓴다 | 예시 데이터를 모은다 |
| 컴퓨터가 하는 일 | 규칙을 적용한다 | 데이터에서 기준을 찾는다 |
| 잘 맞는 문제 | 점수 기준 합격 판정, 세금 계산 | 사진 분류, 댓글 분류, 추천 |
| 막히는 지점 | 기준을 말로 쓸 수 없을 때 | 데이터가 적거나 한쪽으로 치우쳤을 때 |
| 결과를 설명하는 방법 | 규칙을 그대로 읽는다 | 모델이 만든 기준을 꺼내 본다 |

○ **체크 질문**
  - 학교 장학금 선발을 규칙 기반으로 짜면 어디까지 되고, 어디서 막히는가
  - 반대로 머신러닝으로 짜면 무엇이 위험한가

### 2. 분류와 회귀 — 답이 이름인가 숫자인가

머신러닝 문제는 정답의 생김새로 크게 둘로 나뉜다.

○ **분류(classification)** — 정답이 **이름**일 때
  - 스팸인가 정상인가, 고양이인가 강아지인가, 통과인가 미통과인가
  - 답의 종류가 정해져 있고, 그중 하나를 고른다

○ **회귀(regression)** — 정답이 **숫자**일 때
  - 내일 기온은 몇 도인가, 이 중고차는 얼마인가, 이 학생의 점수는 몇 점인가
  - 답이 연속된 값이고, 딱 떨어지는 후보가 없다

**표 4.2** 같은 데이터라도 무엇을 묻느냐에 따라 문제가 달라진다

| 가진 데이터 | 분류 문제로 물으면 | 회귀 문제로 물으면 |
|---|---|---|
| 학생의 공부 시간, 수면 시간 | 시험에 통과할까 | 시험 점수가 몇 점일까 |
| 메일의 링크 수, 대문자 비율 | 스팸일까 | 스팸일 확률이 몇 %일까 |
| 사진의 픽셀값 | 고양이일까 강아지일까 | 사진 속 동물의 나이가 몇 살일까 |

이번 장의 실습은 둘 다 분류다. 회귀는 6장에서 손실함수를 다룰 때 다시 나온다.

○ **자주 하는 실수**
  - 별점 1~5를 예측하는 문제를 회귀로만 보면, 3.7점이라는 답이 나온다. 별점에 3.7은 없다
  - 반대로 기온을 분류로 보면 20도와 21도를 완전히 다른 이름으로 취급해, 1도 차이와 30도 차이를 똑같이 틀린 것으로 센다
  - 정답이 이름인지 숫자인지는 데이터가 아니라 **내가 무엇을 묻는지**가 정한다

### 3. 훈련 데이터와 테스트 데이터

모델을 만들 때 가진 데이터를 전부 쓰면 안 된다. 반드시 일부를 떼어 숨겨 둔다.

![훈련 데이터와 테스트 데이터 분할](../practice/chapter4/results/fig4-2-train-test-split.png)

**그림 4.2** 가진 데이터를 둘로 나눈다 — 모델은 훈련 데이터만 보고 배우고, 성적은 테스트 데이터에서 잰다

이유는 단순하다. 모델이 이미 본 데이터에서 성적을 재면, 답을 보고 시험을 치는 것과 같다. 시험 범위를 통째로 외운 학생과 원리를 이해한 학생은 연습 문제에서 똑같이 100점을 받는다. 둘을 가르려면 처음 보는 문제를 줘야 한다.

○ **나누는 방법**
  - 보통 훈련 7 : 테스트 3, 또는 8 : 2로 나눈다
  - 나눌 때 두 그룹의 비율을 맞춘다(`stratify`). 통과 학생이 훈련 쪽에만 몰리면 비교가 성립하지 않는다
  - 한 번 테스트로 떼어 낸 데이터는 모델을 고칠 때 **보지 않는다**

○ **지금은 넘어가는 것**
  - 실무에서는 훈련 · 검증 · 테스트 셋으로 나눈다. 검증 데이터는 모델을 고르는 데 쓰고, 테스트는 마지막에 딱 한 번 쓴다
  - 이 구분은 7장(과적합)에서 다시 다룬다. 이번 장은 둘로만 나눈다

### 4. 기준선 — 비교 상대가 없으면 잘했는지 알 수 없다

"정확도 95%"라는 말만으로는 아무것도 알 수 없다. 95%가 좋은 성적인지 나쁜 성적인지는 **아무 생각 없이 찍었을 때 몇 %가 나오는지**와 비교해야 정해진다.

기준선(baseline)은 그 비교 상대다. 만드는 방법은 간단하다.

○ **가장 흔한 기준선** — 훈련 데이터에서 더 많았던 쪽으로만 답한다
  - 통과 학생이 더 많으면, 테스트 데이터 전부를 통과로 찍는다
  - 데이터를 보지도 않고, 학습도 하지 않는다

○ **기준선을 만드는 이유**
  - 새 모델이 기준선을 못 넘으면, 그 모델은 데이터에서 아무것도 배우지 못한 것이다
  - 반대로 기준선이 이미 95%라면, 96%짜리 모델은 자랑거리가 아니다

실습 4.1에서 기준선 정확도는 0.500이 나왔다. 두 그룹의 수가 거의 같았기 때문이다. 실습 4.2에서는 같은 기준선이 0.950까지 올라간다. 왜 그런지는 다음 절에서 다룬다.

### 5. 정확도 하나만 보면 속는다

정확도(accuracy)는 맞힌 비율이다.

```
정확도 = 맞힌 개수 / 전체 개수
```

계산이 쉽고 한 숫자로 요약되니 편하다. 그래서 위험하다.

○ **한쪽이 드물면 정확도가 무너진다**
  - 메일 1000통 중 스팸이 50통이라고 하자. 스팸은 전체의 5%다
  - "전부 정상"이라고만 답하는 프로그램을 만들면 950통을 맞힌다. 정확도 95%다
  - 이 프로그램은 스팸을 **한 통도** 못 잡는다. 그런데 성적표에는 95%라고 찍힌다

이런 데이터를 **불균형 데이터**라고 부른다. 실제로 중요한 문제는 대부분 불균형하다. 불량품, 질병, 사기 거래, 재난 신고는 전부 드물게 일어난다. 드물기 때문에 찾아낼 값어치가 있고, 드물기 때문에 정확도가 속인다.

Google 머신러닝 단기집중과정도 같은 예를 든다. 한 클래스가 1%만 나타나는 데이터에서는 전부 음성이라고 답하는 모델이 정확도 99%를 기록하지만, 그 모델은 쓸모가 없다.[^google-acc]

○ **그래서 무엇을 봐야 하는가**
  - 기준선 정확도를 먼저 계산한다. 내 모델이 그보다 나은가
  - 맞힌 비율이 아니라 **무엇을 놓쳤는지** 센다. 그 도구가 다음 절의 혼동행렬이다

### 6. 혼동행렬 — 어느 방향으로 틀렸는가

혼동행렬(confusion matrix)은 예측과 정답을 짝지어 개수를 센 표다. 답이 두 종류면 칸이 네 개 생기고, 그중 두 칸이 틀린 예측을 담는다. 틀리는 방향이 하나가 아니라는 것이 핵심이다.

○ **놓쳤다** — 정답은 스팸인데 정상이라고 했다
  - 스팸이 받은편지함에 들어온다. 사용자가 광고를 본다

○ **헛짚었다** — 정답은 정상인데 스팸이라고 했다
  - 합격 통보 메일이 스팸함으로 간다. 사용자가 중요한 메일을 놓친다

두 오류의 무게는 문제마다 다르다. 스팸 필터에서는 헛짚는 쪽이 더 아프고, 질병 검사에서는 놓치는 쪽이 훨씬 위험하다. 정확도는 이 둘을 그냥 더해 버려서 구분하지 못한다. 혼동행렬은 나눠서 보여준다.

#### 네 칸의 이름

찾으려는 쪽(여기서는 스팸)을 **양성(positive)**, 나머지(정상)를 **음성(negative)**이라고 부른다. 칸 이름의 뒤 낱말은 모델이 예측한 쪽이고, 앞 낱말(참/거짓)은 그 예측이 맞았는지다.

**표 4.3** 혼동행렬 네 칸의 이름 (양성 = 스팸)

| | 예측: 스팸(양성) | 예측: 정상(음성) |
|---|---|---|
| **실제: 스팸** | 참양성 TP — 잡았다 | 거짓음성 FN — 놓쳤다 |
| **실제: 정상** | 거짓양성 FP — 헛짚었다 | 참음성 TN — 맞게 넘겼다 |

위의 두 오류를 이 이름으로 다시 부르면, "놓쳤다"가 거짓음성(FN)이고 "헛짚었다"가 거짓양성(FP)이다.

#### 네 칸으로 계산하는 세 지표

숫자를 넣어 계산한다. 메일 100통 중 실제 스팸이 20통이고, 모델이 10통을 스팸이라고 불렀는데 그중 9통이 진짜 스팸이었다고 하자.

**표 4.4** 계산 예시 — 메일 100통, 실제 스팸 20통

| | 예측: 스팸 | 예측: 정상 | 합계 |
|---|---|---|---|
| **실제: 스팸** | TP = 9 | FN = 11 | 20 |
| **실제: 정상** | FP = 1 | TN = 79 | 80 |
| **합계** | 10 | 90 | 100 |

○ **정확도(accuracy)** — 전체 중에 맞힌 비율
  - 정확도 = (TP + TN) / 전체 = (9 + 79) / 100 = **88%**
  - 5절에서 봤듯이, 불균형 데이터에서는 이 숫자만 보면 속는다

○ **정밀도(precision)** — 스팸이라고 부른 것 중 진짜 스팸의 비율
  - 정밀도 = TP / (TP + FP) = 9 / (9 + 1) = **90%**
  - 분모가 **모델이 양성이라 부른 개수**다. 표의 세로줄(예측: 스팸)을 본다
  - 정밀도가 낮으면 헛짚음(FP)이 많다는 뜻이다. 중요한 업무 메일이 스팸함으로 들어간다

○ **재현율(recall)** — 실제 스팸 중 모델이 잡아낸 비율
  - 재현율 = TP / (TP + FN) = 9 / (9 + 11) = **45%**
  - 분모가 **실제 양성의 개수**다. 표의 가로줄(실제: 스팸)을 본다
  - 재현율이 낮으면 놓침(FN)이 많다는 뜻이다. 의학에서는 민감도(sensitivity)라고도 부른다
  - 예: 실제 감염자 10명을 검사해 8명만 양성이 나왔다면 재현율은 8 / 10 = 80%다. 나머지 2명은 감염된 채 정상 판정을 받았다

같은 표에서 나온 세 숫자가 전부 다르다 — 정확도 88%, 정밀도 90%, 재현율 45%. 이 모델은 스팸이라 부른 것은 거의 맞히지만, 실제 스팸의 절반 이상을 놓친다. 정확도 한 숫자에는 이 차이가 담기지 않는다.

**표 4.5** 세 지표 비교

| 지표 | 묻는 것 | 분모 | 낮을 때 생기는 일 |
|---|---|---|---|
| 정확도 | 전체 중 몇 개를 맞혔는가 | 전체 데이터 수 | 불균형 데이터에서는 높아도 의미가 없을 수 있다 |
| 정밀도 | 양성이라 부른 것 중 진짜는 몇인가 | TP + FP (예측 양성) | 정상 메일이 스팸함으로 간다 (헛짚음) |
| 재현율 | 실제 양성 중 몇 개를 잡았는가 | TP + FN (실제 양성) | 실제 환자가 정상 판정을 받는다 (놓침) |

#### 어느 지표를 우선하는가 — 문제가 정한다

두 지표 중 무엇을 우선할지는 두 오류(FN·FP) 중 어느 쪽 비용이 큰지로 정해진다. 네 칸의 구조는 어느 문제에서나 같지만 비용이 큰 칸은 문제마다 달라지므로, 두 사례를 숫자로 비교한다. 아래 두 표의 숫자는 실행 결과가 아니라 설명을 위해 가정한 값이다.

**스팸 필터 — 헛짚음의 비용이 크다, 그래서 정밀도를 본다**

메일 1000통(실제 스팸 50통, 정상 950통)에 필터 두 개를 돌렸다고 하자. 필터 A는 조금이라도 의심되면 차단하고, 필터 B는 확실할 때만 차단한다.

**표 4.6** 스팸 필터 두 후보의 혼동행렬 — 각 칸은 `필터 A / 필터 B`, 메일 1000통 중 실제 스팸 50통 (가정한 값)

| | 예측: 스팸(양성) | 예측: 정상(음성) | 합계 |
|---|---|---|---|
| **실제: 스팸** | TP = 48 / 30 | FN = 2 / 20 | 50 |
| **실제: 정상** | FP = **30 / 3** | TN = 920 / 947 | 950 |
| **합계** | 78 / 33 | 922 / 967 | 1000 |

○ **세 지표를 계산하면**
  - 정확도 — A = (48 + 920) / 1000 = **96.8%**, B = (30 + 947) / 1000 = **97.7%**. 차이가 0.9%p뿐이어서 정확도로는 둘을 가르기 어렵다
  - 정밀도 — A = 48 / 78 = **61.5%**, B = 30 / 33 = **90.9%**
  - 재현율 — A = 48 / 50 = **96.0%**, B = 30 / 50 = **60.0%**

○ **그래서 필터 B를 쓴다**
  - A는 정상 메일 30통을 스팸함에 넣는다. 그 안에 합격 통보나 거래처 회신이 있으면 사용자는 스팸함을 열어 보기 전까지 사라진 줄도 모른다
  - B는 광고 메일 20통을 놓치지만, 사용자가 받은편지함에서 직접 지우면 그것으로 끝난다
  - 정밀도 = TP / (TP + FP)이므로 FP를 30통에서 3통으로 줄이면 정밀도가 61.5%에서 90.9%로 오른다. 스팸 필터는 이 값을 먼저 본다

**암 검진 — 놓침의 비용이 크다, 그래서 재현율을 본다**

수검자 10,000명 중 실제 암 환자가 100명(1%)이라고 하자. 검사 A는 조금이라도 의심되면 양성으로 판정하고, 검사 B는 확실할 때만 양성으로 판정한다.

**표 4.7** 암 검진 두 후보의 혼동행렬 — 각 칸은 `검사 A / 검사 B`, 수검자 10,000명 중 실제 환자 100명 (가정한 값)

| | 예측: 암(양성) | 예측: 정상(음성) | 합계 |
|---|---|---|---|
| **실제: 암** | TP = 95 / 60 | FN = **5 / 40** | 100 |
| **실제: 정상** | FP = 495 / 20 | TN = 9,405 / 9,880 | 9,900 |
| **합계** | 590 / 80 | 9,410 / 9,920 | 10,000 |

○ **세 지표를 계산하면**
  - 정확도 — A = (95 + 9,405) / 10,000 = **95.0%**, B = (60 + 9,880) / 10,000 = **99.4%**
  - 정밀도 — A = 95 / 590 = **16.1%**, B = 60 / 80 = **75.0%**
  - 재현율 — A = 95 / 100 = **95.0%**, B = 60 / 100 = **60.0%**

○ **그래서 검사 A를 쓴다**
  - 정확도만 보면 B가 4.4%p 높다. 그런데 B는 암 환자 40명을 정상이라고 판정해 집으로 돌려보내고, 그 사이에 지나간 치료 시기는 되돌릴 수 없다
  - A가 헛짚은 495명은 건강한데도 추가 정밀검사를 받는다. 비용과 불안이 생기지만 그 검사로 바로잡는다
  - 재현율 = TP / (TP + FN)이므로 FN을 40명에서 5명으로 줄이면 재현율이 60.0%에서 95.0%로 오른다. 암 검진은 이 값을 먼저 본다
  - 5절에서 본 정확도의 함정이 여기서 다시 나타난다. 정확도가 높은 쪽을 고르면 환자 35명을 더 놓친다

두 표의 네 칸 배치는 똑같고 굵게 표시한 칸만 반대쪽이다. 스팸 필터에서는 왼쪽 아래 거짓양성(FP)이, 암 검진에서는 오른쪽 위 거짓음성(FN)이 비용이 큰 오류다. 판단 기준은 두 경우 모두 같다 — **되돌릴 수 있는 오류와 되돌릴 수 없는 오류를 비교한다.** 이 비교는 데이터가 아니라 그 문제를 아는 사람이 한다.

#### 두 지표는 함께 오르지 않는다

정밀도와 재현율은 한쪽을 올리면 다른 쪽이 내려가는 관계다. 모델이 양성이라고 부르는 기준을 조이면 정밀도가 오르는 대신 재현율이 떨어지고, 풀면 그 반대가 된다. 표 4.4의 모델로 두 극단을 계산해 보면:

○ 스팸을 하나도 안 놓치려고 100통 전부를 스팸이라 부르면 — 재현율 = 20/20 = 100%, 정밀도 = 20/100 = 20%

○ 반대로 가장 확실한 1통만 스팸이라 부르면 — 정밀도 = 1/1 = 100%, 재현율 = 1/20 = 5%

#### F1 점수 — 두 지표를 하나로 합칠 때

정밀도와 재현율을 한 숫자로 합쳐 모델을 비교해야 할 때는 F1 점수를 쓴다. 두 값의 조화평균이다.

> F1 = 2 × (정밀도 × 재현율) / (정밀도 + 재현율)

표 4.4의 모델로 계산하면 F1 = 2 × (0.90 × 0.45) / (0.90 + 0.45) = 0.81 / 1.35 = **0.60**이다.

○ **산술평균이 아니라 조화평균을 쓰는 이유** — 조화평균은 둘 중 낮은 쪽으로 끌려간다
  - 정밀도 90%와 재현율 45%의 산술평균은 67.5%지만, F1은 60%다
  - 한쪽이 0이면 F1도 0이다. 5절의 "전부 정상" 프로그램은 재현율이 0이므로, 정확도가 95%여도 F1은 0점이다

○ **주의** — F1은 정밀도와 재현율을 같은 무게로 합친다. 스팸 필터나 암 검진처럼 한쪽이 확실히 더 중요한 문제라면, F1 한 숫자보다 두 지표를 나란히 놓고 보는 쪽이 낫다

○ **읽는 순서**
  1. 가로줄(실제 양성)을 본다. 실제 스팸 중 몇 통을 잡았는가 — 이것이 재현율이다
  2. 세로줄(예측 양성)을 본다. 스팸이라고 부른 것 중 몇 통이 진짜였는가 — 이것이 정밀도다
  3. 두 빨간 칸 중 이 문제에서 더 아픈 쪽을 정한다. 그쪽 지표를 우선한다

이 지표들을 실제 모델에서 계산하는 것은 실습 4.2에서 한다.

`MY_TREE_DEPTH`를 `1`, `2`, `None`으로 바꿔 다시 실행하고 아래 세 질문에 답한다.

1. 깊이를 `1`로 두면 출력되는 조건문이 몇 줄인가. 깊이 `3`일 때와 몇 줄 차이인가
2. `None`으로 두면 훈련 정확도와 테스트 정확도가 각각 얼마가 되는가
3. 조건문이 길어질수록 두 정확도는 각각 어느 쪽으로 움직이는가

○ 확인할 것은 **조건문을 잘게 쪼갤수록 두 성적이 어떻게 갈라지는지**다

○ 로지스틱 회귀가 `-1.59`와 `13.96`을 어떻게 골랐는지는 이 실습에서 다루지 않는다. 그 값을 찾아가는 규칙이 6장의 경사하강법이다

### 실습 4.2: 정확도 95% 모델의 정체

#### 실습 목표

- 불균형 데이터에서 정확도가 어떻게 사람을 속이는지 직접 본다
- 정확도가 가장 높은 모델이 가장 쓸모없을 수 있다는 것을 혼동행렬로 확인한다

#### 데이터

메일 1000통을 만든다. 그중 스팸은 50통, 전체의 5%다. 특징은 두 개다.

- 메일에 들어 있는 링크 개수
- 제목에서 대문자가 차지하는 비율

스팸은 링크가 많고 대문자 비율이 높은 편이지만, 정상 메일과 겹치는 구간을 남겨 뒀다.

#### 세 모델

| 모델 | 하는 일 |
|---|---|
| A 무조건 정상 | 학습하지 않는다. 모든 메일을 정상이라고 답한다 |
| B 기본 모델 | 로지스틱 회귀를 기본 설정으로 학습한다 |
| C 스팸 중시 모델 | 같은 로지스틱 회귀에 "스팸을 놓치면 더 큰 손해"라고 알려주고 학습한다(`class_weight="balanced"`) |

#### 실행 명령

```bash
cd practice/chapter4/code
python 4-2-accuracy-trap.py
```

#### 실행 결과

```text
전체 1000통 중 스팸 50통 = 5.0%
훈련 700통, 테스트 300통(테스트 안의 스팸 15통)

        모델   정확도   정밀도   재현율    F1 스팸 잡음  정상을 스팸이라 함
  A 무조건 정상 0.950     - 0.000 0.000  0/15           0
   B 기본 모델 0.967 1.000 0.333 0.500  5/15           0
C 스팸 중시 모델 0.883 0.250 0.667 0.364 10/15          30
```

_출처: `practice/chapter4/results/4-2-accuracy-trap.log`_

같은 세 모델을 혼동행렬로 펼치면 정확도 한 숫자에 가려진 차이가 드러난다. 세 표 모두 테스트 300통, 그중 실제 스팸 15통이고, 칸 배치는 표 4.6·4.7과 같다.

**표 4.9** A 무조건 정상 — 정확도 0.950

| | 예측: 스팸(양성) | 예측: 정상(음성) | 합계 |
|---|---:|---:|---:|
| **실제: 스팸** | TP = 0 | FN = 15 | 15 |
| **실제: 정상** | FP = 0 | TN = 285 | 285 |
| **합계** | 0 | 300 | 300 |

○ 예측: 스팸 열이 위아래 모두 0이다. 스팸이라고 부른 메일이 한 통도 없어 정밀도의 분모가 0이 된다

**표 4.10** B 기본 모델 — 정확도 0.967

| | 예측: 스팸(양성) | 예측: 정상(음성) | 합계 |
|---|---:|---:|---:|
| **실제: 스팸** | TP = 5 | FN = 10 | 15 |
| **실제: 정상** | FP = 0 | TN = 285 | 285 |
| **합계** | 5 | 295 | 300 |

○ FP가 0이라 정밀도는 5/5 = 1.000이다. 대신 FN이 10이라 재현율은 5/15 = 0.333에 그친다

**표 4.11** C 스팸 중시 모델 — 정확도 0.883

| | 예측: 스팸(양성) | 예측: 정상(음성) | 합계 |
|---|---:|---:|---:|
| **실제: 스팸** | TP = 10 | FN = 5 | 15 |
| **실제: 정상** | FP = 30 | TN = 255 | 285 |
| **합계** | 40 | 260 | 300 |

○ FN을 10에서 5로 줄인 대가로 FP가 0에서 30으로 늘었다. 6절에서 말한 맞교환이 칸의 수로 나타난다

_출처: `practice/chapter4/results/4-2-accuracy-trap.log`_

#### 결과 읽기

이 표에서 확인할 것은 세 가지다.

○ **A는 아무것도 하지 않고 95%를 받았다**
  - 학습을 한 줄도 하지 않았는데 정확도가 0.950이다. 스팸이 5%뿐이라 그렇다
  - 표 4.9의 `예측: 스팸` 열이 위아래 모두 0이다. 스팸이라고 부른 메일이 한 통도 없다
  - 정확도만 적힌 보고서였다면 이 모델이 통과했을 수도 있다

○ **정확도가 가장 높은 B가 스팸의 3분의 2를 놓쳤다**
  - B의 정확도 0.967은 셋 중 가장 높다
  - 그런데 스팸 15통 중 5통만 잡았다. 10통은 그냥 통과시켰다
  - 정확도 순위와 쓸모 순위가 어긋난다

○ **정확도가 가장 낮은 C가 스팸을 두 배 잡았다**
  - C의 정확도 0.883은 셋 중 가장 낮다. A보다도 낮다
  - 그런데 스팸을 10통 잡았다. B의 두 배다
  - 대신 정상 메일 30통을 스팸이라고 헛짚었다

○ **6절의 지표로 다시 읽으면**
  - A: 재현율 = 0/15 = 0%. 스팸이라 부른 메일이 없어 정밀도는 계산할 수 없다(분모가 0). 그래도 F1은 0.000으로 정해진다. 잡은 스팸이 0통이면 F1의 분자가 0이 되어 정밀도 값과 무관해지기 때문이다
  - B: 정밀도 = 5/5 = 100%, 재현율 = 5/15 = 33%, F1 = 0.500. 부른 것은 전부 맞혔지만 셋 중 둘을 놓쳤다
  - C: 정밀도 = 10/(10+30) = 25%, 재현율 = 10/15 = 67%, F1 = 0.364. 두 배로 잡는 대신 헛짚음이 늘었다
  - B와 C가 정밀도·재현율의 반대 방향에 서 있다. 6절에서 말한 두 지표의 맞교환이 실제 모델에서 그대로 나타난다
  - F1로 줄을 세우면 B 0.500 > C 0.364 > A 0.000이다. 정확도 순위(B 0.967 > A 0.950 > C 0.883)와 달리 아무것도 하지 않은 A가 꼴찌로 내려간다
  - 다만 F1은 정밀도와 재현율을 같은 무게로 합친 값이다. 6절에서 적었듯 스팸 필터처럼 한쪽이 더 중요한 문제에서는 F1 한 숫자로 결정하지 않고 두 지표를 나란히 본다

○ **그래서 어느 모델이 좋은가**
  - 이 질문에는 데이터만 보고 답할 수 없다. 무엇이 더 아픈지를 사람이 정해야 한다
  - 광고 메일이 몇 통 들어오는 정도가 참을 만하다면 B를 고른다
  - 스팸을 놓치는 쪽이 위험한 상황(피싱 메일 차단)이라면, 정상 메일 30통을 스팸함에서 다시 꺼내는 수고를 감수하고 C를 고른다
  - 어느 쪽을 고르든, 정확도 한 숫자만 보고서에 적으면 이 판단 과정이 통째로 사라진다
