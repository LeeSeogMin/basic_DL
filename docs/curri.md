## 2. 수업 개요

본 과목은 학부 2학년을 대상으로 딥러닝의 기본 원리와 실제 활용 방법을 함께 다루는 입문 과목이다. 학생들은 인공지능, 머신러닝, 딥러닝, 생성형 AI의 차이를 이해하고, 데이터가 모델을 통해 예측과 분류로 이어지는 과정을 배운다.

이 수업은 단순히 딥러닝 모델 이름이나 수식을 암기하는 방식으로 운영하지 않는다. 매주 작고 흥미로운 실습을 수행하며, VS Code, GitHub, GitHub Copilot, Antigravity 등 AI 코딩 도구를 활용해 코드를 작성하고 오류를 고치고 결과를 검증한다.

요즘 학생들은 이미 AI를 일상적으로 사용한다. 따라서 이 과목의 목표는 AI를 처음 써보게 하는 데 있지 않다. 이미 쓰고 있는 AI를 더 정확하고 전문적으로 사용하게 하고, 동시에 AI 활용이 표절, 허위정보, 개인정보 노출, 코드 취약점, 사고력 약화로 이어지지 않도록 원리와 책임을 함께 가르치는 데 있다.

이 과목의 핵심 방향은 다음과 같다.

> 딥러닝을 수식으로만 배우지 않고, AI 도구와 함께 직접 만들어보며 이해한다.

> AI를 쓰는 사람에서, AI를 이해하고 검증하며 책임지는 사람으로.

## 3. 수업 목표

수업을 마친 학생은 다음을 할 수 있어야 한다.

1. 인공지능, 머신러닝, 딥러닝, 생성형 AI의 차이를 설명한다.
2. 데이터, 모델, 학습, 손실, 평가, 일반화의 관계를 자기 말로 설명한다.
3. Python과 간단한 딥러닝 코드를 실행하고 결과를 해석한다.
4. 이미지 분류, 텍스트 분류, 생성형 AI 활용 사례를 작은 실습으로 경험한다.
5. VS Code, GitHub, AI 코딩 도구를 사용해 작은 프로그램을 만들고 수정한다.
6. AI가 만든 코드와 답변을 그대로 믿지 않고 실행, 비교, 오류 분석으로 검증한다.
7. AI 활용 과정에서 개인정보, 출처, 저작권, 편향, 보안, 학습 부정행위 위험을 구분한다.
8. 기말 프로젝트로 작은 AI 데모 또는 AI 활용 결과물을 만들고, 그 한계와 위험을 설명한다.

### 4.2 매주 실습 필수

모든 주차에는 실습이 포함된다. 실습은 코드를 따라 치는 데서 끝나지 않고, 학생이 결과를 보고 해석하거나 실패 사례를 찾을 수 있도록 구성한다.

좋은 실습의 기준은 다음과 같다.

- 실행하면 눈에 보이는 결과가 나온다.
- 학생 자신의 입력, 이미지, 문장, 관심사가 들어갈 수 있다.
- 실패하거나 틀린 사례를 관찰할 수 있다.
- 수업 시간 안에 최소 결과를 낼 수 있다.
- AI 코딩 도우미를 사용할 여지가 있다.

### 4.3 AI 코딩 도구 활용

이 수업에서는 AI 코딩 도구 사용을 허용하고 장려한다. 다만 도구 사용 자체가 성취가 되지는 않는다. AI 도구는 학습을 돕는 동료이며, 최종 책임은 학생에게 있다.

대표적으로 다음 도구를 사용하거나 대체 도구로 보완한다.

- VS Code
- GitHub
- GitHub Copilot
- Antigravity 또는 유사 무료 코딩 에이전트
- ChatGPT, Claude, Gemini 등 대화형 AI
- Colab 또는 Jupyter Notebook

특정 도구의 무료 정책은 바뀔 수 있으므로, 과목은 특정 서비스 하나에 종속되지 않는다. 필수 목표는 AI 코딩 도우미와 협업해 코드를 만들고 검증하는 능력이다.

### 4.4 책임 있는 AI 활용

매주 실습에는 가능한 한 다음 네 가지 중 하나 이상을 포함한다.

| 점검 항목 | 질문 |
|---|---|
| 사실 검증 | AI가 말한 사실, 수치, 코드 설명이 맞는가 |
| 실행 검증 | AI가 만든 코드가 실제로 실행되는가 |
| 출처 검증 | 자료, 이미지, 텍스트, 코드의 출처를 설명할 수 있는가 |
| 위험 검증 | 개인정보, 저작권, 편향, 보안, 과도한 의존 위험은 없는가 |

금지 사항은 다음과 같다.

- 개인정보, 비밀번호, API 키, 비공개 자료를 AI 도구에 입력
- AI가 만든 내용을 본인이 작성한 것처럼 숨겨 제출
- 실행하지 않은 코드 결과를 제출
- 출처를 확인하지 않은 사실을 확정적으로 사용
- 이해하지 못한 코드를 그대로 제출
- 보안상 위험한 코드를 검토 없이 실행

### 6.1 AI 사용 평가 원칙

AI 도구 사용 자체는 감점 대상이 아니다. 오히려 잘 사용하면 긍정적으로 평가한다. 그러나 다음은 감점 대상이다.

- AI가 만든 코드를 이해하지 못한 채 제출
- 실행하지 않은 결과를 제출
- 오류 메시지를 숨김
- AI 사용 여부를 기록하지 않음
- 출처 없는 설명이나 허구의 참고자료 사용

좋은 제출물은 다음을 포함한다.

- 실행되는 코드
- 결과 화면 또는 로그
- AI 사용 프롬프트
- 오류와 수정 과정
- 내가 이해한 원리 설명
- 모델이 틀린 사례 또는 한계
- 개인정보, 출처, 편향, 보안, 과도한 의존성 중 최소 1개 위험 점검

## 7. AI 활용 윤리와 제출 규칙

이 과목은 AI 사용을 금지하지 않는다. 대신 AI 사용을 숨기는 것을 금지한다. 과제와 프로젝트에는 다음 항목을 포함한다.

```text
이 과제에서 사용한 AI 도구:
사용한 프롬프트:
AI가 도와준 부분:
내가 직접 수정하거나 검증한 부분:
아직 이해가 부족한 부분:
```

AI를 사용할 때 지켜야 할 규칙은 다음과 같다.

1. 개인정보를 AI 도구에 넣지 않는다.
2. 학교 계정, 비밀번호, API 키를 입력하지 않는다.
3. AI가 만든 코드도 직접 실행하고 확인한다.
4. AI가 말한 사실은 필요한 경우 출처를 확인한다.
5. 이해하지 못한 코드는 이해하지 못했다고 표시한다.
6. AI가 만든 산출물은 저작권과 사용 가능성을 확인한다.
7. AI가 만든 코드가 파일 삭제, 외부 전송, 비밀키 노출 같은 위험을 포함하지 않는지 확인한다.

## 10. 중간 미니 프로젝트

중간 미니 프로젝트는 정확도 경쟁이 아니라 학습 과정과 해석을 평가한다. 학생은 작은 모델을 만들고, 모델이 잘한 사례와 실패한 사례를 함께 분석한다.

예시 주제는 다음과 같다.

- 간단한 취향 분류기
- 작은 이미지 분류기
- 댓글 긍정/부정 분류기
- 학생이 만든 표 데이터 기반 예측기

필수 제출물은 다음과 같다.

- 실행 코드
- 결과 화면 또는 로그
- 실패 사례 3개
- AI 사용 로그
- 3분 발표 자료

## 11. 기말 프로젝트

기말 프로젝트는 큰 모델을 만드는 것이 아니라, 배운 개념을 사용해 작지만 실행되는 결과물을 만드는 것이다.

### 11.1 필수 요건

1. 실행 가능한 코드 또는 데모가 있다.
2. 데이터 또는 입력 예시가 있다.
3. AI 도구 사용 기록이 있다.
4. 결과가 실제로 실행되었음을 보여준다.
5. 실패 사례와 한계를 설명한다.
6. 딥러닝 또는 AI 개념 2개 이상을 연결해 설명한다.
7. 개인정보, 출처, 편향, 보안, 과도한 AI 의존성 중 최소 2개 위험을 점검한다.

### 11.2 권장 프로젝트 예시

- 내 사진 분류기
- 음식, 패션, 동물 이미지 분류기
- 리뷰 감성 분석기
- 공부 도우미 챗봇
- 간단한 추천 시스템
- AI가 만든 코드의 오류를 찾아 고친 프로젝트
- AI 답변의 환각과 출처 문제를 검증하는 도구
- 개인정보를 넣지 않는 안전한 AI 학습 도우미
- 나만의 데이터로 만든 예측기

### 11.3 피해야 할 프로젝트

- 프롬프트 입력 결과만 붙여넣은 보고서
- 실행 코드가 없는 아이디어 발표
- 출처 없는 AI 설명 모음
- 모델 성능만 있고 해석이 없는 결과
- 본인이 이해하지 못한 대형 코드
- 개인정보, API 키, 비공개 자료를 AI 도구에 넣은 결과물
- AI가 생성한 이미지, 코드, 문장의 출처와 사용 가능성을 설명하지 못하는 결과물

## 12. 수업 운영상 조정 기준

다음 신호가 보이면 강의 운영을 조정한다.

| 신호 | 조치 |
|---|---|
| 2주차 환경설정 완료율 70% 미만 | Colab 기반 대체 경로를 기본으로 전환 |
| 주차별 실습 완주율 70% 미만 | 다음 주 실습 난이도와 코드량 축소 |
| 중간 프로젝트에서 원리 설명 부족 | 9주차 전 보충 세션 추가 |
| AI 사용 로그 누락 30% 이상 | 제출 양식 단순화 및 예시 제공 |
| AI 답변 검증표 부실 제출 30% 이상 | 11주차 검증 실습을 보강하고 다음 과제 난이도 조정 |
| 기말 프로젝트가 실행되지 않는 비율 20% 이상 | 14주차를 디버깅 워크숍으로 전환 |
| 개인정보·API 키 입력 사례 발생 | 즉시 해당 과제 중단, 안전한 대체 데이터로 재수행 |
