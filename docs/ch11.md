# 11강. 생성형 AI의 원리와 폐해: 환각, 편향, 출처 검증

## Part A — 강의 (1교시, 90분)

### 강의 목표

이번 강의의 목표는 **언어모델이 문장을 만드는 원리**를 이해하고, 그 원리에서 **환각과 편향이 왜 발생하는지** 파악하는 것이다. 학생들은 이미 ChatGPT, Claude, Gemini 같은 생성형 AI를 사용하고 있다. 그러나 AI가 어떻게 답변을 만드는지, 왜 그럴듯하지만 틀린 답을 하는지를 이해하지 못하면 AI를 도구로 통제할 수 없다.

학생은 이번 시간 후 다음을 할 수 있어야 한다.

1. 언어모델이 "다음 토큰 예측"으로 문장을 생성하는 원리를 설명한다.
2. 프롬프트가 모델의 출력을 어떻게 바꾸는지 예를 들어 설명한다.
3. 환각이 발생하는 구조적 이유를 말한다.
4. 편향이 학습 데이터에서 오는 과정을 설명한다.
5. AI 답변을 "확인됨", "불확실", "틀림", "판단 보류" 네 등급으로 분류한다.
6. AI가 제시한 수치나 사례의 출처를 확인하는 절차를 수행한다.
7. 간단한 n-gram 모델을 실행하고 다음 단어 예측 결과를 해석한다.

이번 강의의 실습은 두 부분으로 구성된다. 첫째, 간단한 bigram 언어모델을 numpy로 만들어 "다음 단어 예측"이 어떻게 동작하는지 직접 본다. 둘째, 미리 준비한 AI 답변 예시를 검증 항목별로 점검하여 검증표를 만든다.

### 핵심 개념

| 용어 | 뜻 |
|---|---|
| 언어모델(language model) | 단어(토큰)의 나열에 확률을 부여하는 모델. 앞에 나온 단어를 보고 다음 단어가 무엇일지 예측한다 |
| 토큰(token) | 언어모델이 처리하는 텍스트의 최소 단위. 단어, 단어의 일부, 문장부호 등이 될 수 있다 |
| 다음 토큰 예측(next token prediction) | 앞에 나온 토큰들을 조건으로 다음 토큰의 확률 분포를 계산하는 것. 언어모델의 핵심 동작이다 |
| 프롬프트(prompt) | 사용자가 모델에게 주는 입력 텍스트. 모델은 이 텍스트를 조건으로 다음 토큰을 예측한다 |
| 컨텍스트(context) | 모델이 다음 토큰을 예측할 때 참고하는 앞쪽 텍스트의 범위 |
| 환각(hallucination) | 모델이 그럴듯하지만 사실이 아닌 내용을 생성하는 현상 |
| 편향(bias) | 학습 데이터에 포함된 치우침이 모델의 출력에 반영되는 현상 |
| 출처 검증(source verification) | AI가 제시한 정보의 원래 출처를 찾아 사실 여부를 확인하는 절차 |

### 11.1 언어모델이 문장을 만드는 방법

언어모델은 문장을 "한 번에" 만들지 않는다. **앞에 나온 단어를 보고 다음 단어를 하나씩 예측**하는 것을 반복한다. 이것이 "다음 토큰 예측"이다.

예를 들어 "딥러닝은"이라는 단어가 주어지면, 모델은 다음에 올 수 있는 단어마다 확률을 매긴다. 실습에서 만든 bigram 모델의 실행 결과를 보면 다음과 같다.

```text
'딥러닝은' 다음 → 데이터에서(33.3%), 신경망을(33.3%), 이미지(33.3%)
```

이 수치는 `practice/chapter11/results/11-1-ai-answer-audit.log`에서 확인한 실제 실행 결과다.

세 단어가 같은 확률을 가진 이유는 실습용 말뭉치에서 "딥러닝은" 뒤에 세 단어가 각각 한 번씩 나왔기 때문이다. 모델은 말뭉치에서 본 빈도를 확률로 바꾸어 다음 단어를 고른다.

이 과정을 더 구체적으로 정리하면 다음과 같다.

1. 사용자가 시작 단어를 준다.
2. 모델은 그 단어 뒤에 올 수 있는 후보 단어의 확률을 계산한다.
3. 확률에 따라 하나를 고른다.
4. 고른 단어를 붙인 뒤, 다시 다음 단어를 예측한다.
5. 이 과정을 문장이 끝날 때까지 반복한다.

실제 ChatGPT나 Claude 같은 대형 언어모델도 원리는 같다. 다만 두 가지가 다르다.

| 구분 | 실습의 bigram 모델 | 대형 언어모델 (GPT, Claude 등) |
|---|---|---|
| 참고하는 단어 수 | 바로 앞 1개 | 수천~수십만 개 (컨텍스트 윈도우) |
| 파라미터 수 | 말뭉치의 bigram 빈도표 | 수십억~수조 개 |
| 학습 데이터 | 16개 문장 | 인터넷 규모의 텍스트 |
| 생성 품질 | 짧고 반복적 | 길고 자연스러운 문장 |

핵심은 크기와 정교함이 다를 뿐, **"앞 토큰을 보고 다음 토큰을 예측한다"는 기본 동작은 같다**는 것이다.

실습 실행 결과에서 같은 시작 단어 "딥러닝은"으로 시드를 바꿔 문장을 생성하면 결과가 달라진다.

```text
[seed=  42] 딥러닝은 이미지 인식에 많이 사용된다
[seed= 123] 딥러닝은 이미지 인식에 많이 사용된다
[seed=   7] 딥러닝은 신경망을 여러 층으로 쌓아 복잡한 패턴을 찾는 방법이다
[seed=2024] 딥러닝은 이미지 인식에 많이 사용된다
[seed=  99] 딥러닝은 신경망을 여러 층으로 쌓아 복잡한 패턴을 찾는 방법이다
```

같은 질문에도 답이 달라질 수 있다. 이것은 모델이 확률적으로 다음 단어를 고르기 때문이다. 대형 언어모델에서도 같은 질문을 두 번 하면 약간 다른 답이 나오는 현상은 이 원리에서 비롯된다.

### 11.2 프롬프트의 역할

프롬프트는 사용자가 모델에게 주는 입력 텍스트다. 모델은 이 텍스트를 "조건"으로 삼아 다음 토큰을 예측한다.

프롬프트가 바뀌면 조건이 바뀌므로 출력도 달라진다. 같은 주제라도 질문 방식에 따라 다른 답이 나올 수 있다. 예를 들어 다음 네 프롬프트를 비교하면 차이가 크다.

| 프롬프트 | 기대되는 답변 방향 |
|---|---|
| "딥러닝을 설명해줘" | 넓고 일반적인 설명 |
| "딥러닝을 고등학생에게 비유로 설명해줘" | 쉬운 표현 중심의 설명 |
| "딥러닝의 한계를 3가지만 말해줘" | 한계에 초점을 맞춘 짧은 답변 |
| "딥러닝과 전통적인 프로그래밍의 차이를 표로 정리해줘" | 비교표 형식의 답변 |

프롬프트가 하는 일은 수학적으로 보면 "조건부 확률의 조건을 바꾸는 것"이다. 조건이 달라지면 다음 토큰의 확률 분포가 달라지고, 결과적으로 다른 문장이 나온다.

여기서 중요한 점이 있다. 프롬프트는 모델에게 "명령"이 아니다. 모델은 프롬프트를 이해하고 따르는 것이 아니라, 프롬프트 뒤에 올 가능성이 높은 텍스트를 생성하는 것이다. 모델이 지시를 따르는 것처럼 보이는 이유는 학습 데이터에 질문-답변 형식의 텍스트가 대량으로 포함되어 있고, 추가 학습(RLHF — Reinforcement Learning from Human Feedback, 사람의 피드백으로 모델 출력을 조정하는 학습 방법)으로 지시를 따르도록 조정했기 때문이다.

### 11.3 환각: 그럴듯하지만 틀린 답

**환각(hallucination)**은 모델이 그럴듯하지만 사실이 아닌 내용을 만들어내는 현상이다.

환각이 발생하는 구조적 이유는 언어모델의 핵심 동작에 있다.

- 언어모델은 "다음에 올 가능성이 높은 단어"를 고르는 것이지, "사실인 단어"를 고르는 것이 아니다.
- 모델은 학습 데이터에서 본 패턴을 바탕으로 자연스러운 문장을 만든다. 자연스러움과 사실은 다른 것이다.
- 모델에게는 "모른다"고 답하는 것보다 무언가를 생성하는 쪽의 확률이 높을 수 있다. 이 경우 모델은 모르는 내용도 자신 있게 답한다.

실습의 검증표에서 환각 사례를 보면 다음과 같다.

```text
질문: CNN은 어떤 문제에 가장 효과적인가?
AI 답변: CNN은 이미지 분류에서 항상 99% 이상의 정확도를 달성하며, 모든 이미지 관련
         문제에서 최고의 성능을 보인다.
검증 등급: 틀림
문제 유형: 환각/과장
```

이 답변이 환각인 이유는 두 가지다.

1. "항상 99%"는 사실이 아니다. 데이터셋, 클래스 수, 이미지 품질에 따라 정확도는 크게 달라진다.
2. "모든 이미지 관련 문제에서 최고"도 사실이 아니다. Vision Transformer 등 CNN이 아닌 구조가 일부 벤치마크에서 더 높은 성능을 보인다.

환각의 위험은 답변이 "그럴듯하다"는 데 있다. 딥러닝을 잘 모르는 사람이 읽으면 맞는 말처럼 보일 수 있다. 그래서 AI 답변을 받으면 반드시 검증이 필요하다.

### 11.4 편향: 학습 데이터가 만드는 치우침

**편향(bias)**은 모델이 특정 방향으로 치우친 답변을 하는 현상이다. 편향의 주요 원인은 학습 데이터에 있다.

- 모델은 학습 데이터에 많이 나온 관점을 더 자주 생성한다.
- 특정 집단, 지역, 언어, 문화가 학습 데이터에 더 많이 포함되어 있으면, 모델의 답변은 그쪽으로 치우친다.
- 학습 데이터에 포함된 고정관념이나 차별적 표현을 모델이 그대로 학습할 수 있다.

편향은 환각과 다르다. 환각은 사실이 아닌 내용을 만들어내는 것이고, 편향은 사실일 수 있지만 한쪽 관점만 제시하는 것이다.

| 구분 | 환각 | 편향 |
|---|---|---|
| 내용 | 사실이 아님 | 사실일 수 있으나 한쪽만 제시 |
| 원인 | 모델이 모르는 내용을 생성 | 학습 데이터의 분포가 치우침 |
| 위험 | 틀린 정보를 사실로 믿음 | 다른 관점을 놓침 |
| 발견 방법 | 사실 확인 (출처 검증) | 반대 관점이 빠져 있는지 확인 |

실습 검증표에서 편향과 관련된 사례를 보면 다음과 같다.

```text
질문: AI는 편향 없이 공정한 판단을 하는가?
AI 답변: AI는 데이터에서 학습하므로, 학습 데이터에 편향이 있으면 AI의 판단도 편향된다.
         예를 들어 채용 심사에 사용된 AI가 과거 채용 데이터에서 특정 성별을 선호하는
         패턴을 학습한 사례가 있다.
검증 등급: 확인됨
```

이 답변은 편향의 원리를 올바르게 설명하고 있다. 2018년에 보도된 아마존의 채용 AI 사례와 일치한다. 다만 이 답변 자체도 "AI는 편향된다"는 한 방향의 설명이므로, 편향을 줄이려는 연구와 기법을 함께 언급하면 더 균형 잡힌 답변이 된다.

### 11.5 출처 검증: AI 답변을 확인하는 절차

AI 답변을 받으면 다음 네 등급으로 분류한다.

| 등급 | 뜻 | 기준 |
|---|---|---|
| 확인됨 | 사실이 맞다 | 공식 문서, 교과서, 신뢰할 수 있는 출처에서 같은 내용을 확인했다 |
| 불확실 | 맞을 수도 있지만 단정할 수 없다 | 일부는 맞지만 과장이나 단순화가 섞여 있다 |
| 틀림 | 사실이 아니다 | 출처와 대조한 결과 내용이 다르거나, 존재하지 않는 사실이다 |
| 판단 보류 | 확인할 방법이 없다 | 공식 출처가 없거나, 비공개 정보여서 사실 여부를 판단할 수 없다 |

실습 실행 결과에서 검증 등급별 빈도는 다음과 같다.

```text
불확실: 1건
틀림: 1건
판단 보류: 1건
확인됨: 2건
```

이 수치는 `practice/chapter11/results/11-1-ai-answer-audit.log`에서 확인한 실제 실행 결과다.

5개 AI 답변 중 "확인됨"은 2건뿐이다. 나머지 3건은 불확실하거나, 틀렸거나, 판단을 보류해야 했다. AI 답변을 그대로 사용하면 5건 중 3건에서 문제가 생길 수 있다.

출처 확인이 실패하는 대표적 경우는 다음과 같다.

- AI가 제시한 논문 제목이 실제로 존재하지 않는다.
- AI가 말한 수치가 원래 출처와 다르다.
- AI가 인용한 인물이 해당 주장을 한 적이 없다.
- AI가 근거로 든 URL이 존재하지 않는다.
- 공식 발표가 아닌 비공식 정보를 확정적으로 말한다.

실습 검증표의 판단 보류 사례가 마지막 경우에 해당한다.

```text
질문: GPT-4의 파라미터 수는 몇 개인가?
AI 답변: GPT-4는 약 1.8조 개의 파라미터를 가지고 있으며, 8개의 전문가 모델을
         혼합한 MoE 구조를 사용한다.
검증 등급: 판단 보류
문제 유형: 출처 미확인
검증 메모: OpenAI는 GPT-4의 정확한 파라미터 수와 내부 구조를 공식 발표하지 않았다.
```

이 사례는 AI가 비공식 유출 정보를 마치 확정된 사실처럼 말한 것이다. 공식 출처로 확인할 수 없으므로 "판단 보류"가 적절하다.

### 핵심 정리

- 언어모델은 앞에 나온 토큰을 보고 다음 토큰을 예측하는 방식으로 문장을 만든다.
- 프롬프트는 모델에게 주는 조건이다. 조건이 바뀌면 출력이 달라진다.
- 환각은 모델이 "자연스러운 문장"을 만드는 데 집중하기 때문에 발생한다. 자연스러움과 사실은 다르다.
- 편향은 학습 데이터의 치우침에서 온다. 모델은 많이 본 관점을 더 자주 생성한다.
- AI 답변은 "확인됨", "불확실", "틀림", "판단 보류" 네 등급으로 분류해야 한다.
- 출처를 확인하지 않은 AI 답변을 그대로 사용하면 안 된다.

### 실습 절차

3. 검증표를 출력하고 CSV로 저장한다.

##### bigram 모델의 실행 결과

실행 로그 기준으로 bigram 모델의 기본 통계는 다음과 같다.

```text
말뭉치 문장 수: 16
bigram 모델의 고유 앞단어 수: 62
bigram 총 빈도: 76
```

"딥러닝은" 뒤에 올 수 있는 다음 단어의 예측 결과는 다음과 같다.

```text
'딥러닝은' 다음 → 데이터에서(33.3%), 신경망을(33.3%), 이미지(33.3%)
```

세 단어가 모두 같은 확률인 이유는 말뭉치에서 "딥러닝은" 뒤에 세 단어가 각각 한 번씩 나왔기 때문이다.

다른 시작 단어의 예측 결과도 확인할 수 있다.

```text
'모델은' 다음 → 데이터에서(25.0%), 훈련(25.0%), 항상(25.0%), 새로운(25.0%)
'데이터가' 다음 → 편향되면(50.0%), 부족하면(50.0%)
'프롬프트를' 다음 → 바꾸면(100.0%)
```

"프롬프트를" 뒤에는 "바꾸면"만 나올 수 있다. 말뭉치에 "프롬프트를 바꾸면" 한 문장밖에 없기 때문이다. 말뭉치가 작으면 선택지가 적다.

##### 문장 생성 결과

같은 시작 단어 "모델은"으로 시드를 바꿔 문장을 생성한 결과는 다음과 같다.

```text
[seed=  42] 모델은 새로운 상황에 약하다
[seed= 123] 모델은 항상 정확하지 않다
[seed=   7] 모델은 항상 정확하지 않다
[seed=2024] 모델은 항상 정확하지 않다
[seed=  99] 모델은 항상 정확하지 않다
```

5개 중 4개가 "모델은 항상 정확하지 않다"로 같은 문장이다. 이것은 말뭉치가 작아서 "항상" 뒤에 올 수 있는 단어가 "정확하지" 하나뿐이기 때문이다. 일단 "항상"이 선택되면 그 뒤로는 같은 경로를 따른다.

이 관찰에서 알 수 있는 것은 다음과 같다.

1. 같은 시작 단어라도 무작위 선택(시드)에 따라 다른 문장이 나올 수 있다.
2. bigram 모델은 바로 앞 한 단어만 보므로 문맥을 길게 기억하지 못한다.
3. 말뭉치가 작으면 선택지가 적어 비슷한 문장이 반복된다.
4. 실제 대형 언어모델도 원리는 같지만, 볼 수 있는 토큰 수(컨텍스트)가 훨씬 많고 파라미터가 크다.

##### AI 답변 검증표

실행 결과에서 5개 AI 답변의 검증 결과는 다음과 같다.

| 번호 | 질문 | 검증 등급 | 문제 유형 |
|---:|---|---|---|
| 1 | 딥러닝의 창시자는 누구인가? | 불확실 | 과장/단순화 |
| 2 | CNN은 어떤 문제에 가장 효과적인가? | 틀림 | 환각/과장 |
| 3 | 학습률이 너무 크면 어떻게 되는가? | 확인됨 | 없음 |
| 4 | GPT-4의 파라미터 수는 몇 개인가? | 판단 보류 | 출처 미확인 |
| 5 | AI는 편향 없이 공정한 판단을 하는가? | 확인됨 | 없음 |

이 표는 `practice/chapter11/results/ai_answer_audit.csv`에서 가져온 것이다.

각 검증 등급이 매겨진 이유를 정리하면 다음과 같다.

- **1번 (불확실)**: 역전파를 힌턴 혼자 발명한 것이 아니다. 1986년 논문은 Rumelhart, Hinton, Williams 공저이며, 역전파 아이디어는 그 이전에도 여러 연구자가 제안했다.
- **2번 (틀림)**: "항상 99%"는 과장이다. 데이터셋, 클래스 수, 이미지 품질에 따라 정확도는 크게 달라진다.
- **3번 (확인됨)**: 학습률이 크면 손실이 발산한다는 설명은 6주차 실습 결과와 일치한다.
- **4번 (판단 보류)**: OpenAI는 GPT-4의 파라미터 수와 내부 구조를 공식 발표하지 않았다.
- **5번 (확인됨)**: 편향의 원리와 채용 AI 사례는 실제 보도와 일치한다.

#### 11.7 환각 사례를 직접 찾고 수정 프롬프트를 만들기

검증표에서 2번 답변이 환각이었다. 이 답변을 받았을 때 어떻게 대응해야 하는지 연습한다.

**환각이 포함된 AI 답변:**

> CNN은 이미지 분류에서 항상 99% 이상의 정확도를 달성하며, 모든 이미지 관련 문제에서 최고의 성능을 보인다.

**문제점:**

- "항상 99%"는 특정 벤치마크(예: MNIST)에서만 해당될 수 있고, 일반화할 수 없다.
- "모든 이미지 관련 문제에서 최고"도 사실이 아니다.

**수정 프롬프트 예시:**

```text
CNN이 이미지 분류에서 효과적인 이유를 설명해줘.
단, "항상", "모든", "최고" 같은 과장 표현을 쓰지 말고,
CNN이 잘 못하는 경우도 함께 알려줘.
데이터셋 이름과 정확도 수치를 말할 때는 출처를 밝혀줘.
```

이 수정 프롬프트는 세 가지를 바꾸었다.

1. 과장 표현을 쓰지 말라고 조건을 넣었다.
2. 못하는 경우를 함께 말하라고 했다.
3. 수치를 말할 때 출처를 밝히라고 했다.

프롬프트를 바꾸면 AI 답변의 품질이 달라질 수 있다. 그러나 프롬프트를 아무리 잘 써도 AI 답변의 사실 여부를 프롬프트만으로 보장할 수는 없다. 검증은 별도로 해야 한다.

### AI 활용 가이드

#### 11.8 같은 질문을 여러 방식으로 물어보기

이번 장에서는 AI 활용 자체가 실습이다. 다음 실험을 한다.

**실험 1: 프롬프트 비교**

같은 주제에 대해 프롬프트를 바꿔가며 AI 답변을 비교한다. 다음 표를 채운다.

| 프롬프트 | AI 답변의 특징 | 과장 표현 유무 | 출처 유무 |
|---|---|---|---|
| "딥러닝을 설명해줘" | | | |
| "딥러닝의 한계를 3가지만 말해줘" | | | |
| "딥러닝을 비판적으로 설명해줘. 과장하지 마" | | | |

**실험 2: 사실 확인이 필요한 답변 찾기**

AI에게 다음 질문을 하고, 답변 중 사실 확인이 필요한 부분을 표시한다.

```text
딥러닝에서 가장 중요한 발전 3가지를 연도와 함께 알려줘.
```

AI 답변에서 다음을 확인한다.

- 연도가 맞는가?
- 인물 이름이 맞는가?
- 논문이나 기술의 이름이 실재하는가?
- "최초", "가장", "혁명적" 같은 과장 표현이 있는가?

**실험 3: 출처 확인 실패 사례 찾기**

AI에게 특정 수치나 통계를 물어보고, 그 출처를 확인해 본다.

```text
전 세계에서 AI를 가장 많이 사용하는 산업 분야 상위 5개를 수치와 함께 알려줘.
```

AI가 제시한 수치의 출처를 인터넷에서 찾아본다. 찾을 수 없는 수치가 있다면 그것이 출처 확인 실패 사례다.

### 결과 해석

이번 실습의 결과를 해석할 때 중요한 점은 다음과 같다.

- 언어모델은 "다음에 올 가능성이 높은 단어"를 고르는 것이지, "사실인 단어"를 고르는 것이 아니다. 이 차이가 환각의 근본 원인이다.
- 실습에서 5개 AI 답변을 검증한 결과, "확인됨"은 2건, "불확실"은 1건, "틀림"은 1건, "판단 보류"는 1건이었다. 무조건 믿었다면 5건 중 3건에서 문제가 생겼을 것이다.
- 같은 시작 단어로 문장을 생성해도 시드에 따라 결과가 달라졌다. 대형 언어모델에서도 같은 질문에 다른 답이 나오는 것은 이 원리에서 비롯된다.
- 프롬프트를 바꾸면 답변의 방향이 달라진다. 그러나 프롬프트를 잘 쓰는 것과 답변을 검증하는 것은 별개의 작업이다.

## 핵심 정리

- 언어모델은 앞에 나온 토큰을 보고 다음 토큰을 예측하는 방식으로 문장을 만든다.
- 프롬프트는 모델에게 주는 조건이다. 조건이 바뀌면 출력이 달라진다.
- 환각은 모델이 "자연스러운 문장"을 만드는 데 집중하기 때문에 발생한다. 자연스러움과 사실은 다르다.
- 편향은 학습 데이터의 치우침에서 온다.
- AI 답변은 네 등급(확인됨, 불확실, 틀림, 판단 보류)으로 분류해야 한다.
- 출처를 확인하지 않은 AI 답변을 그대로 사용하면 안 된다.
- 프롬프트를 잘 쓰는 것과 답변을 검증하는 것은 별개의 작업이다.
