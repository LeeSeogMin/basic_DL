# 제8장 중간 미니 프로젝트 — 1~7장을 하나로 잇는다

---

이 장은 교재 장이 아니다. 새 이론이 없고 정해진 실습 코드도 없다. 1장부터 7장까지 나눠서 해 본 일을 학생이 직접 하나로 잇는 주간이다. `강의계획서.md`의 평가 항목 중 **중간 고사(20%)**가 이 프로젝트다.

앞선 일곱 주 동안 실습은 이미 만들어진 코드를 받아 값을 바꿔 보는 방식이었다. 여기서는 무엇을 풀지부터 학생이 정한다.

---

## [전반부] 프로젝트 설계

---

### 학습 목표

- 풀 문제를 스스로 정하고, 그 문제가 분류인지 회귀인지 가른다
- 데이터를 준비하고 특성과 라벨을 구분한다
- 기준선을 먼저 만들고, 그 위에서 모델을 비교한다
- 훈련 성적과 테스트 성적을 함께 재서 과적합 여부를 확인한다
- 모델이 틀린 사례를 찾아 왜 틀렸는지 설명한다

---

### 1. 지난 일곱 주에서 무엇을 가져오는가

프로젝트는 새로 배우는 자리가 아니라 흩어져 있던 것을 붙이는 자리다. 각 장에서 손으로 확인한 것이 프로젝트의 어느 칸에 들어가는지 먼저 맞춘다.

**표 8.1** 앞 장과 프로젝트의 대응

| 장 | 그때 확인한 것 | 프로젝트에서 답할 것 |
|---|---|---|
| 3장 | 표에서 특성과 라벨을 갈랐다 | 내 입력은 무엇이고 정답은 무엇인가 |
| 4장 | 기준선·정확도·혼동행렬로 모델을 쟀다 | 내 모델은 기준선을 넘었는가, 어느 방향으로 틀리는가 |
| 5장 | 선 하나로 못 나누는 데이터에 은닉층을 넣었다 | 내 데이터는 선 하나로 갈리는가 |
| 6장 | 학습률을 바꿔 학습을 망가뜨려 봤다 | 손실이 실제로 내려갔는가 |
| 7장 | 훈련 성적과 검증 성적이 갈라지는 지점을 봤다 | 두 성적의 차이가 얼마인가 |

○ **표를 채우지 못하는 칸이 있으면 거기가 약한 자리다**
  - 그 장의 실습을 다시 실행한 뒤 프로젝트로 돌아온다
  - 프로젝트에서 처음 배우려 하면 시간이 모자란다

---

### 2. 주제를 고르는 두 가지 기준

1장에서 "AI에게 맡길 일"을 두 질문으로 갈랐다. 같은 자를 자기 주제에 댄다.

○ **비슷한 예시를 충분히 모을 수 있는가**
  - 클래스마다 최소 수십 건이 필요하다. 한쪽이 몇 건뿐이면 모델은 많은 쪽으로 쏠린다
  - 직접 만들 수 있으면 만든다. 합성 데이터를 써도 된다

○ **정답이 하나로 정해지는가**
  - 라벨을 붙일 수 있어야 채점이 된다
  - "좋은 글인가" 같은 문제는 채점 기준이 없어서 이 프로젝트에 맞지 않는다

**표 8.2** 주제 유형과 출발점

| 유형 | 예 | 어느 장을 다시 보는가 |
|---|---|---|
| 취향 분류기 | 영화·음식·음악 취향으로 유형을 가른다 | 3장, 4장 |
| 작은 이미지 분류기 | 손글씨 숫자, 간단한 도형 | 4장, 9장 예고 |
| 문장 분류기 | 짧은 리뷰를 긍정·부정으로 가른다 | 3장, 4장 |
| 표 데이터 예측기 | 직접 만든 표로 결과를 예측한다 | 3장, 4장, 7장 |

○ **피할 주제**
  - GPU가 있어야 도는 대형 모델. 이 수업의 패키지는 `numpy`, `pandas`, `matplotlib`, `scikit-learn`, `scipy`뿐이다
  - 데이터를 구할 방법이 없는 주제
  - 대화형 AI에 물어본 답을 그대로 붙여 넣는 것. 이것은 모델을 만든 것이 아니다

---

### 3. 계획서 한 장

코드를 쓰기 전에 아래를 채운다. 나중에 바뀌어도 된다. 시작 전에 한 번 적어 두면 무엇이 빠졌는지 보인다.

```text
제목:
문제:        무엇을 무엇으로 가르는가
데이터:      몇 건인가. 어디서 왔는가. 합성인가 실제인가
라벨:        정답을 어떻게 붙였는가
기준선:      비교 상대는 무엇인가
모델:        무엇을 쓸 계획인가
평가:        정확도 외에 무엇을 볼 것인가
예상 난관:   어디서 막힐 것 같은가
AI 도구:     어떤 작업에 쓸 계획인가
```

○ **기준선 칸을 비워 두지 않는다**
  - 4장에서 확인했다. 비교 상대가 없으면 정확도 숫자만으로는 잘했는지 알 수 없다
  - 가장 흔한 클래스로 전부 찍는 모델이 기준선이다

---

### 4. 실패를 숨기지 않는다

이 프로젝트는 정확도 순위를 매기지 않는다. 모델이 틀렸는데 왜 틀렸는지 설명한 프로젝트가, 정확도만 높고 해석이 없는 프로젝트보다 점수가 높다.

**표 8.3** 채점이 갈리는 지점

| 인정되는 것 | 감점되는 것 |
|---|---|
| 모델이 틀린 사례를 찾아 원인을 적었다 | 정확도 숫자만 있고 해석이 없다 |
| AI가 쓴 부분과 내가 고친 부분을 갈라 적었다 | AI가 만든 코드를 그대로 냈다 |
| 훈련 성적과 테스트 성적을 함께 적었다 | 훈련 성적만 보고 잘한다고 적었다 |
| 기준선과 비교했다 | 비교 상대 없이 정확도만 적었다 |
| 코드가 실행된다 | 코드가 실행되지 않는다 |

○ 4장 실습 4.1에서 모델이 틀린 세 명은 모두 경계선 가까이에 있었다. 엉뚱한 곳에서 틀린 것이 아니라 두 그룹이 섞이는 구간에서 틀렸다. 자기 프로젝트의 오류도 같은 방식으로 읽는다

## [후반부] 제작

---

### 실행 환경

```bash
cd practice
python -m pip install -r requirements.txt
```

새 패키지를 설치하지 않는다. 앞선 장의 실습 코드를 열어 필요한 부분을 가져다 쓴다.

○ **개인정보 주의**
  - 실제 사람의 이름·학번·연락처를 데이터에 넣지 않는다
  - 합성 데이터를 쓰면 코드 주석과 발표 자료 양쪽에 "합성 데이터"라고 적는다

---

### 제작 순서

1. **주제를 확정하고 계획서를 채운다.** 교수자에게 주제를 확인받는다
2. **데이터를 준비한다.** 직접 만들거나, 공개 데이터를 쓰거나, `make_classification`·`make_moons`·`make_circles`로 만든다
3. **훈련과 테스트로 나눈다.** 3장·4장에서 한 방식 그대로다. 테스트 데이터는 마지막에 한 번만 쓴다
4. **기준선을 먼저 잰다.** 이 값이 출발선이다
5. **모델을 학습시킨다.** 4~7장에서 쓴 것 중 하나를 고른다
6. **훈련 정확도와 테스트 정확도를 함께 출력한다.** 두 값의 차이가 과적합 신호다
7. **혼동행렬을 출력한다.** 어느 방향으로 틀리는지 본다
8. **틀린 사례를 세 건 골라 원인을 한 줄씩 적는다**

○ **4번을 건너뛰지 않는다** — 기준선 없이 얻은 정확도는 해석할 수 없다

○ **6번에서 차이가 크면** — 7장 실습 7.2에서 쓴 방법을 적용한 뒤 다시 잰다

---

### 발표에 담을 것

발표는 3분이다. 아래 일곱 가지를 순서대로 말한다.

| 순서 | 내용 |
|---:|---|
| 1 | 무엇을 무엇으로 가르는가 (한 문장) |
| 2 | 데이터 몇 건, 어떤 특성, 합성인가 실제인가 |
| 3 | 기준선 값 |
| 4 | 쓴 모델과 테스트 정확도 |
| 5 | 혼동행렬에서 어느 방향으로 많이 틀렸는가 |
| 6 | 틀린 사례 하나와 그 원인 |
| 7 | AI 도구로 무엇을 했고 무엇을 직접 고쳤는가 |

○ 정확도가 낮아도 3번부터 6번을 설명하면 발표가 성립한다

---

### AI 도구를 쓰는 범위

**표 8.4** 맡길 수 있는 일과 넘길 수 없는 일

| 맡길 수 있다 | 넘길 수 없다 |
|---|---|
| 코드 작성 보조 | 주제 결정 |
| 오류 메시지 풀이 | 결과 해석과 실패 분석 |
| 시각화 코드 생성 | 발표 내용 전체 작성 |
| 모델 후보 제안 | 읽지 않은 코드를 그대로 제출 |

○ 2장에서 정한 순서를 그대로 쓴다. 받은 코드는 실행해 보고, 무엇을 하는 코드인지 한 줄로 말할 수 있을 때만 쓴다

○ 12장에서 다시 다룬다. 지금은 "실행해 보지 않은 코드를 내지 않는다" 하나만 지킨다
