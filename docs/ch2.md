# 2강. AI 코딩 작업실 만들기

## 강의 목표

이번 강의의 목표는 딥러닝 실습을 시작할 수 있는 개인 작업실을 만드는 것이다. 여기서 작업실은 책상이나 실습실을 뜻하지 않는다. **VS Code에서 Python 파일을 만들고, 실행하고, 오류를 확인하고, AI 코딩 도구에게 도움을 요청할 수 있는 상태**를 뜻한다.

학생은 이번 시간 후 다음을 할 수 있어야 한다.

1. VS Code에서 수업 폴더를 열고 Python 파일을 만든다.
2. 터미널에서 Python 파일을 실행한다.
3. GitHub 저장소를 만들고 실습 파일을 올린다.
4. GitHub Copilot, Antigravity, ChatGPT, Claude 같은 AI 도구에게 코드 설명과 오류 수정을 요청한다.
5. AI가 만든 코드와 설명을 그대로 믿지 않고 직접 실행해 확인한다.
6. 비밀번호, API 키, 개인정보를 AI 도구에 입력하지 않는다.

이번 강의는 딥러닝 모델을 바로 학습시키지 않는다. 대신 앞으로 모델을 학습시키기 위한 가장 기본적인 능력, 즉 **내 컴퓨터에서 코드가 실제로 실행되는지 확인하는 능력**을 만든다.

## 2.1 오늘 만들 작업실

딥러닝 실습에는 여러 도구가 필요하다. 그러나 각 도구의 역할은 복잡하지 않다. 다음 표처럼 생각하면 된다.

| 도구 | 수업에서의 역할 | 학생이 확인할 것 |
|---|---|---|
| VS Code | 코드를 작성하는 편집기 | 폴더를 열고 `.py` 파일을 만들 수 있는가 |
| Python | 코드를 실행하는 언어와 실행기 | `python3` 또는 `.venv/bin/python`으로 파일이 실행되는가 |
| 터미널 | 컴퓨터에게 직접 명령을 입력하는 창 | 현재 폴더 위치와 실행 명령을 확인할 수 있는가 |
| GitHub | 실습 파일을 저장하고 제출하는 공간 | 저장소 링크를 제출할 수 있는가 |
| GitHub Copilot | VS Code 안에서 코드 작성과 설명을 돕는 AI | AI 제안을 직접 실행해 확인했는가 |
| Antigravity | AI 에이전트가 계획, 코드 작성, 실행을 도울 수 있는 개발 도구 | 에이전트가 한 일을 그대로 믿지 않고 확인했는가 |
| Colab | 로컬 설치 실패 시 쓰는 브라우저 대체 환경 | 웹에서 Python 코드를 실행할 수 있는가 |

여기서 중요한 도구는 하나가 아니다. 특정 도구가 설치되지 않거나 무료 사용량이 제한되더라도 수업을 계속할 수 있어야 한다. 따라서 이 수업의 필수 목표는 "Copilot을 반드시 쓰는 것"이나 "Antigravity를 반드시 쓰는 것"이 아니다. 필수 목표는 **AI 코딩 도우미와 협업하되, 마지막에는 내가 실행하고 검증하는 것**이다.

현재 공식 문서 기준으로 GitHub Copilot은 VS Code에서 사용할 수 있고, 구독이 없는 사용자는 제한된 Free 플랜으로 시작할 수 있다. 다만 무료 사용량과 제공 기능은 바뀔 수 있다. Google Antigravity는 Google이 제공하는 agentic development platform이며, 공식 codelab은 로컬 설치와 Chrome, Gmail 계정을 전제로 안내한다. 따라서 수업에서는 Copilot과 Antigravity를 대표 도구로 사용하되, 계정이나 정책 문제로 사용이 어려운 경우 ChatGPT, Claude, Gemini, Colab 등으로 대체한다.

## 2.2 폴더를 만들고 VS Code에서 열기

코드는 반드시 어딘가의 폴더 안에 있어야 한다. 폴더가 없으면 파일이 흩어지고, 나중에 GitHub에 올리거나 오류를 찾기 어렵다.

이번 시간에는 다음 폴더 구조를 만든다.

```text
basic-dl-week02/
├── hello_ai.py
└── ai_log.md
```

각 파일의 역할은 다음과 같다.

| 파일 | 역할 |
|---|---|
| `hello_ai.py` | 오늘 실행할 첫 Python 코드 |
| `ai_log.md` | AI에게 물어본 내용, AI 답변, 내가 고친 내용을 기록 |

VS Code에서는 `File > Open Folder`를 눌러 `basic-dl-week02` 폴더를 연다. 폴더를 연 뒤 왼쪽 탐색기에서 `hello_ai.py`를 만든다. 파일 이름은 정확해야 한다. `hello_ai.txt`나 `hello_ai.py.txt`로 만들면 Python 파일이 아니다.

## 2.3 첫 Python 파일 실행하기

첫 실습 코드는 복잡하지 않아야 한다. 이번 시간의 목적은 딥러닝 모델을 만드는 것이 아니라, **파일을 만들고 실행하고 결과를 확인하는 것**이다.

다음 코드를 `hello_ai.py`에 작성한다.

```python
name = "민지"
interest = "이미지 분류"
goal = "AI가 만든 코드를 실행하고 검증하기"

print(f"{name} 학생은 {interest}에 관심이 있다.")
print(f"오늘의 목표는 {goal}이다.")
```

이 코드는 세 가지 정보를 출력한다.

1. 학생 이름
2. 관심 분야
3. 오늘의 목표

터미널에서 다음 명령을 실행한다.

```bash
python3 hello_ai.py
```

Windows에서 `python3`가 동작하지 않으면 다음 명령을 시도한다.

```bash
python hello_ai.py
```

실행 결과는 학생마다 조금씩 달라도 된다. 중요한 것은 출력이 실제로 화면에 나타나는 것이다.

수업 저장소의 예제 코드는 `practice/chapter2/code/2-1-hello-ai.py`에 있다. 이 코드는 하네스로 실제 실행했고, 실행 로그는 `practice/chapter2/results/2-1-hello-ai.log`에 저장되어 있다.

로그에는 다음 출력이 기록되어 있다.

```text
=== 2주차 첫 Python 실행 ===
민지 학생은 이미지 분류에 관심이 있으며, 오늘의 목표는 'AI가 만든 코드를 실행하고 검증하기'이다.
```

이 출력은 임의로 만든 예시가 아니라 실제 실행 로그에서 확인한 결과다.

## 2.4 AI에게 코드 설명을 요청하기

이제 AI 코딩 도구를 사용한다. 단, AI에게 코드를 대신 쓰게 하기 전에 먼저 코드를 설명하게 한다. 설명을 요청하면 학생은 코드의 흐름을 더 쉽게 확인할 수 있다.

다음 프롬프트를 사용한다.

```text
다음 Python 코드를 학부 2학년이 이해할 수 있게 설명해줘.
각 줄이 무엇을 하는지 구체적으로 말해줘.

[여기에 hello_ai.py 코드 붙여넣기]
```

AI 답변을 받은 뒤에는 다음 표를 채운다.

| 확인 항목 | 내 판단 |
|---|---|
| AI가 `name`, `interest`, `goal`의 역할을 맞게 설명했는가 |  |
| AI가 `print()`의 역할을 맞게 설명했는가 |  |
| AI 설명 중 모호하거나 과장된 표현이 있었는가 |  |
| 내가 직접 실행한 결과와 AI 설명이 일치했는가 |  |

여기서 중요한 점은 AI 설명이 항상 맞지는 않는다는 것이다. 아주 쉬운 코드에서도 AI는 불필요하게 어려운 용어를 쓰거나, 코드에 없는 기능을 설명할 수 있다. 따라서 설명은 참고자료이고, 최종 확인은 실행 결과로 한다.

## 2.5 오류 메시지로 디버깅하기

프로그래밍을 배울 때 오류 메시지는 실패의 증거가 아니라 학습 자료다. 오류 메시지는 컴퓨터가 "어디에서 이해하지 못했는지" 알려주는 문장이다.

다음 코드처럼 일부러 따옴표 하나를 지워본다.

```python
name = "민지
print(name)
```

이 코드는 실행되지 않는다. Python은 문자열이 어디에서 끝나는지 알 수 없기 때문이다.

오류가 나면 다음 순서로 처리한다.

1. 오류 메시지를 복사한다.
2. AI에게 오류 메시지를 붙여넣는다.
3. "고쳐줘"라고만 하지 말고, 왜 오류인지 설명해달라고 요청한다.
4. AI가 제안한 수정 코드를 직접 실행한다.
5. 실행이 성공했는지 기록한다.

추천 프롬프트는 다음과 같다.

```text
다음 Python 오류 메시지를 설명해줘.
오류가 난 이유를 한 문장으로 말하고,
수정된 코드를 제시해줘.
단, 내가 초보자라고 가정하고 설명해줘.

[여기에 오류 메시지 붙여넣기]
```

오류 수정 기록은 다음 형식으로 남긴다.

| 항목 | 내용 |
|---|---|
| 내가 만든 오류 | 따옴표 하나 삭제 |
| 오류 메시지 핵심 | 문자열이 끝나지 않음 |
| AI의 설명 |  |
| 내가 직접 고친 코드 |  |
| 실행 성공 여부 |  |

이 과정의 핵심은 AI가 고쳐줬다는 사실이 아니다. **오류 메시지를 읽고, AI 설명을 비교하고, 수정된 코드가 실제로 실행되는지 확인한 것**이 핵심이다.

## 2.6 GitHub에 첫 저장소 만들기

GitHub는 코드를 저장하고 공유하는 공간이다. 이번 수업에서는 복잡한 Git 명령을 먼저 배우지 않는다. 웹사이트에서 저장소를 만들고 파일을 올리는 방식으로 시작한다.

절차는 다음과 같다.

1. GitHub에 로그인한다.
2. `New repository`를 누른다.
3. 저장소 이름을 `basic-dl-week02`로 입력한다.
4. 공개 여부는 수업 지시에 따른다. 공개가 부담되면 비공개 저장소를 사용한다.
5. `hello_ai.py`와 `ai_log.md`를 업로드한다.
6. 저장소 링크를 복사한다.

저장소 링크는 다음과 같은 모양이다.

```text
https://github.com/사용자이름/basic-dl-week02
```

GitHub 저장소는 과제 제출물의 일부다. 다만 계정 생성이나 인증 문제가 있으면 파일 제출로 대체할 수 있다. 수업의 목적은 GitHub 계정을 평가하는 것이 아니라, 실습 파일과 실행 과정을 남기는 것이다.

## 2.7 책임 있는 AI 사용: 넣으면 안 되는 정보

AI 도구는 편리하지만, 아무 정보나 입력해도 되는 도구가 아니다. 특히 코딩 도구는 파일, 터미널, 브라우저와 연결될 수 있으므로 더 조심해야 한다.

다음 정보는 AI 도구에 입력하지 않는다.

| 입력 금지 정보 | 이유 |
|---|---|
| 학교 계정 비밀번호 | 계정 탈취 위험 |
| GitHub 비밀번호 또는 토큰 | 저장소 접근권 유출 위험 |
| API 키 | 외부 서비스 비용 발생 또는 악용 위험 |
| 주민등록번호, 전화번호, 주소 | 개인정보 유출 위험 |
| 친구나 가족의 개인정보 | 동의 없는 정보 제공 |
| 비공개 과제 답안 | 학습 부정행위 위험 |

또한 AI가 만든 코드를 실행하기 전에 다음을 확인한다.

| 확인 항목 | 질문 |
|---|---|
| 파일 삭제 | 코드가 `delete`, `remove`, `rm` 같은 동작을 하는가 |
| 외부 전송 | 코드가 모르는 웹사이트로 데이터를 보내는가 |
| 비밀키 출력 | 코드가 비밀번호나 API 키를 화면에 출력하는가 |
| 과도한 설치 | 이유 없이 많은 패키지를 설치하라고 하는가 |
| 이해 부족 | 내가 설명하지 못하는 코드가 포함되어 있는가 |

이번 시간의 안전 원칙은 단순하다.

> AI에게 물어볼 수는 있지만, 실행 버튼을 누르는 사람은 나다.

## 2.8 Colab 대체 경로

일부 학생은 노트북 권한, 운영체제 문제, 계정 인증 문제로 2주차 안에 로컬 환경을 완성하지 못할 수 있다. 이 경우 Colab을 사용한다.

Colab 대체 절차는 다음과 같다.

1. 브라우저에서 Colab을 연다.
2. 새 Notebook을 만든다.
3. 첫 코드 셀에 `hello_ai.py`의 코드를 붙여넣는다.
4. 실행 버튼을 누른다.
5. 실행 결과 화면을 캡처한다.
6. AI 협업 로그는 별도 문서에 작성한다.

Colab은 대체 경로이지 낮은 수준의 경로가 아니다. 중요한 것은 어디에서 실행했는지가 아니라, **코드를 직접 실행했고 결과를 확인했는지**다.

## 2.9 제출물

이번 주 제출물은 다음과 같다.

| 제출물 | 설명 |
|---|---|
| GitHub 저장소 링크 또는 Colab 링크 | `hello_ai.py`와 `ai_log.md`가 들어 있어야 함 |
| 실행 결과 화면 또는 로그 | 코드가 실제로 실행되었음을 보여줌 |
| AI 협업 로그 | 사용한 도구, 프롬프트, AI 답변, 내가 고친 부분 |
| 오류 수정 기록 | 일부러 만든 오류와 수정 과정 |
| 안전 점검표 | 개인정보, API 키, 비밀번호를 넣지 않았는지 확인 |

`ai_log.md`는 다음 형식으로 작성한다.

```markdown
# 2주차 AI 협업 로그

## 사용한 AI 도구

## 내가 입력한 프롬프트

## AI가 도와준 부분

## 내가 직접 수정하거나 검증한 부분

## 오류 메시지와 해결 과정

## 안전 점검
- 개인정보를 입력하지 않았다:
- 비밀번호나 API 키를 입력하지 않았다:
- AI가 만든 코드를 직접 실행했다:
- 이해하지 못한 코드를 표시했다:
```

## 핵심 정리

이번 강의의 핵심은 개발환경 설치 자체가 아니다. 핵심은 다음 네 가지다.

1. 코드는 파일로 저장되어야 한다.
2. 코드는 실행되어야 한다.
3. AI 설명은 실행 결과와 비교되어야 한다.
4. AI에게 입력하면 안 되는 정보가 있다.

딥러닝 수업에서 가장 위험한 습관은 "AI가 만들어준 코드니까 맞겠지"라고 생각하는 것이다. 앞으로의 모든 실습에서는 AI를 사용할 수 있다. 그러나 실행, 검증, 설명의 책임은 학생에게 있다.
