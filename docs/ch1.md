# 1강. AI와 딥러닝은 무엇인가

## Part A — 강의 (1교시, 90분)

### 강의 목표

이번 강의의 목표는 인공지능, 머신러닝, 딥러닝, 생성형 AI 네 가지 용어의 관계를 잡고, AI가 잘하는 일과 못하는 일을 구분하는 것이다.

학생은 이번 시간 후 다음을 할 수 있어야 한다.

1. 인공지능, 머신러닝, 딥러닝, 생성형 AI의 포함 관계를 설명한다.
2. 규칙 기반 방식, 머신러닝 방식, 딥러닝 방식의 차이를 한두 문장으로 구분한다.
3. AI 역사에서 "AI 겨울"이 왜 왔는지 한 문장으로 말한다.
4. AI가 잘하는 일, 못하는 일, 위험한 일을 각각 2가지 이상 든다.
5. "딥러닝을 왜 배워야 하는가"에 대해 자기 말로 답한다.

이번 강의는 코딩 실습이 없다. 대신 AI 결과물을 판별하고 토론하는 활동을 한다. 코딩은 2주차부터 시작한다.

### 핵심 개념

이번 강의에서 다루는 핵심 용어는 다음과 같다.

| 용어 | 뜻 |
|---|---|
| 인공지능(AI) | 사람이 하는 지적 작업을 컴퓨터가 수행하도록 만드는 기술 전체 |
| 머신러닝(ML) | 규칙을 사람이 직접 쓰는 대신, 데이터에서 패턴을 찾아 배우는 방식 |
| 딥러닝(DL) | 여러 층의 인공 신경망을 사용하는 머신러닝의 한 갈래 |
| 생성형 AI | 텍스트, 이미지, 코드 등 새로운 결과물을 만들어내는 AI |
| 규칙 기반 방식 | 사람이 판단 규칙을 직접 작성하고 컴퓨터가 규칙을 실행하는 방식 |
| 데이터 기반 학습 | 모델이 예시 데이터를 보고 판단 기준을 스스로 찾는 방식 |

### 1.1 AI는 어디에 있는가

AI라는 말은 뉴스, 광고, 일상 대화에 자주 등장한다. 그런데 우리가 이미 매일 쓰고 있는 서비스 안에도 AI가 들어 있다.

- 유튜브가 다음에 볼 영상을 추천하는 것
- 카카오톡에서 음성을 텍스트로 바꾸는 것
- 네이버 파파고가 문장을 번역하는 것
- 스마트폰 카메라가 얼굴을 인식하는 것
- ChatGPT가 질문에 답하는 것

이 서비스들은 모두 AI 기술을 사용한다. 다만 사용하는 방식과 복잡도가 다르다. 어떤 것은 간단한 규칙으로 동작하고, 어떤 것은 수억 개의 매개변수를 가진 신경망으로 동작한다.

이 차이를 이해하려면 먼저 네 가지 용어의 관계를 정리해야 한다.

### 1.2 네 가지 용어: AI, 머신러닝, 딥러닝, 생성형 AI

이 네 용어는 서로 독립된 것이 아니라 포함 관계에 있다.

- **인공지능(AI)**은 가장 넓은 개념이다. 사람이 하는 지적 작업(판단, 인식, 생성 등)을 컴퓨터가 수행하게 만드는 기술 전체를 뜻한다. 규칙을 직접 작성하는 방식도 AI에 포함된다.
- **머신러닝(ML)**은 AI의 한 갈래다. 규칙을 사람이 직접 쓰지 않고, 데이터에서 패턴을 찾아 배우는 방식이다. 예를 들어 스팸 메일을 분류할 때, 사람이 "이 단어가 들어가면 스팸"이라고 쓰는 대신, 수천 개의 메일을 보여주면 모델이 스스로 기준을 찾는다.
- **딥러닝(DL)**은 머신러닝의 한 갈래다. 여러 층의 인공 신경망을 쌓아서 복잡한 패턴을 배우는 방식이다. 이미지 인식, 음성 인식, 번역처럼 입력이 복잡한 문제에서 강하다.
- **생성형 AI**는 딥러닝 기술을 사용해 새로운 결과물을 만들어내는 AI다. ChatGPT, Claude, Gemini 같은 대화형 AI, DALL-E와 Midjourney 같은 이미지 생성 AI가 여기에 해당한다.

네 용어의 포함 관계를 표로 정리하면 다음과 같다.

| 범위 | 용어 | 예 |
|---|---|---|
| 가장 넓음 | 인공지능(AI) | 규칙 기반 체스 프로그램, 자동 분류 시스템 |
| 중간 | 머신러닝(ML) | 스팸 분류기, 추천 시스템 |
| 좁음 | 딥러닝(DL) | 이미지 인식, 음성 인식, 번역 |
| 가장 좁음 (최근) | 생성형 AI | ChatGPT, DALL-E, Midjourney |

여기서 주의할 점이 있다. 생성형 AI가 가장 좁다고 해서 가장 중요하지 않다는 뜻은 아니다. 반대로 가장 넓은 AI가 가장 좋다는 뜻도 아니다. 이것은 포함 관계일 뿐, 좋고 나쁨의 순서가 아니다.

### 1.3 세 가지 방식: 규칙 기반, 머신러닝, 딥러닝

AI가 문제를 해결하는 방식은 크게 세 가지로 나눌 수 있다. 각 방식은 "사람이 하는 일"과 "컴퓨터가 하는 일"의 비중이 다르다.

**규칙 기반 방식**

사람이 판단 규칙을 직접 작성하고, 컴퓨터는 그 규칙을 적용한다.

- 예를 들어 "점수가 60점 이상이면 합격, 미만이면 불합격"이라고 쓰면, 컴퓨터는 점수를 받아 규칙을 실행한다.
- 규칙이 명확한 문제에서는 단순하고 강력하다.
- 그러나 "고양이 사진인지 강아지 사진인지 구분하라"처럼 규칙을 말로 쓰기 어려운 문제에서는 한계가 있다. 고양이 귀의 모양, 눈의 크기, 털의 색을 규칙으로 전부 쓸 수 없기 때문이다.

**머신러닝 방식**

사람이 규칙을 직접 쓰지 않고, 예시 데이터를 준비한다. 모델은 데이터를 보고 판단 기준을 찾는다.

- 예를 들어 스팸 메일 1,000개와 정상 메일 1,000개를 보여주면, 모델은 어떤 단어 조합이 스팸에 자주 나오는지 배운다.
- 사람은 데이터를 준비하고, 어떤 특성(단어 빈도, 문장 길이 등)을 모델에 넣을지 결정한다. 이것을 "특성 엔지니어링"이라고 한다.
- 머신러닝의 약점은 사람이 특성을 잘못 골르면 모델도 제대로 배우지 못한다는 점이다.

**딥러닝 방식**

머신러닝과 같이 데이터에서 배우지만, 특성까지도 모델이 스스로 찾는다.

- 예를 들어 고양이와 강아지 사진 수만 장을 보여주면, 딥러닝 모델은 귀 모양, 눈 크기, 털 패턴 같은 특성을 사람이 지정하지 않아도 스스로 찾는다.
- 이것이 가능한 이유는 여러 층의 인공 신경망이 입력 데이터를 점점 추상적으로 변환하기 때문이다. 앞쪽 층은 가장자리나 색을, 중간 층은 모양을, 뒤쪽 층은 "고양이다/강아지다" 같은 판단을 담당한다.
- 딥러닝은 대량의 데이터와 높은 계산 능력이 필요하다. 데이터가 적으면 전통적인 머신러닝이 더 나을 수 있다.

세 방식의 차이를 정리하면 다음과 같다.

| 구분 | 규칙 기반 | 머신러닝 | 딥러닝 |
|---|---|---|---|
| 사람이 하는 일 | 규칙을 직접 작성 | 데이터와 특성을 준비 | 데이터를 준비 |
| 컴퓨터가 하는 일 | 규칙을 실행 | 특성에서 패턴을 찾음 | 특성도 스스로 찾음 |
| 데이터 필요량 | 적음 | 중간 | 많음 |
| 좋은 예 | 점수 기준 합격 판정 | 스팸 분류, 추천 시스템 | 이미지 인식, 번역, 음성 인식 |
| 약점 | 복잡한 규칙을 쓰기 어려움 | 특성 선택이 까다로움 | 데이터와 계산 비용이 큼 |

### 1.4 AI 역사: 기대와 겨울

AI라는 말은 1956년에 처음 만들어졌다. 그 뒤로 AI는 기대와 실망을 반복해 왔다. 이 흐름을 알면 "지금의 AI가 왜 다른가"를 이해하는 데 도움이 된다.

**1950~1960년대: AI의 탄생**

- 1950년, 앨런 튜링이 "기계가 생각할 수 있는가"라는 질문을 던졌다.
- 1956년, 다트머스 회의에서 "인공지능"이라는 이름이 처음 쓰였다.
- 초기 AI 연구자들은 규칙 기반 방식으로 체스, 수학 증명 같은 문제를 풀었다.
- "10년 안에 인간 수준의 AI가 만들어질 것"이라는 낙관이 있었다.

**1970~1980년대: 첫 번째 AI 겨울**

- 규칙 기반 방식으로 풀 수 있는 문제가 한정적이라는 사실이 드러났다.
- 기대에 비해 성과가 부족하자 연구 자금이 줄었다. 이 시기를 "AI 겨울"이라고 부른다.
- 1980년대에 전문가 시스템(의료 진단, 화학 분석 등 특정 영역의 규칙을 컴퓨터에 넣은 시스템)이 인기를 끌었지만, 규칙이 많아질수록 유지 비용이 커졌다.

**1990~2000년대: 두 번째 AI 겨울과 머신러닝의 성장**

- 전문가 시스템의 한계가 드러나면서 두 번째 AI 겨울이 왔다.
- 그러나 이 시기에 머신러닝 연구가 꾸준히 진행됐다. 데이터에서 패턴을 찾는 방식이 규칙 기반보다 다양한 문제에 적용 가능하다는 것이 알려졌다.

**2010년대: 딥러닝의 부상**

- 2012년, 딥러닝 모델(AlexNet)이 이미지 인식 대회(ImageNet)에서 기존 방식을 크게 이겼다. 이것이 딥러닝 시대의 시작점으로 꼽힌다.
- 대량의 데이터(인터넷, 스마트폰, SNS)와 GPU 계산 능력이 딥러닝의 성장을 뒷받침했다.
- 음성 인식, 번역, 이미지 분류, 게임(알파고) 등 여러 분야에서 사람 수준에 가까운 결과가 나왔다.

**2020년대: 생성형 AI의 등장**

- 2022년 11월, ChatGPT가 공개되면서 생성형 AI가 일반 사용자에게 널리 퍼졌다.
- ChatGPT는 트랜스포머(Transformer)라는 딥러닝 구조를 기반으로 하며, 대량의 텍스트 데이터로 학습한 뒤 인간 피드백으로 조정한 모델이다.
- 텍스트 생성뿐 아니라 이미지 생성(DALL-E, Midjourney, Stable Diffusion), 코드 생성, 음악 생성 등 다양한 생성 AI가 등장했다.
- AI 기술을 쓰는 기업은 삼성, 카카오, 네이버, 구글, 마이크로소프트, 메타, 아마존, 엔비디아 등 폭넓다.

AI 겨울이 두 번 온 이유는 비슷하다. 기대가 현실보다 앞서 나갔고, 결과가 기대에 못 미치자 투자가 줄었다. 현재 AI 시장은 실제로 쓰이는 서비스(검색, 추천, 번역, 자동화)가 많아 이전과 상황이 다르다. 다만 기대가 지나치면 같은 일이 반복될 수 있다는 점은 기억할 필요가 있다.

### 1.5 AI가 잘하는 일과 못하는 일

AI는 만능이 아니다. 잘하는 일이 분명히 있지만, 못하는 일과 위험한 일도 있다.

**AI가 잘하는 일**

| 분야 | 예 |
|---|---|
| 패턴 인식 | 사진 속 얼굴 인식, 음성을 텍스트로 변환, 의료 영상에서 이상 부위 탐지 |
| 대량 데이터 분류 | 스팸 메일 분류, 뉴스 카테고리 분류, 상품 리뷰 감성 분석 |
| 번역과 요약 | 영어를 한국어로 번역, 긴 문서를 요약 |
| 텍스트와 이미지 생성 | 질문에 대한 답변 생성, 키워드 기반 이미지 생성 |
| 반복 작업 자동화 | 데이터 입력, 이미지 크기 변환, 코드 포맷팅 |

**AI가 못하는 일**

| 분야 | 이유 |
|---|---|
| 처음 보는 상황에서의 상식 판단 | AI는 학습 데이터에 없는 상황을 추론하기 어렵다 |
| 맥락에 따른 윤리적 판단 | "이것이 옳은가"에 대한 판단은 사회적 맥락에 따라 달라지는데, AI는 데이터의 패턴만 따른다 |
| 자기가 틀렸는지 아는 것 | AI는 확신도와 정답을 스스로 구분하지 못한다. 틀린 답도 자신 있게 말한다 |
| 물리적 세계와의 상호작용 | 실제 물건을 옮기거나, 예상 못 한 환경에서 대응하기는 어렵다 |

**AI가 위험한 일**

| 위험 | 예 |
|---|---|
| 환각(hallucination) | AI가 존재하지 않는 논문, 인물, 수치를 그럴듯하게 만들어 내는 것 |
| 편향 | 학습 데이터에 편향이 있으면 AI도 편향된 결과를 낸다(예: 특정 인종의 얼굴을 더 많이 오인식) |
| 개인정보 유출 | AI에게 개인정보를 입력하면 어디에 저장되고 어떻게 사용될지 알기 어렵다 |
| 출처 없는 단정 | AI가 말한 내용이 사실인 것처럼 보이지만 출처가 없거나 확인이 안 되는 경우 |
| 과도한 의존 | AI에게 맡기고 직접 확인하지 않는 습관이 생기면 오류를 발견하지 못한다 |

이 과목에서는 AI를 쓰는 법만 배우지 않는다. AI가 틀릴 수 있다는 점, 틀린 결과를 발견하는 법, 위험을 줄이는 법을 함께 배운다.

### 핵심 정리

- 인공지능은 가장 넓은 개념이고, 머신러닝은 AI의 한 갈래, 딥러닝은 머신러닝의 한 갈래다.
- 규칙 기반 방식은 사람이 규칙을 쓰고, 머신러닝은 데이터에서 패턴을 찾고, 딥러닝은 특성까지 스스로 찾는다.
- AI 역사에서 겨울이 온 이유는 기대가 현실보다 앞서 나갔기 때문이다.
- 생성형 AI는 딥러닝 기술을 사용해 텍스트, 이미지, 코드 등 새로운 결과물을 만든다.
- AI는 패턴 인식과 반복 작업에 강하지만, 상식 판단, 윤리적 판단, 자기 오류 인식에는 약하다.
- AI가 만든 결과를 그대로 믿지 않고 직접 확인하는 것이 이 과목의 출발점이다.

## Part B — 실습 (2교시, 90분)

### 실습 목표

이번 실습의 목표는 AI가 만든 결과물을 직접 판별하고, AI가 잘하는 일과 못하는 일을 분류하는 것이다. 코딩 실습은 없다. 대신 관찰, 판단, 토론, 기록을 한다.

학생은 이번 실습 후 다음을 할 수 있어야 한다.

1. 결과물을 보고 사람이 만든 것인지 AI가 만든 것인지 근거를 들어 판단한다.
2. AI가 잘하는 일, 못하는 일, 위험한 일을 분류표로 정리한다.
3. AI에게 설명을 요청하고, 설명에서 과장이나 부정확한 부분을 찾는다.

### 실습 절차

#### 활동 1: AI 판별 실험 (30분)

교수자가 5~8개의 결과물을 보여준다. 결과물은 글(수필, 뉴스 기사, 시), 그림, 코드, 번역문 등이다. 일부는 사람이 만든 것이고 일부는 AI가 만든 것이다.

학생은 각 결과물에 대해 다음을 기록한다.

| 번호 | 결과물 종류 | 내 판단 (사람/AI) | 판단 근거 | 정답 | 맞았는가 |
|---:|---|---|---|---|---|
| 1 | | | | | |
| 2 | | | | | |
| 3 | | | | | |
| ... | | | | | |

기록 후 교수자가 정답을 공개한다. 학생은 자기 판단이 맞았는지 틀렸는지 확인한다. 틀린 경우, 왜 속았는지 한 문장으로 적는다.

#### 활동 2: AI가 잘하는/못하는/위험한 일 분류 (30분)

모둠(3~4명)별로 다음 세 칸에 해당하는 것을 가능한 한 많이 적는다.

| AI가 잘하는 일 | AI가 못하는 일 | AI가 위험한 일 |
|---|---|---|
| | | |
| | | |
| | | |

분류가 끝나면 모둠별로 한 가지씩 발표한다. 다른 모둠에서 자기 모둠에 없는 내용이 나오면 추가한다.

분류 결과를 `week01-ai-map.md`에 정리한다. 파일 형식은 다음과 같다.

```markdown
# AI 분류표 — 1주차

## AI가 잘하는 일
- (예: 이미지 속 물체를 인식한다)
- ...

## AI가 못하는 일
- (예: 처음 보는 상황에서 상식으로 판단한다)
- ...

## AI가 위험한 일
- (예: 존재하지 않는 논문을 만들어 낸다)
- ...
```

#### 활동 3: AI 설명 검증 (20분)

대화형 AI(ChatGPT, Claude, Gemini 등)에게 다음 프롬프트를 입력한다.

```text
딥러닝을 고등학생에게 설명해줘.
전문 용어는 쉬운 말로 풀어줘.
```

AI 답변을 받은 뒤 다음 표를 채운다.

| 확인 항목 | 내 판단 |
|---|---|
| AI가 딥러닝의 정의를 맞게 설명했는가 |  |
| AI가 딥러닝과 머신러닝의 관계를 맞게 말했는가 |  |
| AI 설명 중 과장된 표현이 있었는가 (예: "모든 문제를 해결한다") |  |
| AI 설명 중 출처 없이 단정한 문장이 있었는가 |  |
| AI가 딥러닝의 한계를 함께 설명했는가 |  |

AI 접속이 어려운 경우, 교수자가 미리 준비한 AI 답변 캡처 자료로 대체한다.

### AI 활용 가이드

이번 실습에서 AI는 분석 대상이다. AI가 만든 결과물을 평가하고, AI의 설명을 검증한다.

- AI에게 코드를 쓰라고 요청하는 것이 아니라, 설명을 요청하고 그 설명을 평가한다.
- AI 답변을 그대로 제출하지 않는다. 자기 판단과 근거를 함께 적어야 한다.
- AI 접속이 어려우면 교수자 제공 자료로 대체한다.

### 결과 해석

AI 판별 실험에서 학생이 주목해야 할 점은 다음과 같다.

- AI가 만든 결과물이 사람이 만든 것처럼 보이는 경우가 많다. 이것은 AI의 강점이자 위험이다.
- 사람이 만든 결과물이 AI가 만든 것처럼 보이는 경우도 있다. 판별이 어렵다는 것 자체가 중요한 발견이다.
- 판별 정확도가 낮다고 부끄러워할 필요는 없다. 이 실험의 목적은 "구별이 쉽지 않다"는 것을 경험하는 것이다.

AI 분류 활동에서 주목할 점은 다음과 같다.

- "잘하는 일"에만 치우치기 쉽다. "못하는 일"과 "위험한 일"도 같은 비중으로 적어야 한다.
- 같은 기술이 "잘하는 일"이면서 동시에 "위험한 일"이 될 수 있다. 예를 들어 이미지 생성은 창작에 유용하지만 가짜 사진을 만드는 데도 쓰인다.

### 책임 있는 AI 체크

| 점검 항목 | 확인 질문 |
|---|---|
| 과장 표시 | AI 설명에서 "모든", "항상", "완벽히" 같은 과장 표현을 표시했는가 |
| 출처 확인 | AI가 말한 사실 중 출처가 없는 단정을 표시했는가 |
| 균형 점검 | AI가 잘하는 일만 적지 않고, 못하는 일과 위험한 일도 함께 기록했는가 |
| 판별 기록 | AI 판별 실험 결과를 정직하게(틀린 것 포함) 기록했는가 |
