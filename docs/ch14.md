# 14강. 기말 프로젝트 제작 워크숍

## Part A — 강의 (1교시, 90분)

### 강의 목표

이번 강의의 목표는 **기말 프로젝트를 착수하고, 수업 시간 안에 최소한 실행 가능한 중간 결과를 만드는 것**이다. 8주차 중간 미니 프로젝트와 비슷한 구조이지만, 1~13주차 전체를 포괄하며 프로젝트 규모와 평가 기준이 다르다.

학생은 이번 시간 후 다음을 할 수 있어야 한다.

1. 기말 프로젝트 주제를 확정하고 계획서를 작성한다.
2. 수업 시간 안에 최소한 실행 가능한 중간 결과를 만든다.
3. 프로젝트의 위험 요소를 점검한다.
4. 15주차 발표에 필요한 구성 요소를 정리한다.

이번 강의에서 새로운 이론은 없다. 대신 프로젝트 기준, 유형, 발표 구성을 확인하고 바로 착수한다.

### 핵심 개념

이번 주에 새로 배우는 개념은 없다. 대신 1~13주차의 핵심 개념을 기말 프로젝트 맥락에서 다시 확인한다.

| 주차 | 핵심 개념 | 프로젝트에서 확인할 것 |
|---:|---|---|
| 3~4 | 데이터, 분류, 기준선, 혼동행렬 | 내 프로젝트의 데이터와 평가 방법은 적절한가 |
| 5~7 | 신경망, 손실함수, 과적합 | 모델이 학습되고 있는가, 과적합은 없는가 |
| 9~10 | CNN, 임베딩, 텍스트 분류 | 내 프로젝트에 맞는 모델을 선택했는가 |
| 11 | 생성형 AI, 환각, 편향 | AI가 만든 결과의 출처와 신뢰성을 확인했는가 |
| 12 | 코딩 에이전트, 보안 점검 | AI가 만든 코드를 검증했는가, 보안 위험은 없는가 |
| 13 | 데모 앱, 한계 안내 | 모델의 한계를 사용자에게 안내하고 있는가 |

### 14.1 기말 프로젝트 기준

기말 프로젝트의 필수 요건은 다음과 같다.

1. **실행 가능한 코드 또는 데모**가 있다.
2. **데이터 또는 입력 예시**가 있다.
3. **AI 도구 사용 기록**이 있다.
4. 결과가 **실제로 실행되었음**을 보여준다.
5. **실패 사례와 한계**를 설명한다.
6. 딥러닝 또는 AI 개념 **2개 이상**을 연결해 설명한다.
7. 개인정보, 출처, 편향, 보안, AI 의존성 중 **최소 2개 위험**을 점검한다.

평가 기준은 8주차와 비슷하지만 더 넓은 범위를 요구한다.

| 잘한 프로젝트 | 부족한 프로젝트 |
|---|---|
| 모델이 틀린 이유를 설명한다 | 정확도 숫자만 있고 해석이 없다 |
| AI가 도와준 부분과 내가 고친 부분을 구분한다 | AI가 만든 코드를 그대로 제출한다 |
| 과적합 여부를 확인한다 | 훈련 정확도만 보고 모델이 좋다고 한다 |
| 실패 사례를 기록한다 | 틀린 사례를 숨기거나 없다고 한다 |
| 코드가 실행된다 | 코드가 실행되지 않는다 |
| 모델의 한계를 설명한다 | 모델의 한계를 언급하지 않는다 |
| 위험 점검을 수행한다 | 위험 점검이 없다 |
| 딥러닝 개념 2개 이상을 연결한다 | 개념 연결 없이 결과만 보여준다 |

### 14.2 프로젝트 유형

다음 유형 중 하나를 선택하거나, 비슷한 규모의 주제를 정한다.

| 유형 | 예 | 관련 주차 |
|---|---|---|
| 이미지 분류기 | 내 사진 분류, 음식·동물·패션 분류 | 4, 5, 9주차 |
| 텍스트 분류기 | 리뷰 감성 분석, 댓글 분류 | 3, 4, 10주차 |
| 데이터 예측기 | 표 데이터로 예측, 추천 시스템 | 3, 4, 7주차 |
| AI 도구 검증 프로젝트 | AI 답변의 환각·출처 검증 도구 | 11, 12주차 |
| AI 데모 앱 | 숫자 인식 앱, 감성 분석 앱 | 13주차 |
| AI 코딩 도구 활용 프로젝트 | AI와 함께 만든 도구, 보안 점검 도구 | 12주차 |

피해야 할 프로젝트는 다음과 같다.

- 프롬프트 결과만 붙여넣은 보고서
- 실행 코드가 없는 아이디어 발표
- 출처 없는 AI 설명 모음
- 모델 성능만 있고 해석이 없는 결과
- 본인이 이해하지 못한 대형 코드
- 개인정보, API 키, 비공개 자료를 AI 도구에 넣은 결과물
- GPU 없이 실행할 수 없는 대형 모델

### 14.3 발표 구성

15주차 기말 발표에 포함할 요소는 다음과 같다.

| 순서 | 항목 | 설명 | 시간 |
|---:|---|---|---|
| 1 | 문제와 목표 | 무엇을 예측 또는 분류하는가 | 30초 |
| 2 | 데이터 | 몇 개, 어떤 특성, 합성인지 실제인지 | 30초 |
| 3 | 모델 | 어떤 모델을 선택했고 왜 선택했는가 | 30초 |
| 4 | 결과 | 기준선, 정확도, 혼동행렬 | 1분 |
| 5 | 실패 사례 | 모델이 틀린 예시와 원인 분석 | 30초 |
| 6 | AI 활용 | 어떤 도구로 무엇을 했고, 내가 무엇을 고쳤는가 | 30초 |
| 7 | 위험 점검 | 개인정보, 보안, 편향, 성능 과장 중 점검한 항목 | 30초 |
| 8 | 한계와 개선 방향 | 모델의 한계, 다음에 시도할 것 | 30초 |

전체 발표 시간은 5분이다. 질문 시간은 별도로 둔다.

### 핵심 정리

- 기말 프로젝트는 정확도 경쟁이 아니라 "왜 이런 결과가 나왔는가"를 설명하는 활동이다.
- 수업 시간 안에 최소 결과를 낼 수 있는 주제를 선택한다.
- 실패 사례는 감점 대상이 아니라 학습 자료다. 숨기지 않고 분석한다.
- 모델의 한계를 설명하고, 위험 점검을 수행하는 것이 좋은 프로젝트의 조건이다.
- 발표에는 문제, 데이터, 모델, 결과, 실패, AI 활용, 위험, 한계를 포함한다.

## Part B — 실습 (2교시, 90분)

### 실습 목표

이번 실습의 목표는 기말 프로젝트를 실제로 착수하고, 수업 시간 안에 최소 결과를 만드는 것이다.

학생은 이번 실습 후 다음을 할 수 있어야 한다.

1. 프로젝트 주제를 확정하고 계획서를 작성한다.
2. 데이터를 준비하거나 생성한다.
3. 최소한 하나의 모델을 학습시키고 결과를 확인한다.
4. 위험 점검표를 작성한다.
5. 발표에 포함할 내용을 정리한다.

### 실습 절차

#### 14.4 프로젝트 착수

##### 단계 1: 주제 확정과 계획서 작성 (10분)

1교시에 소개한 프로젝트 유형 중 하나를 선택한다. 다음 계획서 양식을 채운다.

```text
프로젝트 제목:
문제:          (무엇을 예측 또는 분류하는가)
데이터:        (어디서 가져오거나 어떻게 만드는가)
모델:          (어떤 모델을 쓸 계획인가)
평가 방법:     (정확도, 혼동행렬, 손실 곡선 등)
예상 어려움:   (데이터 부족, 코드 오류, 과적합 등)
AI 도구 계획:  (어떤 도구를 어떤 작업에 쓸 계획인가)
딥러닝 개념:   (프로젝트에서 연결할 개념 2개 이상)
위험 점검:     (개인정보, 보안, 편향, 성능 과장 중 점검할 항목)
```

교수자 또는 조교에게 주제를 확인받는다.

##### 단계 2: 데이터 준비 (15분)

- 기존 실습 데이터를 확장하거나, 공개 데이터셋을 사용하거나, 합성 데이터를 만든다.
- 합성 데이터를 사용하면 반드시 합성 데이터임을 표시한다.
- 데이터에 개인정보가 포함되지 않았는지 확인한다.

##### 단계 3: 모델 학습과 평가 (25분)

- 기준선 모델과 비교한다.
- 정확도와 혼동행렬을 함께 확인한다.
- 훈련 정확도와 테스트 정확도를 비교해 과적합 여부를 확인한다.
- 가능하면 데모 형태로 결과를 보여줄 수 있게 만든다.

#### 14.5 디버깅과 중간 점검

##### 단계 4: 중간 점검 (15분)

다음 체크리스트로 프로젝트 진행 상황을 확인한다.

| 항목 | 확인 |
|---|---|
| 코드가 실행되는가 |  |
| 기준선 모델을 만들었는가 |  |
| 테스트 정확도를 확인했는가 |  |
| 혼동행렬을 확인했는가 |  |
| 모델이 틀린 사례를 하나 이상 찾았는가 |  |
| AI 도구 사용 기록을 남기고 있는가 |  |

오류가 나면 다음 순서로 처리한다.

1. 오류 메시지를 읽는다.
2. 오류가 난 줄 번호를 확인한다.
3. AI에게 오류 메시지를 보여주고 원인을 물어본다.
4. AI가 제안한 수정을 직접 실행한다.
5. 수정 전후의 차이를 기록한다.

#### 14.6 위험 점검

##### 단계 5: 위험 점검 (10분)

다음 표에서 최소 2개 항목을 점검한다.

| 위험 항목 | 점검 질문 | 내 확인 |
|---|---|---|
| 개인정보 | 데이터에 실제 개인정보가 포함되지 않았는가 |  |
| 보안 | 코드에 파일 삭제, 외부 전송, 비밀키 노출 위험이 없는가 |  |
| 편향 | 데이터가 특정 그룹에 편향되지 않았는가 |  |
| 성능 과장 | 정확도만 보고 모델이 좋다고 단정하지 않았는가 |  |
| AI 의존성 | AI가 만든 코드를 이해하고 있는가 |  |
| 출처 | 데이터, 코드, 설명의 출처를 확인했는가 |  |
| 한계 안내 | 모델의 한계를 설명할 수 있는가 |  |

##### 단계 6: 발표 준비 (15분)

14.3에서 안내한 발표 구성 요소에 맞춰 초안을 정리한다.

```text
1. 문제와 목표:
2. 데이터:
3. 모델:
4. 결과:
5. 실패 사례:
6. AI 활용:
7. 위험 점검:
8. 한계와 개선:
```

### AI 활용 가이드

이번 실습에서 AI 도구는 다음 역할을 할 수 있다.

| AI에게 맡길 수 있는 일 | AI에게 맡기면 안 되는 일 |
|---|---|
| 코드 작성 보조 | 프로젝트 주제 결정 |
| 오류 메시지 설명 | 결과 해석과 실패 분석 |
| 데이터 시각화 코드 생성 | 발표 내용 전체 작성 |
| 모델 선택 제안 | 이해하지 못한 코드 제출 |
| 보안 점검 보조 | 위험이 없다는 최종 판단 |

### 결과 해석

이번 프로젝트에서 주목해야 할 점은 다음과 같다.

- 기준선보다 모델이 나아졌는가. 나아지지 않았다면 데이터나 모델을 점검한다.
- 훈련 정확도와 테스트 정확도의 차이가 크면 과적합을 의심한다.
- 정확도가 높아도 혼동행렬에서 한쪽 오류가 집중되면 모델의 약점이 있다.
- 모델이 틀린 사례를 분석하면 데이터의 한계와 모델의 한계를 구분할 수 있다.
- 모델의 한계를 설명하지 못하면 좋은 프로젝트가 아니다.

### 책임 있는 AI 체크

| 점검 항목 | 확인 질문 |
|---|---|
| 성능 과장 | 정확도만 보고 모델이 좋다고 단정하지 않았는가 |
| 실패 기록 | 모델이 틀린 사례를 최소 3개 기록했는가 |
| 과적합 확인 | 훈련 정확도와 테스트 정확도를 함께 확인했는가 |
| AI 기록 | AI 도구 사용 과정을 프롬프트와 함께 기록했는가 |
| 개인정보 | 데이터에 실제 개인정보가 포함되지 않았는가 |
| 보안 | 코드에 파일 삭제, 외부 전송, 비밀키 노출 위험이 없는가 |
| 한계 안내 | 모델의 한계를 설명했는가 |
| 코드 이해 | AI가 만든 코드를 이해하고 직접 실행했는가 |

### 제출물

| 제출물 | 설명 |
|---|---|
| 프로젝트 계획서 | 주제, 데이터, 모델, 평가 방법, 딥러닝 개념, 위험 점검 |
| 실행 가능한 중간 결과 | 코드 + 실행 로그 |
| 발표 초안 | 8가지 항목에 대한 정리 |
| 위험 점검표 | 최소 2개 항목 점검 |
| 책임 있는 AI 체크리스트 | 위 표의 각 항목 확인 |

## 핵심 정리

- 기말 프로젝트는 정확도 경쟁이 아니라 "왜 이런 결과가 나왔는가"를 설명하는 활동이다.
- 수업 시간 안에 최소 결과를 낼 수 있는 주제를 선택한다.
- 실패 사례는 감점 대상이 아니라 학습 자료다. 숨기지 않고 분석한다.
- 딥러닝 개념 2개 이상을 프로젝트와 연결해 설명한다.
- 모델의 한계를 설명하고, 위험을 최소 2개 이상 점검한다.
- AI 도구를 사용할 수 있지만, 사용 기록과 검증 과정을 함께 제출한다.
