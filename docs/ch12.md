# 12강. AI 코딩 에이전트와 책임 있는 자동화

## Part A — 강의 (1교시, 90분)

### 강의 목표

이번 강의의 목표는 **AI 코딩 에이전트가 코드를 생성하는 과정을 이해하고, AI가 만든 코드를 읽고 검증하고 고치는 능력**을 기르는 것이다. AI 코딩 에이전트는 2주차에서 사용한 자동완성 도구보다 더 넓은 범위의 작업을 수행한다. 코드를 한 줄씩 제안하는 것이 아니라, 여러 파일을 만들고, 실행하고, 결과를 확인하는 작업을 연속으로 수행할 수 있다.

학생은 이번 시간 후 다음을 할 수 있어야 한다.

1. AI 코딩 에이전트가 코드를 생성하는 과정을 설명한다.
2. 하나의 작업을 AI에게 맡길 수 있는 작은 단위로 나눈다.
3. AI에게 명확한 프롬프트를 작성한다.
4. AI가 생성한 코드를 읽고, 의도와 다른 부분을 찾아 수정한다.
5. 코드에 파일 삭제, 외부 전송, 비밀키 노출 같은 보안 위험이 있는지 점검한다.

이번 실습은 이미지 크기 변환 도구를 만들고, 그 코드에 보안 위험이 없는지 점검하는 것이다.

### 핵심 개념

| 용어 | 뜻 |
|---|---|
| 코딩 에이전트 | 사용자의 지시를 받아 코드를 작성하고, 실행하고, 결과를 확인하는 AI 도구 |
| 자동완성 | 코드를 한 줄씩 제안하는 AI 기능. 에이전트보다 범위가 좁다 |
| 작업 분해 | 큰 목표를 AI가 처리할 수 있는 작은 단계로 나누는 과정 |
| 프롬프트 명세 | AI에게 입력, 출력, 제약 조건을 명확히 알려주는 지시문 |
| 코드 리뷰 | 코드를 읽고 오류, 보안 위험, 의도와 다른 동작을 찾는 활동 |
| 보안 점검 | 코드에 파일 삭제, 외부 전송, 비밀키 노출 같은 위험이 있는지 확인하는 활동 |

### 12.1 AI 코딩 에이전트란 무엇인가

2주차에서 GitHub Copilot 같은 도구를 사용해 본 적이 있다. 그때의 도구는 커서가 있는 줄 다음에 올 코드를 제안하는 방식이었다. 학생이 한 줄씩 수락하거나 거절했다.

AI 코딩 에이전트는 이보다 범위가 넓다. 에이전트는 다음과 같은 일을 연속으로 수행한다.

- 사용자의 지시를 읽고 작업 계획을 세운다.
- 필요한 파일을 만들거나 수정한다.
- 코드를 실행하고 결과를 확인한다.
- 오류가 나면 원인을 추정하고 수정을 시도한다.

자동완성과 에이전트의 차이는 다음 표와 같다.

| 구분 | 자동완성 (예: Copilot 인라인 제안) | 에이전트 (예: Copilot Agent, Claude Code, Antigravity) |
|---|---|---|
| 작업 범위 | 한 줄 또는 한 함수 | 여러 파일, 여러 단계 |
| 실행 여부 | 코드를 제안만 한다 | 코드를 실행하고 결과를 확인할 수 있다 |
| 사용자 역할 | 제안을 수락하거나 거절한다 | 지시를 내리고 결과를 검증한다 |
| 위험 | 한 줄이 잘못될 수 있다 | 여러 파일을 한꺼번에 잘못 수정할 수 있다 |
| 검증 부담 | 한 줄씩 확인한다 | 전체 결과를 함께 확인해야 한다 |

에이전트가 더 강력하다고 해서 더 안전한 것은 아니다. 작업 범위가 넓어진 만큼 학생이 확인해야 할 범위도 넓어진다.

### 12.2 작업 분해

AI 에이전트에게 "이미지 크기 변환 프로그램을 만들어줘"라고 한 번에 지시하면, 에이전트는 코드를 만들 수 있다. 그러나 결과물이 기대와 다를 가능성이 높다. 지시가 모호하면 에이전트는 자기 나름대로 해석해 결과를 만든다.

따라서 큰 작업을 작은 단계로 나눈 뒤 하나씩 지시하는 것이 낫다.

이번 실습의 작업을 예로 들면 다음과 같이 나눌 수 있다.

| 단계 | 작업 | AI에게 지시할 내용 |
|---:|---|---|
| 1 | 샘플 이미지 만들기 | "200x150 픽셀의 랜덤 이미지를 PNG로 저장하는 함수를 만들어줘" |
| 2 | 크기 변환 함수 | "PIL을 사용해 이미지 크기를 변환하는 함수를 만들어줘. 입력은 파일 경로, 출력 경로, 새 너비, 새 높이다" |
| 3 | 여러 크기로 변환 | "100x75, 50x50, 300x200 세 가지 크기로 변환하고 결과를 출력해줘" |
| 4 | 보안 점검 | "이 코드에 파일 삭제, 외부 전송, 비밀키 하드코딩이 있는지 검사하는 함수를 만들어줘" |

작업을 나누면 두 가지 장점이 있다.

- 각 단계의 결과를 바로 확인할 수 있다. 3단계에서 문제가 생기면 3단계만 다시 지시하면 된다.
- AI가 오해할 범위가 줄어든다. 한 단계에 하나의 목표만 있으면 결과가 기대에 가까워진다.

### 12.3 프롬프트 명세

AI에게 코드를 요청할 때는 다음 세 가지를 분명히 적는 것이 좋다.

- **입력**: 함수가 받는 데이터의 종류와 형태
- **출력**: 함수가 돌려주는 결과의 종류와 형태
- **제약 조건**: 사용할 라이브러리, 금지할 동작, 파일 저장 위치

예를 들어 다음 프롬프트를 비교해 본다.

- 모호한 프롬프트:
  - "이미지 크기를 바꾸는 코드 만들어줘"
  - 문제: 어떤 이미지인지, 어떤 크기로 바꿀지, 결과를 어디에 저장할지 알 수 없다.

- 명확한 프롬프트:
  - "PIL을 사용해 PNG 이미지의 크기를 변환하는 Python 함수를 만들어줘. 입력은 원본 파일 경로(Path), 출력 파일 경로(Path), 새 너비(int), 새 높이(int)다. 반환값은 원본 크기와 새 크기를 담은 딕셔너리다. 파일 삭제나 외부 전송 코드를 넣지 마라."
  - 장점: 입력, 출력, 제약 조건이 모두 들어 있다.

명확한 프롬프트를 쓰면 AI가 만든 코드를 검증하기도 쉽다. 프롬프트에 적은 조건과 실제 코드를 대조할 수 있기 때문이다.

### 12.4 코드 리뷰

AI가 코드를 만들면 학생은 그 코드를 실행하기 전에 읽어야 한다. 코드 리뷰는 다음 질문을 순서대로 확인하는 것이다.

| 순서 | 질문 | 확인 방법 |
|---:|---|---|
| 1 | 함수가 내가 요청한 입력을 받는가 | 함수 매개변수와 프롬프트를 비교한다 |
| 2 | 함수가 내가 요청한 출력을 돌려주는가 | 반환값의 형태를 확인한다 |
| 3 | 내가 금지한 동작이 들어 있는가 | 파일 삭제, 외부 전송, 비밀키 관련 코드를 찾는다 |
| 4 | 내가 이해하지 못하는 코드가 있는가 | 이해하지 못하는 줄에 표시한다 |
| 5 | 에러가 날 수 있는 부분이 있는가 | 파일이 없을 때, 입력이 잘못됐을 때를 생각한다 |

코드 리뷰는 코드를 완벽하게 이해하는 것이 아니다. 위 다섯 가지 질문에 답하는 것이다.

### 12.5 보안 점검

AI가 만든 코드를 실행하기 전에 반드시 확인해야 할 보안 위험은 세 가지다.

| 위험 | 확인 방법 | 예 |
|---|---|---|
| 파일 삭제 | `os.remove`, `shutil.rmtree`, `Path.unlink` 같은 코드가 있는지 찾는다 | AI가 "임시 파일 정리" 코드를 넣었는데 실제로는 중요한 파일을 지울 수 있다 |
| 외부 전송 | `requests.post`, `urllib`, `socket` 같은 코드가 있는지 찾는다 | AI가 "결과를 서버에 저장" 코드를 넣었는데 개인정보가 외부로 전송될 수 있다 |
| 비밀키 하드코딩 | `API_KEY = "..."`, `PASSWORD = "..."` 같은 코드가 있는지 찾는다 | AI가 예제 API 키를 넣었는데 학생이 실제 키로 바꾼 뒤 GitHub에 올릴 수 있다 |

이번 실습 코드에는 이 세 가지 위험을 자동으로 검사하는 함수가 포함되어 있다. 실행 로그에서 보안 점검 결과를 확인할 수 있다.

실행 결과, 가상의 위험 코드에서 다음 5건의 보안 위험이 발견되었다.

```text
발견된 보안 위험: 5건

  [1] 파일 삭제
      파일: example_risky_code.py, 줄: 13
      코드: os.remove(os.path.join(folder, f))

  [2] 파일 삭제
      파일: example_risky_code.py, 줄: 19
      코드: shutil.rmtree("/tmp/my_temp_folder")

  [3] 외부 전송
      파일: example_risky_code.py, 줄: 16
      코드: requests.post("https://example.com/collect", json=data)

  [4] 비밀키 하드코딩
      파일: example_risky_code.py, 줄: 8
      코드: API_KEY = "sk-fake-1234567890abcdef"

  [5] 비밀키 하드코딩
      파일: example_risky_code.py, 줄: 9
      코드: PASSWORD = "my_super_secret_password_123"
```

이 결과는 `practice/chapter12/results/12-1-ai-coded-tool.log`에서 확인한 실제 실행 결과다.

### 핵심 정리

- AI 코딩 에이전트는 자동완성보다 넓은 범위의 작업을 수행한다. 검증 부담도 그만큼 커진다.
- 큰 작업을 작은 단계로 나누면 AI가 오해할 범위가 줄어든다.
- AI에게 코드를 요청할 때는 입력, 출력, 제약 조건을 명확히 적는다.
- AI가 만든 코드를 실행하기 전에 코드 리뷰와 보안 점검을 수행한다.
- 파일 삭제, 외부 전송, 비밀키 하드코딩은 반드시 확인해야 할 세 가지 보안 위험이다.

## Part B — 실습 (2교시, 90분)

### 실습 목표

이번 실습의 목표는 AI와 함께 이미지 크기 변환 도구를 만들고, 그 코드에 보안 위험이 없는지 점검하는 것이다.

학생은 이번 실습 후 다음을 할 수 있어야 한다.

1. 이미지 크기 변환 코드를 실행하고 결과 파일을 확인한다.
2. 보안 점검 도구를 실행하고 위험 항목을 해석한다.
3. AI에게 코드를 요청하고, AI가 만든 코드와 내가 수정한 부분을 구분한다.
4. 코드 리뷰 체크리스트를 작성한다.

### 실습 절차

#### 12.6 AI와 함께 Python 도구 만들기

이번 실습의 전체 코드는 다음 위치에 있다.

```text
practice/chapter12/code/12-1-ai-coded-tool.py
```

실습 코드는 세 부분으로 구성된다.

1. **이미지 크기 변환 도구**: 샘플 이미지를 만들고 여러 크기로 변환한다.
2. **보안 점검 도구**: 가상의 위험 코드에서 파일 삭제, 외부 전송, 비밀키 하드코딩을 검사한다.
3. **자기 점검**: 실습 코드 자체를 보안 점검 도구로 검사한다.

실행 명령은 다음과 같다.

```bash
python3 scripts/run_and_capture.py 12
```

실행 후 다음 파일이 생성되었다.

| 파일 | 역할 |
|---|---|
| `practice/chapter12/results/12-1-ai-coded-tool.log` | 실행 로그 |
| `practice/chapter12/results/12-1-ai-coded-tool.evidence.json` | 실행 증거 JSON |
| `practice/chapter12/results/sample_image.png` | 합성 샘플 이미지 |
| `practice/chapter12/results/resized_100x75.png` | 100x75로 변환한 이미지 |
| `practice/chapter12/results/resized_50x50.png` | 50x50으로 변환한 이미지 |
| `practice/chapter12/results/resized_300x200.png` | 300x200으로 변환한 이미지 |
| `practice/chapter12/results/security_check_report.csv` | 보안 점검 결과 CSV |

##### 이미지 크기 변환 결과

실행 로그 기준으로 이미지 크기 변환 결과는 다음과 같다.

```text
샘플 이미지 생성: sample_image.png (200x150, 합성 데이터)
  크기 변환: 200x150 -> 100x75 -> resized_100x75.png
  크기 변환: 200x150 -> 50x50 -> resized_50x50.png
  크기 변환: 200x150 -> 300x200 -> resized_300x200.png
```

이 결과에서 확인할 수 있는 것은 다음과 같다.

- 원본 이미지는 200x150 픽셀이며 합성 데이터다.
- 세 가지 크기로 변환했다. 축소(100x75, 50x50)와 확대(300x200) 모두 수행했다.
- 변환된 이미지 파일이 실제로 생성되었다.

##### 보안 점검 결과

보안 점검 도구는 가상의 위험 코드에서 5건의 보안 위험을 발견했다.

| 순번 | 분류 | 줄 | 발견된 코드 |
|---:|---|---:|---|
| 1 | 파일 삭제 | 13 | `os.remove(os.path.join(folder, f))` |
| 2 | 파일 삭제 | 19 | `shutil.rmtree("/tmp/my_temp_folder")` |
| 3 | 외부 전송 | 16 | `requests.post("https://example.com/collect", json=data)` |
| 4 | 비밀키 하드코딩 | 8 | `API_KEY = "sk-fake-1234567890abcdef"` |
| 5 | 비밀키 하드코딩 | 9 | `PASSWORD = "my_super_secret_password_123"` |

이 표는 `practice/chapter12/results/security_check_report.csv`에서 가져온 실제 결과다.

또한 실습 코드 자체를 점검한 결과, 8건의 보안 위험이 발견되었다. 이 8건은 실습 코드 안에 포함된 가상의 위험 코드 문자열과 보안 점검 안내 출력문에서 패턴이 일치한 것이다. 실습 코드가 실제로 파일을 삭제하거나 외부로 데이터를 전송하지는 않는다.

이 결과는 보안 점검 도구의 한계를 보여준다. 문자열 패턴 검사는 코드가 실제로 실행되는지 여부를 구분하지 못한다. 문자열 안에 패턴이 들어 있어도 위험으로 보고한다. 따라서 자동 점검 결과를 사람이 직접 확인해야 한다.

#### 12.7 AI 활용 가이드

이번 실습에서 AI 도구는 다음 역할을 할 수 있다.

| AI에게 맡길 수 있는 일 | AI에게 맡기면 안 되는 일 |
|---|---|
| 이미지 변환 함수 코드 작성 | 보안 점검 결과 해석 |
| 보안 점검 패턴 추가 제안 | 보안 위험이 없다는 판단 |
| 오류 메시지 설명 | 코드를 읽지 않고 실행하는 것 |
| 코드 리뷰 도움 | 코드 리뷰를 AI에게 전부 맡기는 것 |

다음 프롬프트를 사용해 AI에게 코드 리뷰를 요청할 수 있다.

```text
다음 Python 코드를 검토해줘.
```

### 결과 해석

이번 실습의 결과를 해석할 때 중요한 점은 다음과 같다.

- 보안 점검 도구는 문자열 패턴을 검사한다. 코드가 실제로 위험한지는 사람이 판단해야 한다.
- 자동 점검은 위험을 줄이는 도구이지 위험을 없애는 도구가 아니다.
- AI가 만든 코드를 실행하기 전에 코드 리뷰와 보안 점검을 수행하면 위험을 줄일 수 있다.
- AI에게 보안 점검을 요청할 수 있지만, AI가 "안전하다"고 한 것을 그대로 믿으면 안 된다.

### 책임 있는 AI 체크

| 점검 항목 | 확인 질문 |
|---|---|
| 코드 이해 | AI가 만든 코드의 각 함수가 무엇을 하는지 설명할 수 있는가 |
| 보안 점검 | 파일 삭제, 외부 전송, 비밀키 노출 코드가 없는지 확인했는가 |
| 개인정보 | 코드가 개인정보를 수집하거나 전송하지 않는가 |
| AI 기록 | AI에게 요청한 프롬프트와 내가 수정한 부분을 기록했는가 |
| 실행 검증 | AI가 만든 코드를 직접 실행하고 결과를 확인했는가 |
| 점검 한계 인식 | 자동 보안 점검의 한계를 이해하고 수동 확인을 병행했는가 |

## 핵심 정리

- AI 코딩 에이전트는 코드를 작성하고 실행하고 결과를 확인하는 넓은 범위의 작업을 수행한다.
- 큰 작업을 작은 단계로 나누면 AI의 오해를 줄이고 검증을 쉽게 할 수 있다.
- AI에게 코드를 요청할 때는 입력, 출력, 제약 조건을 명확히 적는다.
- AI가 만든 코드를 실행하기 전에 파일 삭제, 외부 전송, 비밀키 하드코딩을 확인한다.
- 자동 보안 점검은 위험을 줄이는 도구이지 위험을 없애는 도구가 아니다. 사람이 최종 판단한다.
- AI에게 코드를 맡길 수 있지만, 실행과 검증의 책임은 학생에게 있다.
