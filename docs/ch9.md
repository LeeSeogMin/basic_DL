# 제9장 이미지 인식과 CNN — 컴퓨터가 이미지를 보는 방식

---

### 학습 목표

- 이미지 한 장이 컴퓨터에게 어떤 숫자 덩어리인지 설명한다
- 픽셀과 채널을 구분하고, 흑백 이미지와 컬러 이미지가 숫자 판 몇 장인지 말한다
- 이미지를 한 줄로 펴서 넣으면 무엇이 사라지는지 실험 결과로 설명한다
- 3x3 필터로 합성곱을 손으로 한 칸 계산하고, 필터가 어떤 창에 큰 값을 내는지 말한다
- pooling이 크기를 줄이면서 무엇을 남기고 무엇을 남기지 못하는지 설명한다
- CNN의 층 순서를 그리고, 필터의 숫자를 학습으로 찾는다는 뜻을 설명한다

지금까지 다룬 데이터는 표였다. 가로줄 하나가 학생 한 명이었고, 세로줄 하나가 공부 시간이나 수면 시간 같은 특징이었다. 이번 장에서는 이미지를 다룬다. 이미지도 결국 숫자지만, 표와 달리 숫자가 **어느 칸에 놓였는지**에 뜻이 있다. 합성곱은 칸의 위치 관계를 살려서 계산하는 방법이고, 합성곱을 층으로 쌓은 신경망이 CNN이다.

이 장은 문제를 먼저 측정하고 해법을 뒤에 둔다. 1~3절에서 이미지를 숫자로 보고 한 줄로 펴서 넣는 방식을 설명한 뒤, 실습 9.1에서 그 방식으로 분류기를 만들어 어디까지 되고 어디서 무너지는지 측정한다. 4~5절에서 합성곱과 pooling을 설명하고, 실습 9.2에서 둘을 직접 계산한다. 6절에서는 이 계산을 층으로 쌓은 CNN의 구조를 그림으로 본다.

○ **합성곱을 직접 계산하는 이유**
  - 딥러닝 라이브러리는 합성곱을 함수 하나로 계산해 주므로, 안에서 무슨 일이 일어나는지 보이지 않는다
  - 이 장의 실습은 합성곱과 pooling을 numpy 반복문 두 개로 직접 계산하고, 필터의 숫자 아홉 개를 직접 정해 넣는다. 숫자를 바꾸면 결과가 어떻게 바뀌는지 칸 단위로 따라갈 수 있다

### 2. 픽셀과 채널

○ **픽셀(pixel)** — 이미지를 이루는 가장 작은 칸 하나
  - 8 x 8 이미지에는 픽셀이 64개 있다
  - 흑백 이미지에서 픽셀 하나는 밝기를 뜻하는 숫자 하나다

○ **채널(channel)** — 같은 크기의 숫자 판이 몇 장 겹쳐 있는가
  - 흑백은 판이 한 장이므로 채널 수가 1이다
  - 컬러는 빨강·초록·파랑 판이 한 장씩 있어서 채널 수가 3이다

![흑백은 숫자 판 한 장, 컬러는 세 장](../practice/chapter9/results/fig9-1-pixel-and-channel.png)

**그림 9.2** 같은 위치에 있는 세 판의 숫자 세 개가 색 하나를 만든다

컬러 이미지에서 픽셀 하나의 색을 알려면 숫자를 세 개 봐야 한다. 빨강 판에서 200, 초록 판에서 40, 파랑 판에서 60이면 그 픽셀은 붉은색이다.

이미지가 커지면 숫자 개수는 가로 × 세로 × 채널 수만큼 늘어난다.

**표 9.1** 이미지 크기와 숫자 개수

| 28 x 28 흑백 | 1 | 784 |

### 3. 한 줄로 펴서 넣으면 무엇이 사라지는가

5장에서 만든 신경망은 입력을 한 줄로 받았다. 이미지를 그 신경망에 넣으려면 8 x 8을 한 줄로 펴야 한다. 위 줄부터 차례로 이어 붙이면 숫자 64개짜리 한 줄이 된다. 이 작업을 **평탄화(flatten)**라고 부른다.

**그림 9.3** 주황 칸(4행 2열, 값 16)과 파랑 칸(5행 2열, 값 8)은 그림에서 위아래로 붙어 있다. 한 줄로 펴면 34번과 42번 자리로 가서 8칸 떨어진다

가로로 붙은 두 칸은 한 줄에서도 붙어 있다. 위아래로 붙은 두 칸은 한 줄이 8칸이라서 8칸 떨어진다. 그림에서는 같은 획에 속한 두 칸이 한 줄에서는 멀리 놓인다.

#### 3-2. 평탄화 모델은 칸 번호만 안다

평탄화 모델은 64칸을 0번부터 63번까지 번호로만 구별하고, 번호마다 가중치를 따로 둔다. "34번과 42번은 그림에서 위아래 이웃이다"라는 정보는 모델 어디에도 없다. 여기서 세 가지 결과를 예상할 수 있다.

○ **예측 1: 칸 순서를 섞어도 정확도가 거의 같다**
  - 모든 이미지의 칸 순서를 똑같이 섞으면 번호만 바뀌고 값은 그대로 남는다
  - 모델은 바뀐 번호에 맞춰 가중치를 배운다. 사람은 섞인 그림을 알아볼 수 없지만 모델에게는 차이가 없다

○ **예측 2: 그림을 한 칸 밀면 정확도가 무너진다**
  - 7을 오른쪽으로 한 칸 옮겨 써도 사람 눈에는 같은 7이다
  - 모델에게는 번호마다 들어오는 값이 바뀐다. 17번 이미지에서 34번 칸은 획의 밝기 16을 받았는데, 한 칸 밀면 배경의 0을 받는다

○ **문제 3: 이미지가 커지면 가중치가 너무 많아진다**
  - 첫 층 뉴런 하나가 모든 칸과 연결되므로, 가중치 수는 입력 숫자 수 × 뉴런 수다
  - 8 x 8 흑백에 뉴런 32개(실습 9.1의 모델)이면 64 × 32 = 2,048개다
  - 200 x 200 컬러에 뉴런 100개이면 120,000 × 100 = 12,000,000개다

○ **바로 다음 실습 9.1의 설정**
  - 1797장을 훈련 1257장과 테스트 540장으로 나누고, 8 x 8을 편 64개 숫자로 숫자 0~9를 분류한다
  - 정확도와 자주 헷갈린 짝을 본 뒤, 예측 1과 예측 2를 실험으로 확인한다
  - 실험 1은 64칸의 순서를 섞어 모델을 새로 학습한다. 실험 2는 학습이 끝난 모델에 한두 칸 민 테스트 이미지를 넣는다

### 실습 9.1: 64개 숫자로 분류하고 한계를 측정한다

#### 실습 목표

- 8 x 8을 한 줄로 편 64개 숫자로 숫자 0~9를 분류하고, 기준선과 비교한다
- 틀린 이미지를 모아 실패 갤러리를 만들고, 어떤 짝이 자주 헷갈리는지 찾는다
- 칸 순서를 섞었을 때와 그림을 밀었을 때 정확도가 어떻게 달라지는지 측정한다

#### 데이터와 모델

`load_digits()` 1797장이다. 모델은 scikit-learn의 `MLPClassifier`이고, 은닉층이 하나인 신경망이다. **CNN이 아니다.** 합성곱 층이 없다.

모델을 만드는 코드는 다음 한 줄이다.

```python
MLPClassifier(hidden_layer_sizes=(32,), max_iter=60, random_state=42)
```

○ **은닉층(hidden layer)이란**
  - 입력(숫자 64개)과 출력(숫자 0~9의 점수 10개) 사이에 있는 층이다. 입력과 출력은 우리가 정하는 값이고, 그 사이의 계산은 모델이 알아서 하므로 밖에서 보이지 않는다는 뜻에서 은닉(hidden, 숨겨진)이라고 부른다
  - 은닉층의 뉴런 하나는 앞 층의 숫자를 전부 받아 하나씩 가중치를 곱해 더한 값 하나를 내보낸다

○ **`hidden_layer_sizes=(32,)`를 읽는 법**
  - 괄호 안의 숫자 하나가 은닉층 하나이고, 숫자의 크기가 그 층의 뉴런 수다. `(32,)`는 "은닉층 1개, 뉴런 32개"다. 숫자가 하나뿐이어도 쉼표를 붙이는 것은 파이썬에서 원소가 하나인 묶음을 쓰는 규칙이다
  - `(64, 32)`라고 쓰면 은닉층이 2개이고 뉴런 수가 64개, 32개다. 숫자를 늘리면 층이 깊어지고, 숫자를 키우면 층이 넓어진다

○ **이 모델의 크기를 숫자로 보면**
  - 층별 뉴런 수는 입력 64 → 은닉 32 → 출력 10이다
  - 연결마다 가중치가 있다. 입력과 은닉층 사이는 64 × 32 = 2,048개, 은닉층과 출력 사이는 32 × 10 = 320개다. 뉴런마다 따로 더하는 값(편향)이 은닉층 32개, 출력층 10개 있어서 학습으로 정하는 숫자는 모두 2,410개다
  - 은닉층 뉴런 수를 바꾸면 이 개수가 바뀐다. 뉴런이 늘수록 모델이 만들 수 있는 모양이 다양해지고, 가중치도 그만큼 늘어난다. 7장 표 7.3에서 신경망의 복잡도 손잡이가 층 수와 뉴런 수라고 한 것이 이 값이다

#### 핵심 코드

파일 맨 위에 바꿀 값이 다섯 개 있다.

```python
SAMPLE_INDEX = 17      # 픽셀 표로 볼 손글씨 번호. 0부터 1796까지 넣을 수 있다.
HIDDEN_SIZE = 32       # 은닉층 뉴런 수. 크게 하면 정확도가 오르지만 느려진다.
MAX_ITER = 60          # 학습을 몇 바퀴 돌 것인가.
TEST_RATIO = 0.3       # 테스트로 떼어 둘 비율
GALLERY_SIZE = 12      # 실패 갤러리에 넣을 이미지 장수
```

`HIDDEN_SIZE`는 코드 안에서 `hidden_layer_sizes=(HIDDEN_SIZE,)`로 들어간다. 이 값을 32에서 128로 바꾸면 입력과 은닉층 사이의 가중치는 64 × 128 = 8,192개가 된다.

실험 1은 64칸의 순서를 한 번 정해 훈련과 테스트 모두에 똑같이 적용한 뒤 새로 학습한다.

```python
perm = np.random.default_rng(RANDOM_SEED).permutation(x.shape[1])
model_perm.fit(x_train[:, perm], y_train)
perm_acc = accuracy_score(y_test, model_perm.predict(x_test[:, perm]))
```

실험 2는 다시 학습하지 않는다. 테스트 이미지만 밀어서 원래 모델에 넣는다. 비는 칸은 0(검정)으로 채운다.

```python
shifted = shift_images(img_test, dx, dy)
acc = accuracy_score(y_test, model.predict(flatten(shifted)))
```

### 4. 합성곱과 필터

평탄화 모델은 칸 번호마다 따로 가중치를 배운다. 실습 9.1의 실험 2에서 그림을 한 칸 밀자 정확도가 0.933에서 0.439로 떨어진 결과도 이 구조와 맞는다. 합성곱은 다른 방식으로 묻는다. "이 근처 3 x 3 칸에 세로 획 모양이 있는가"를 이미지의 **모든 위치에서 같은 방식으로** 묻는다.

#### 4-1. 창 하나에서 곱하고 더한다

**필터(filter)**는 작은 숫자 판이다. 보통 3 x 3이나 5 x 5를 쓴다. **합성곱(convolution)**은 필터를 이미지 위에서 한 칸씩 옮기며, 겹친 숫자끼리 곱해서 전부 더하는 계산이다.

![3x3 창 하나에서 곱하고 더하는 과정](../practice/chapter9/results/fig9-2-convolution-step.png)

**그림 9.6** 주황 창 안의 숫자 아홉 개와 필터의 숫자 아홉 개를 위치마다 곱해 더하면, 출력 칸 하나가 채워진다. 그림의 5 x 5 입력은 설명용으로 손으로 고른 값이다

계산 순서는 세 단계다.

1. 이미지 왼쪽 위에서 3 x 3 창을 하나 떼어 낸다
2. 창의 숫자 아홉 개와 필터의 숫자 아홉 개를 **위치마다** 곱한 뒤 전부 더한다
3. 그 합 하나를 출력 칸 하나에 적고, 창을 오른쪽으로 한 칸 옮겨 반복한다

실습 9.2는 이 계산을 로그에 그대로 풀어 찍는다. 아래는 1절의 17번 이미지에서 2행 2열부터 시작하는 창에 세로선 필터를 씌운 결과다.

```text
  이미지 창          필터            곱한 값
    10    0   10   x    -1.0   0.0   1.0   =    -10.0    0.0   10.0
     3    5   15   x    -1.0   0.0   1.0   =     -3.0    0.0   15.0
    16   16   16   x    -1.0   0.0   1.0   =    -16.0    0.0   16.0

  더하기: (10x-1) + (0x0) + (10x1) + (3x-1) + (5x0) + (15x1) + (16x-1) + (16x0) + (16x1)
        = 12.0
```

_출처: `practice/chapter9/results/9-2-filter-and-pooling.log`_

#### 4-2. 필터는 생김새가 닮은 창에 큰 값을 낸다

세로선 필터는 왼쪽 열이 -1, 가운데 열이 0, 오른쪽 열이 +1이다. 가운데 열에는 0을 곱하므로 결과는 다음과 같다.

```
세로선 필터의 결과 = (오른쪽 열 세 칸의 합) - (왼쪽 열 세 칸의 합)
```

위 계산에 넣어 보면 오른쪽 열 합은 10 + 15 + 16 = 41, 왼쪽 열 합은 10 + 3 + 16 = 29이고, 41 - 29 = 12다. 곱셈 아홉 개를 푼 결과와 같다.

이 식에서 원리가 나온다. 필터의 +1 칸에 밝은 픽셀이, -1 칸에 어두운 픽셀이 겹치면 결과가 커진다. 즉 **창의 밝기 배치가 필터의 숫자 배치와 닮을수록 결과가 크다.** 반대로 생긴 창은 큰 음수가 되고, 좌우 밝기가 비슷한 창은 0 근처가 된다. 실습 9.2는 17번 이미지의 36개 창 가운데 세 개를 골라 이것을 확인한다.

![세로선 필터와, 그 필터에 가장 크게·가장 작게·0 근처로 반응한 창](../practice/chapter9/results/filter_similarity.png)

**그림 9.7** 맨 왼쪽은 세로선 필터다. 나머지 세 장은 17번 이미지에서 이 필터의 결과가 가장 큰 창, 가장 작은 창, 0에 가장 가까운 창이다

```text
가장 큰 결과: 4행 1열 창, 결과 37
  왼쪽 열 합 1, 오른쪽 열 합 38, 오른쪽 - 왼쪽 = 37
가장 작은 결과: 0행 4열 창, 결과 -39
  왼쪽 열 합 39, 오른쪽 열 합 0, 오른쪽 - 왼쪽 = -39
0에 가장 가까운 결과: 3행 3열 창, 결과 1
  왼쪽 열 합 33, 오른쪽 열 합 34, 오른쪽 - 왼쪽 = 1
```

_출처: `practice/chapter9/results/9-2-filter-and-pooling.log`_

○ **결과 37인 창** — 왼쪽 열이 거의 검정(합 1)이고 오른쪽 열이 밝다(합 38). 필터의 -1·+1 배치와 같은 모양이다. 획이 시작되는 왼쪽 경계다

○ **결과 -39인 창** — 왼쪽 열이 밝고(합 39) 오른쪽 열이 검정(합 0)이다. 필터와 좌우가 뒤집힌 모양이다. 획이 끝나는 오른쪽 경계다

○ **결과 1인 창** — 가운데 줄이 16, 16, 16으로 꽉 찼다. 좌우 밝기가 33과 34로 거의 같아서 세로 경계가 없다

필터를 바꾸면 "무엇과 닮았는가"의 기준이 바뀐다. 위 줄이 -1이고 아래 줄이 +1인 필터는 위가 어둡고 아래가 밝은 창, 즉 가로 경계에 큰 값을 낸다.

#### 4-3. 창을 옮기며 판 전체를 채운다

창 하나가 출력 칸 하나를 채운다. 창을 왼쪽 위에서 오른쪽으로 한 칸씩 옮기고, 줄 끝에 닿으면 한 줄 내려가 다시 왼쪽부터 옮긴다.

![창이 한 칸씩 옮겨 가며 6x6 출력을 채우는 과정](../practice/chapter9/results/sliding_window.png)

**그림 9.8** 윗줄의 주황 창 하나가 아랫줄의 초록 칸 하나가 된다. 1번째·2번째·6번째·36번째 창을 골라 그렸다

○ **8 x 8이 6 x 6이 되는 이유**
  - 창은 이미지 밖으로 나갈 수 없다. 3 x 3 창의 왼쪽 위 모서리가 놓일 수 있는 위치는 가로로 0~5열의 6개, 세로로 0~5행의 6개다
  - 그래서 출력은 6 x 6 = 36칸이다. 일반식은 `출력 크기 = 입력 크기 - 필터 크기 + 1`이고, 8 - 3 + 1 = 6이다
  - 가장자리를 0으로 채워 출력 크기를 입력과 같게 유지하는 방법(padding)도 있다. 이 장의 계산은 padding 없이 한다

○ **36개 창 모두에 같은 필터를 쓴다**
  - 평탄화 모델은 64칸마다 다른 가중치를 두었다. 합성곱은 36개 위치 모두에 같은 숫자 아홉 개를 쓴다
  - 그래서 어떤 무늬가 2열에 있든 4열에 있든 같은 크기의 값이 나온다. 무늬가 옮겨 가면 큰 값이 나오는 출력 칸도 함께 옮겨 갈 뿐이다. 실습 9.2에서 그림을 한 칸 밀어 이것을 확인한다
  - 이미지가 커져도 필터의 숫자는 아홉 개 그대로다. 3절의 문제 3(가중치 폭증)이 이렇게 줄어든다

### 5. pooling — 크기를 줄이고 강한 반응만 남긴다

합성곱 출력은 입력보다 조금 작을 뿐 여전히 숫자가 많다. **pooling**은 출력 크기를 크게 줄이는 단계다. 가장 흔한 방식은 겹치지 않는 2 x 2 덩어리마다 가장 큰 값 하나만 남기는 **최대 pooling(max pooling)**이다.

![2x2 최대 pooling](../practice/chapter9/results/fig9-3-pooling.png)

**그림 9.9** 2 x 2 덩어리마다 최댓값 하나만 남긴다. 숫자 16개가 4개로 줄었다. 그림의 숫자는 설명용으로 손으로 고른 값이다

○ **크기가 4분의 1로 줄어든다**
  - 6 x 6에 2 x 2 pooling을 하면 3 x 3이 된다. 가로 절반, 세로 절반이므로 칸 수는 36에서 9로 4분의 1이 된다
  - 뒤에 오는 층이 다룰 숫자가 그만큼 줄어든다

○ **덩어리 안에서의 작은 이동은 지운다**
  - pooling 결과에는 덩어리 안 네 칸 가운데 어느 칸이 가장 컸는지가 남지 않는다
  - 그래서 강한 반응이 덩어리 안에서 한 칸 옮겨 가면 pooling 결과는 그대로다

○ **덩어리 경계를 넘는 이동은 지우지 못한다**
  - 강한 반응이 옆 덩어리로 넘어가면 그 값은 옆 칸에 나타난다
  - 2 x 2 pooling 한 번으로 모든 이동을 흡수하지는 못한다. 실습 9.2에서 이 경우를 직접 본다

○ **남는 것과 잃는 것**
  - "얼마나 강한 반응이었는가"는 남고, "정확히 어느 칸이었는가"는 흐려진다
  - 위치를 정밀하게 알아야 하는 문제에서는 이 손실이 단점이 된다

○ **바로 다음 실습 9.2의 설정**
  - 1절의 17번 이미지를 그대로 쓴다
  - 창 하나의 계산(4-1), 닮은 창 찾기(4-2), 창 옮기기(4-3)를 로그와 그림으로 출력한다
  - 필터 네 개를 적용해 결과를 비교하고, 내가 만든 필터를 하나 넣어 본다
  - 이미지를 오른쪽으로 한 칸 민 뒤, 합성곱 결과와 2 x 2 pooling 결과를 원본과 비교한다

### 실습 9.2: 필터와 pooling을 직접 계산한다

#### 실습 목표

- 3 x 3 창 하나의 합성곱을 곱셈 아홉 개까지 풀어서 확인한다
- 필터의 숫자를 직접 바꿔 결과가 달라지는 것을 본다
- 그림을 한 칸 밀었을 때 합성곱 결과와 pooling 결과가 어떻게 바뀌는지 확인한다

#### 데이터

`load_digits()`의 8 x 8 손글씨 1797장 중 한 장을 고른다. 기본값은 1절의 17번 이미지다.

#### 실행 명령

```bash
cd practice/chapter9/code
python 9-2-filter-and-pooling.py
```

#### 핵심 코드

파일 맨 위에 학생이 바꿀 값이 세 개 있다.

```python
SAMPLE_INDEX = 17          # 몇 번째 손글씨를 볼 것인가
MY_FILTER = np.array([     # 내가 만드는 필터. 3x3 숫자를 마음대로 바꿔 본다
    [0.0, -1.0, 0.0],
    [-1.0, 4.0, -1.0],
    [0.0, -1.0, 0.0],
])
SHIFT_PIXELS = 1           # pooling 비교에서 이미지를 오른쪽으로 몇 칸 밀 것인가
```

합성곱은 반복문 두 개다. 창을 떼어 내고, 필터와 곱해 더한다.

```python
for r in range(out_h):
    for c in range(out_w):
        window = image[r:r + kh, c:c + kw]
        out[r, c] = float(np.sum(window * kernel))
```

최대 pooling도 반복문 두 개다. 2 x 2 덩어리를 떼어 내고, 가장 큰 값을 남긴다.

```python
for r in range(out_h):
    for c in range(out_w):
        block = feature[r * size:(r + 1) * size, c * size:(c + 1) * size]
        out[r, c] = float(block.max())
```

**그림 9.11** 윗줄은 원본, 아랫줄은 오른쪽으로 1칸 민 이미지다. 가운데 판은 세로선 필터 결과 6 x 6이고, 검은 선은 2 x 2 pooling 덩어리의 경계다. 오른쪽 판은 pooling 결과 3 x 3이다

#### 결과 읽기

○ **흐리게 필터만 최솟값이 양수다**
  - 아홉 칸이 전부 1/9라서 결과는 주변 아홉 칸의 평균이다. 평균은 원래 값의 범위(0~16)를 벗어나지 않는다
  - 나머지 세 필터에는 음수가 들어 있어서 결과도 음수가 나온다. 음수는 "필터가 찾는 무늬와 반대로 생긴 창"이라는 뜻이다(4-2)

○ **그림을 한 칸 밀면 합성곱 결과도 같은 값 그대로 한 칸 밀린다**
  - 로그에는 "밀린 결과의 1열부터 끝까지 == 원본 결과의 0열부터 4열까지: 같다"가 찍힌다. 그림 9.11 가운데 판의 24, 26, 29, 27, 24, 8 열이 한 칸 오른쪽으로 옮겨 갔다
  - 실습 9.1의 평탄화 모델은 같은 이동에서 정확도가 0.933에서 0.439로 떨어졌다. 합성곱 결과는 값이 바뀌지 않고 위치만 바뀐다
  - 36개 위치 모두에 같은 필터를 썼기 때문이다(4-3)

○ **2 x 2 pooling 한 번으로는 한 칸 이동을 다 흡수하지 못한다**
  - pooling 결과 아홉 칸 가운데 값이 같은 칸은 1칸뿐이다
  - 가장 큰 반응 37은 원본에서 왼쪽 아래 덩어리에 있었고, 밀린 이미지에서는 가운데 아래 덩어리로 넘어갔다. 덩어리 경계를 넘은 이동이다(5절)
  - 그래도 가장 큰 반응의 크기 37은 그대로 남았다. pooling을 여러 번 거쳐 덩어리가 커질수록, 이미지 안 어디에 무늬가 있든 "그 무늬가 있었다"는 사실이 같은 값으로 남는다

#### 해 보기

1. `MY_FILTER`의 아홉 개 숫자를 전부 0으로 둔다. 결과가 어떻게 되는가
2. 세로선 필터를 90도 돌린 값(위 줄 -1, 아래 줄 +1)을 `MY_FILTER`에 넣는다. 가로선 검출 필터와 같은 그림이 나오는가
3. 가운데만 1이고 나머지가 0인 필터를 넣으면 원본이 그대로 나온다. 왜 그런지 4-1의 계산 순서로 설명한다
4. `SHIFT_PIXELS`를 2로 바꾼다. pooling 결과 3 x 3에서 값이 같은 칸이 몇 칸으로 바뀌는가. 두 칸 이동이 2 x 2 덩어리와 어떤 관계인지 설명한다
5. `SAMPLE_INDEX`를 0으로 바꾼다. 숫자 0의 세로선 필터 결과에서 양수와 음수는 각각 어느 쪽에 모이는가

○ 확인할 것은 정확도가 아니다. **필터의 숫자 아홉 개를 바꾸면 찾는 무늬가 바뀐다**는 것과 **합성곱 결과는 그림과 함께 옮겨 간다**는 것을 눈으로 확인하면 된다

### 6. CNN의 전체 모양

CNN(Convolutional Neural Network, 합성곱 신경망)은 4~5절의 계산을 층으로 쌓은 신경망이다.

![8x8 입력에 필터 4개를 쓰는 작은 CNN의 층 순서](../practice/chapter9/results/fig9-4-cnn-structure.png)

**그림 9.12** 8 x 8 입력에 필터 4개를 쓰는 작은 CNN의 개념 도식이다. 판의 크기는 8 → 6 → 3으로 줄고, 판의 장수는 1 → 4로 는다

그림 9.12의 크기는 이 장의 계산 규칙에서 나온다. 3 x 3 필터를 쓰면 8 x 8이 6 x 6이 되고(4-3), 필터 하나가 판 하나를 만들므로 필터 4개면 6 x 6 판이 4장이다. 2 x 2 pooling을 거치면 3 x 3 판 4장이 되고, 이것을 펴면 숫자 36개다. 마지막 완전연결층이 이 36개로 숫자 0~9의 점수 10개를 계산한다. 실제 CNN은 합성곱·ReLU·pooling 묶음을 여러 번 반복하고, 필터도 수십~수백 개를 쓴다.

○ **앞쪽 층은 단순한 무늬를, 뒤쪽 층은 무늬의 조합을 찾는다**
  - 첫 합성곱 층의 필터는 4절에서 본 것처럼 경계나 선에 큰 값을 낸다
  - 그 결과 판 위에 다시 합성곱을 걸면, 다음 층의 필터는 "세로 경계 판과 가로 경계 판에서 이런 배치로 큰 값이 모인 곳"에 큰 값을 낸다
  - pooling으로 판 크기를 줄여 가며 이 과정을 반복하면, 뒤쪽 층의 칸 하나가 입력 이미지의 넓은 범위를 대표하게 된다

○ **필터의 숫자를 사람이 정하지 않는다**
  - 실습 9.2에서 필터의 숫자 아홉 개는 사람이 정했다. 세로선 필터도, 흐리게 필터도 사람이 고른 값이다
  - CNN에서는 이 아홉 개 숫자가 **가중치**다. 6장의 경사하강법이 손실을 줄이는 방향으로 이 숫자를 고친다
  - 즉 CNN이 학습하는 것은 "어떤 무늬를 찾을지"다

**표 9.4** 3절의 문제와 CNN이 쓰는 방법

| 평탄화 방식의 문제 | 실습에서 확인한 것 | 합성곱·pooling이 하는 일 |
|---|---|---|
| 칸 사이의 이웃 관계를 쓰지 않는다 | 순서를 섞어도 0.933 → 0.943 | 3 x 3 창으로 붙어 있는 칸끼리만 묶어 계산한다 |
| 위치가 밀리면 배운 것을 쓰지 못한다 | 1칸 밀면 0.933 → 0.439 | 같은 필터를 모든 위치에 쓰므로 결과가 그림과 함께 옮겨 가고, pooling이 작은 이동을 지운다 |
| 이미지가 커지면 가중치가 폭증한다 | 8 x 8에서도 첫 층 가중치 2,048개 | 필터 하나의 숫자는 9개이고, 이미지가 커져도 그대로다 |

_출처: `practice/chapter9/results/9-1-flatten-classifier.log`, `practice/chapter9/results/9-2-filter-and-pooling.log`_

두 실습으로 확인한 것은 두 가지다. 평탄화 모델은 그림이 한 칸만 밀려도 정확도가 반 아래로 떨어진다(실습 9.1). 사람이 정한 필터 하나는 이미지에서 특정 무늬를 끄집어내고, 그림이 밀리면 그 결과도 같은 값으로 함께 밀린다(실습 9.2). 표 9.4의 오른쪽 열은 합성곱과 pooling의 계산 구조에서 나오는 성질이며, 학습을 마친 CNN의 정확도로 확인한 값이 아니다.

필터의 숫자를 데이터에서 찾는 원리는 6장의 경사하강법과 같다. 실제로 CNN을 학습시킬 때는 합성곱 층과 경사 계산을 함께 제공하는 PyTorch나 TensorFlow 같은 딥러닝 라이브러리를 쓴다.

### 핵심 정리

| 개념 | 한 줄 정리 |
|---|---|
| 픽셀 | 이미지의 가장 작은 칸 하나. 흑백에서는 숫자 하나가 밝기를 뜻한다 |
| 채널 | 같은 크기의 숫자 판이 몇 장 겹쳤는가. 흑백은 1장, 컬러는 3장이다 |
| 평탄화 | 이미지를 한 줄로 펴는 것. 칸 순서를 섞어도 성능이 같고, 그림을 1칸 밀면 성능이 반 아래로 떨어진다 |
| 합성곱 | 작은 창을 옮기며 겹친 숫자끼리 곱해 더하는 계산. 8x8에 3x3을 쓰면 6x6이 나온다 |
| 필터 | 합성곱에 쓰는 작은 숫자 판. 창의 밝기 배치가 필터의 숫자 배치와 닮을수록 결과가 크다 |
| 같은 필터 공유 | 모든 위치에 같은 필터를 쓰므로, 그림이 옮겨 가면 결과도 같은 값으로 옮겨 간다 |
| pooling | 덩어리마다 최댓값 하나만 남긴다. 크기를 줄이고 덩어리 안의 작은 이동을 지운다 |
| CNN | 합성곱과 pooling을 층으로 쌓은 신경망. 필터의 숫자를 데이터에서 학습한다 |

다음 장에서는 이미지 대신 문장을 다룬다. 문장을 숫자로 바꾸는 방법이 이미지와 어떻게 다른지가 드러난다.
