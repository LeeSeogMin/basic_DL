### 1. 컴퓨터는 글자를 모른다

○ **글자는 번호로 저장된다**
  - 파일 안에서 '가'는 44032번, '나'는 45208번 같은 번호로 저장된다
  - 다만 이 번호에는 뜻이 없다

○ **번호끼리 빼 보면 드러난다**
  - '가'와 '나'의 번호 차이는 1176이고, '가'와 '개'의 번호 차이는 28이다
  - 그렇다고 '가'가 '나'보다 '개'에 42배 더 가까운 낱말인 것은 아니다
  - 글자 번호는 글자마다 자리를 정해 주려고 붙인 번호이고, 뜻이 얼마나 가까운지 나타내려고 붙인 번호가 아니다

○ **모델에 넣을 숫자가 가져야 할 성질**
  - 뜻이 비슷한 두 문장은 숫자도 비슷하고, 뜻이 먼 두 문장은 숫자도 멀어야 한다
  - 이 장의 내용은 전부 이 성질을 어떻게 만드는지에 관한 것이다

**그림 10.1** 문장 → 토큰 → 사전 → 벡터. 마지막 줄 `[1, 1, 1, 0, 0]`이 모델에 들어간다. 그림은 개념을 보여 주려고 손으로 만든 도식이고, 실제 숫자는 실습 10.1 로그에서 확인한다

### 2. 토큰과 사전

○ **토큰**(token) — 문장을 자를 때 나오는 조각 하나
  - 어디서 자를지는 사람이 정하고, 자르는 규칙에 따라 토큰의 개수와 종류가 달라진다
  - 이 장에서 쓰는 규칙은 두 줄이다

1. 문장부호를 공백으로 바꾼다
2. 공백으로 자른다

- "배송이 정말 빨라요"를 이 규칙으로 자르면 `배송이 | 정말 | 빨라요` 세 조각이 나온다

○ **사전**(vocabulary) — 문장들에서 나온 서로 다른 토큰에 번호를 붙인 목록
  - 실습 10.1에서 문장 8개를 자르면 서로 다른 단어가 19개 나온다
  - 이 19가 문장 하나를 나타내는 숫자 줄의 길이가 된다

○ **한국어가 까다로운 이유**
  - 영어는 공백으로 자르면 대체로 낱말이 나온다. `delivery`가 두 문장에 나오면 같은 단어로 잡힌다
  - 한국어는 낱말 뒤에 조사와 어미가 붙는다. 공백으로만 자르면 "배송이", "배송은", "배송도"가 서로 다른 단어 세 개로 잡힌다
  - "배송이"를 "배송 + 이"로 쪼개 주는 프로그램이 **형태소 분석기**다. 이 장에서는 설치하지 않고, 조사가 붙은 채로 두면 무엇이 망가지는지를 실습 10.2에서 먼저 확인한다

### 3. 단어 가방과 코사인 유사도

#### 3-1. 단어 가방 표

○ **단어 가방**(bag of words) — 문장을 숫자 줄로 바꾸는 가장 단순한 방법
  - 사전의 단어마다 열을 하나씩 만들고, 문장에 그 단어가 몇 번 나왔는지 칸에 적는다
  - 행은 문장, 열은 단어, 칸은 나온 횟수다

![단어 가방 표의 생김새](../practice/chapter10/results/fig10-2-bag-of-words.png)

**그림 10.2** 초록 칸이 1, 회색 칸이 0이다

○ **"가방"이라는 이름** — 단어를 가방에 쏟아 담으면 순서가 사라진다
  - "나는 밥을 먹었다"와 "밥을 나는 먹었다"는 토큰 세 개가 같으므로 표에서 같은 줄이 된다. 두 문장은 뜻도 같으니 잃은 정보가 없다
  - 영어 `dog bites man`과 `man bites dog`는 토큰 세 개가 같은데 뜻이 반대다. 단어 가방은 두 문장을 구분하지 못한다

#### 3-2. 두 문장이 얼마나 닮았는가 — 코사인 유사도

○ **코사인 유사도**(cosine similarity) — 두 화살표가 같은 쪽을 가리키는 정도
  - 표의 한 줄은 숫자 19개짜리 화살표(벡터)로 볼 수 있다
  - 두 줄이 같은 쪽을 가리키면 1, 직각이면 0이다

![코사인 유사도는 두 화살표가 이루는 각도](../practice/chapter10/results/fig10-4-cosine.png)

**그림 10.3** 사전에 단어가 "배송이", "하루" 두 개뿐이라고 가정한 그림이다. 겹치는 단어가 없는 두 문장은 서로 다른 축 위에 놓여 직각을 이루므로 유사도가 0이다. 화살표 좌표는 설명용으로 손으로 정한 값이다

계산 순서는 다음과 같다.

1. 두 줄에서 같은 칸끼리 곱해 모두 더한다
2. 각 줄의 길이를 구한다. 칸마다 제곱해 더한 뒤 제곱근을 씌운다
3. 1의 값을 두 길이의 곱으로 나눈다

○ **칸이 0과 1뿐일 때**
  - 1번 값은 **두 문장에 모두 나온 단어 수**가 된다
  - 줄의 길이는 √(그 문장의 단어 수)가 된다
  - 실습 10.1의 문장2와 문장3으로 계산하면 다음과 같다

```text
  문장2: 배송이 하루 만에 왔어요   -> 1이 찍힌 칸 4개
  문장3: 택배가 하루 만에 도착했어요   -> 1이 찍힌 칸 4개
  두 문장에 모두 1이 찍힌 칸(겹친 단어): 2개 (만에, 하루)
  코사인 유사도 = 같은 칸끼리 곱해 더한 값 / (각 줄의 길이를 곱한 값)
              = 2 / (√4 x √4) = 2 / 4.00 = 0.50
```

_출처: `practice/chapter10/results/10-1-text-to-numbers.log`_

○ **이 계산에서 나오는 성질**
  - **겹친 단어가 0개면 분자가 0이므로 유사도도 0이다**
  - 단어 가방은 글자가 같은 단어가 있는지만 보고, 뜻이 같은지는 보지 않는다

#### 3-3. TF-IDF — 흔한 단어의 무게를 낮춘다

○ **단어 가방의 빈틈** — "하루"처럼 여러 문장에 나오는 단어와 "왔어요"처럼 한 문장에만 나오는 단어가 똑같이 1이다

○ **TF-IDF** — 여러 문장에 나오는 단어의 칸 값을 낮추고, 적은 문장에만 나오는 단어의 칸 값을 높인다
  - 문장2의 칸 값은 다음과 같이 바뀐다

```text
문장2의 TF-IDF 칸 값(0이 아닌 칸만, 줄의 길이를 1로 맞춘 값)
  왔어요    0.60   (이 단어가 나온 문장 1개)
  배송이    0.51   (이 단어가 나온 문장 2개)
  만에     0.44   (이 단어가 나온 문장 3개)
  하루     0.44   (이 단어가 나온 문장 3개)
단어 가방으로 계산한 문장2-문장3 유사도는 0.50, TF-IDF로 계산하면 0.36로 바뀐다.
```

_출처: `practice/chapter10/results/10-1-text-to-numbers.log`_

○ **결과 읽기**
  - 문장2와 문장3이 공유한 "하루"와 "만에"는 문장 3개에 나오는 흔한 단어라서 칸 값이 0.44로 낮아졌다
  - 그래서 유사도가 0.50에서 0.36으로 내려갔다
  - TF-IDF도 겹친 단어의 칸끼리만 곱하므로, 겹치는 단어가 없으면 유사도는 여전히 0이다

#### 3-4. 실습 전에 세우는 예측

3-2의 계산 방식에서 세 가지 결과를 예상할 수 있다.

○ **예측 1: 뜻이 같아도 단어가 안 겹치면 유사도가 0이다**
  - "배송이 정말 빨라요"와 "택배가 하루 만에 도착했어요"는 사람이 보면 같은 이야기다
  - 두 문장에는 겹치는 단어가 하나도 없으므로 분자가 0이 된다

○ **예측 2: 뜻이 달라도 단어가 겹치면 유사도가 0보다 크다**
  - "택배가 하루 만에 도착했어요"와 "배터리가 하루 만에 닳아요"는 칭찬과 불만이다
  - 두 문장은 "하루", "만에"를 공유하므로 분자가 0이 아니다

○ **문제 3: 표가 거의 0으로 채워진다**
  - 한 문장은 단어 서너 개만 쓰는데 열은 사전의 단어 수만큼 있다
  - 문장을 더 모으면 사전이 커지고, 한 문장이 채우는 칸의 비율은 더 작아진다

```python
def tokenize(text: str) -> list[str]:
    cleaned = re.sub(r"[^\w\s]", " ", text)   # 문장부호를 공백으로

```

### 4. 임베딩 — 뜻은 이웃 단어에서 온다

○ **실습 10.1에서 남은 문제**
  - "배송이"와 "택배가"는 표에서 서로 다른 열이었고, 두 열 사이에는 아무 연결이 없었다
  - 그래서 뜻이 같은 문장1과 문장3의 유사도가 0이었다

○ **임베딩**(embedding) — 단어나 문장을 짧은 실수 벡터로 바꾸되, 뜻이 가까운 단어끼리 벡터도 가깝게 놓는 방법

#### 4-1. 임베딩이 단어 가방과 다른 두 가지

Google 머신러닝 단기집중과정은 임베딩을 "희소 데이터의 저차원 표현"으로 정의한다.[^google-emb] 이 정의에 두 가지가 들어 있다.

○ **저차원** — 열의 개수를 줄인다
  - 단어 가방은 사전에 단어가 10만 개면 열도 10만 개다
  - 임베딩은 단어 하나를 수십~수백 개의 숫자로 나타낸다

○ **희소하지 않다** — 칸이 0으로 차 있지 않다
  - 단어 가방의 한 줄은 대부분 0이고 몇 칸만 1이다(실습 10.1에서 82.2%가 0)
  - 임베딩의 한 줄은 모든 칸에 0.31, -0.07 같은 실수가 들어 있다

○ **칸마다 실수가 들어 있으면 달라지는 점**
  - 겹치는 단어가 없는 두 문장도 가까울 수 있다
  - "택배가"와 "배송이"의 벡터를 가깝게 만들어 두면, 두 단어로 만든 문장 벡터도 가까워진다

![뜻이 비슷한 문장이 가까이 모이는 평면](../practice/chapter10/results/fig10-3-sentence-space.png)

**그림 10.5** 임베딩으로 만들려는 배치 — 배송 이야기끼리, 화면 이야기끼리 모인다. 좌표는 설명을 위해 손으로 정한 값이다

#### 4-2. 이웃이 같으면 뜻이 가깝다고 본다

○ **두 단어가 비슷하다는 근거 = 이웃 단어**
  - "배송이"와 "택배가"는 한 문장에 같이 나오지 않아도, 둘 다 "하루 만에", "도착했어요", "빨라요" 옆에 나온다
  - 이웃이 같은 두 단어를 뜻이 가까운 단어로 본다

실습 10.1의 5단계는 이 원리를 세 단계로 계산한다.

1. **이웃 표를 만든다** — 합성 문장 22개에서 서로 다른 단어 35개를 뽑아 35행 x 35열 표를 만든다. 칸에는 두 단어가 같은 문장에 함께 나온 문장 수를 적는다. 단어 하나는 이 표의 한 줄, 즉 숫자 35개짜리 벡터가 된다
2. **줄을 짧게 줄인다** — 4단계와 같은 `TruncatedSVD`로 35칸을 3칸으로 줄인다. 이 3칸짜리 벡터가 단어 벡터다
3. **문장 벡터를 만든다** — 문장에 든 단어 벡터의 평균을 문장 벡터로 쓰고, 문장끼리 코사인 유사도를 계산한다

```text
--- 이웃 표에서 두 단어의 줄을 비교한다 ---
  배송이 - 택배가
    같은 문장에 함께 나온 횟수: 0회
    배송이의 이웃 11개, 택배가의 이웃 9개, 공유한 이웃 7개 (늦게, 도착했어요, 만에, 빨라요, 왔어요, 정말, 하루)
    두 줄의 코사인 유사도: 0.70
  화면이 - 액정이
    같은 문장에 함께 나온 횟수: 0회
    화면이의 이웃 7개, 액정이의 이웃 6개, 공유한 이웃 5개 (또렷해요, 밝고, 선명해요, 어두워서, 크고)
    두 줄의 코사인 유사도: 0.77
  배송이 - 화면이
    같은 문장에 함께 나온 횟수: 0회
    배송이의 이웃 11개, 화면이의 이웃 7개, 공유한 이웃 0개 (없음)
    두 줄의 코사인 유사도: 0.00
```

### 5. 텍스트 분류와 감성 분석

○ **텍스트 분류**(text classification) — 문장을 넣으면 이름표 하나를 돌려주는 문제
  - 4장에서 다룬 분류와 같은 틀이고, 입력이 표 대신 문장일 뿐이다
  - 메일이 스팸인지, 문의 글이 배송 문제인지 결제 문제인지, 리뷰가 칭찬인지 불만인지를 가리는 데 쓴다

○ **감성 분석**(sentiment analysis) — 의견이 긍정인지 부정인지 가리는 텍스트 분류
  - Google 텍스트 분류 가이드는 감성 분석을 "콘텐츠가 표현하는 의견의 유형을 파악"하는 일로 정의한다.[^google-text]

#### 5-1. 단어 가중치를 더해 확률을 만든다

○ **만드는 순서** — 4장과 같다
  - 문장마다 정답(긍정 1, 부정 0)을 붙인다
  - 문장을 단어 가방 벡터로 바꾸고, 로지스틱 회귀를 학습시킨다
  - 처음 보는 문장으로 정확도를 측정한다

○ **가중치**(weight) — 학습이 끝나면 사전의 단어마다 붙는 숫자 하나
  - 가중치가 양수인 단어는 긍정 쪽으로, 음수인 단어는 부정 쪽으로 판단을 민다
  - 문장 하나의 확률은 다음 두 줄로 계산한다

```
점수 z = 절편 + (문장에 든 단어의 가중치를 모두 더한 값)
긍정 확률 = 1 / (1 + e^(-z))
```

○ **두 줄 읽는 법**
  - 절편은 단어와 상관없이 늘 더하는 숫자다
  - 둘째 줄은 4장의 시그모이드 함수다. z가 0이면 0.5, z가 양수면 0.5보다 크고, 음수면 0.5보다 작다
  - 실습 10.2의 로그가 반어 문장 하나를 이 식으로 풀어 찍는다

```text
문장: 정말 좋겠다, 배송이 일주일이나 걸려서
  점수 z = 절편(-0.090) + 아는 단어 가중치의 합 (+0.382) + (-0.196) + (-0.295)
        = -0.199
  긍정 확률 = 1 / (1 + e^(-z)) = 1 / (1 + e^(+0.199)) = 0.450
  모델이 직접 낸 확률(predict_proba): 0.450
```

_출처: `practice/chapter10/results/10-2-sentiment.log`_

○ **결과 읽기**
  - 세 가중치는 각각 "정말"(+0.382), "배송이"(-0.196), "일주일이나"(-0.295)의 값이다
  - 손으로 계산한 0.450과 모델이 낸 0.450이 같다
  - 모델이 하는 일이 이 덧셈과 시그모이드 계산이라는 것을 확인할 수 있다

#### 5-2. 실습 전에 세우는 예측

5-1의 계산 방식에서 세 가지 약점을 예상할 수 있다.

○ **예측 1: 처음 보는 단어는 판단에 끼지 못한다**
  - 가중치는 훈련 문장에 나온 단어에만 붙는다. 처음 보는 단어는 z의 덧셈에서 빠진다
  - 2절의 조사 문제와 겹친다. 훈련 문장에 "화면이"가 있어도 "화면은"은 처음 보는 단어다

○ **예측 2: 부정어를 읽지 못한다**
  - z는 단어 가중치를 더할 뿐 순서를 보지 않는다
  - "나쁘지 않아요"에서 "않아요"가 "나쁘지"를 뒤집는다는 규칙을 덧셈으로 나타낼 수 없다

○ **예측 3: 한쪽 라벨에만 나온 단어가 큰 가중치를 받는다**
  - 어떤 단어가 긍정 문장에만 나오면, 그 단어를 부정 쪽으로 미는 근거가 훈련 문장에 하나도 없다
  - 그 단어가 원래 감정과 무관한 말이어도 긍정 단어가 된다

### 6. 학습 문장이 치우치면 생기는 일

○ **모델은 감정 단어를 훈련 문장에서만 배운다**
  - 실습 10.2의 훈련 문장 44개에는 서로 다른 단어 89개가 나온다
  - 그중 72개(80.9%)가 긍정 문장이나 부정 문장 **한쪽에만** 나온다
  - 가중치 상위 10개와 하위 10개, 모두 20개가 이 72개 안에 든다

○ **"정말"이 긍정 단어가 된 과정**
  - "정말"은 강조하는 말이므로 "정말 좋아요"에도 "정말 별로예요"에도 붙는다
  - 실습 10.2의 훈련 문장에서는 "배송이 정말 빨라요" 한 문장에만 나왔다. 긍정 1회, 부정 0회다
  - 모델은 "정말"에 +0.382를 줬다. 문장 하나에 나왔다는 이유로 긍정 단어가 되었다
  - "좋아요"는 긍정 문장 6개에만 나와 +1.185를 받았다. "좋아요"는 뜻이 긍정이라서 긍정 쪽에 몰렸고, "정말"은 우연히 긍정 문장에만 들어갔다

○ **데이터 편향** — 데이터가 세상의 일부만 담고 있는데 모델이 그 일부를 전부로 취급하는 현상
  - 데이터의 문장 하나하나가 틀린 것은 아니다

○ **알아채는 방법**
  - 단어마다 긍정 문장에 몇 번, 부정 문장에 몇 번 나왔는지 센다. 실습 10.2의 5단계 표가 이 일을 한다
  - 한쪽이 0인 단어가 가중치 상위에 몰려 있으면 의심한다
  - 그 단어를 사람이 읽어 본다. "실망했어요"가 부정 쪽에 몰린 것은 뜻 때문이고, "정말"이 긍정 쪽에 몰린 것은 우연이다

○ **생성형 AI에게 학습 문장을 만들게 할 때**
  - "긍정 리뷰 30개를 써 줘"라고 요청하면 비슷한 문장이 반복해서 나올 수 있다
  - 긍정 문장에는 "만족", 부정 문장에는 "실망"만 되풀이될 수 있다
  - 만들어진 문장을 바로 쓰지 말고, 위의 단어 횟수 세기를 먼저 해 본다

|---|---|---|
| 텍스트 분류(text classification) | 문장 하나에 이름표 하나 | 리뷰가 긍정인지 부정인지(실습 10.2), 메일이 스팸인지 |
| 토큰 분류(token classification) | 토큰마다 이름표 하나 | "서울에서 김철수가 주문했다"에서 "서울"은 장소, "김철수"는 사람이라고 표시하기 |
| 문장 유사도(sentence similarity) | 두 문장이 닮은 정도를 나타내는 숫자 | 비슷한 문의 글 찾기(실습 10.1의 코사인 유사도) |
| 특징 추출(feature extraction) | 문장이나 단어의 벡터 | 문장을 임베딩 벡터로 바꿔 검색·추천에 쓰기(4절) |
| 질의응답(question answering) | 질문에 대한 답 | 제품 설명서에서 "충전 시간은?"의 답 찾기 |
| 요약(summarization) | 짧게 줄인 글 | 긴 회의록을 몇 줄로 줄이기 |
| 번역(translation) | 다른 언어로 옮긴 글 | 한국어 리뷰를 영어로 옮기기 |
| 텍스트 생성(text generation) | 이어지는 글 | 다음 단어를 예측해 문장 이어 쓰기(11장) |

_참고: 작업 이름은 Hugging Face Tasks 페이지(https://huggingface.co/tasks, 2026년 11월 확인)의 Natural Language Processing 분류에서 골랐다. 각 작업의 예는 이 장의 내용에 맞춰 직접 든 것이다_

헷갈리기 쉬운 작업은 다음처럼 구분한다.

○ **텍스트 분류와 토큰 분류**
  - 텍스트 분류는 문장 전체에 이름표 하나를 붙이고, 토큰 분류는 토큰마다 이름표를 붙인다
  - 9장의 이미지 분류와 의미 분할(픽셀마다 이름표)의 관계와 같다

○ **문장 유사도와 특징 추출**
  - 특징 추출은 문장을 벡터로 바꾸는 단계이고, 문장 유사도는 그 벡터 두 개로 코사인 유사도 같은 값을 계산하는 단계다
  - 실습 10.1의 5단계에서 문장 벡터를 만든 것이 특징 추출, 그 벡터로 0.88을 계산한 것이 문장 유사도에 해당한다

○ **틀릴 수 있다**
  - 실습 10.2처럼 자연어 처리 모델도 반어와 부정어에서 틀리고, 처음 보는 표현을 판단에서 빼 버린다
  - 불만 접수나 상담 분류처럼 놓치면 손해가 큰 곳에서는 모델이 틀린 문장을 따로 모아 사람이 확인한다

○ **글에는 사람이 들어 있다**
  - 리뷰, 상담 기록, 메일에는 이름, 전화번호, 주소가 섞여 있다
  - 이런 글은 개인정보이므로 무엇을 모으고 얼마 동안 보관하는지 먼저 정해야 한다
  - 이 장의 실습이 합성 문장을 쓴 이유도 여기에 있다

### 핵심 정리

| 개념 | 한 줄 정리 |
|---|---|
| 토큰 | 문장을 자른 조각. 어디서 자를지는 사람이 정한다 |
| 한국어 토큰 | 조사와 어미가 붙어 남는다. "화면이"와 "화면은"이 다른 단어가 된다 |
| 단어 가방 | 행은 문장, 열은 단어, 칸은 횟수. 순서를 버리고, 칸의 대부분이 0이다 |
| 코사인 유사도 | 두 줄의 같은 칸끼리 곱해 더한 값을 두 줄의 길이로 나눈 값. 겹친 단어가 없으면 0이다 |
| TF-IDF | 여러 문장에 나오는 흔한 단어의 칸 값을 낮춘다. 겹친 단어가 없으면 여전히 0이다 |
| 임베딩 | 희소 데이터의 저차원 표현. 이웃 단어가 같은 단어끼리 벡터를 가깝게 놓는다 |
| 이웃 단어의 한계 | 함께 나오는지만 보므로, 이웃이 같으면 뜻이 반대인 문장도 가깝게 놓는다 |
| 가중치와 확률 | 절편과 아는 단어의 가중치를 더한 z를 시그모이드에 넣으면 긍정 확률이 된다. 모르는 단어는 덧셈에서 빠진다 |
| 데이터 편향 | 한쪽 라벨에만 나온 단어가 판단을 좌우한다. 데이터가 세상의 일부만 담는다 |

○ **다음 장** — 다음 단어를 예측하는 방식으로 문장을 만들어 내는 모델을 다룬다. 그럴듯한 문장이 왜 틀린 내용을 담을 수 있는지가 드러난다
