# 2주차 계획서 — AI 코딩 작업실 만들기: 내 컴퓨터에서 코드가 도는지 확인한다

## 1. 장의 역할

2주차는 3주차 이후 모든 실습이 딛고 설 바닥을 만든다. 목표는 학생을 개발자로 만드는 것이 아니라, 파이썬 파일 하나를 끝까지 실행하고 그 결과를 눈으로 확인하는 상태까지 데려가는 것이다.

이 주차의 성패는 설치 성공률에서 갈린다. 그래서 이론 절에 설치 순서와 학생이 실제로 막히는 지점을 구체적으로 적고, 로컬 설치가 끝나지 않은 학생을 위한 Colab 대체 경로를 같은 절에 붙인다. 도구 하나에 수업이 묶이지 않게 한다.

AI 코딩 도우미는 이 장에서 처음 쓴다. 첫 사용부터 규칙을 붙인다. 개인정보·비밀번호·API 키를 프롬프트에 넣지 않고, AI가 쓴 코드는 내가 실행해 확인한다.

대상은 학부 2학년이다. 1차시 이론 강의, 2차시 실습으로 나눠 진행한다.

## 2. 학습 목표

1. 개발환경을 이루는 네 가지(편집기, 파이썬, 터미널, 저장소)의 역할을 구분한다.
2. VS Code와 파이썬을 순서대로 설치하고, 막히는 지점 세 가지를 미리 안다.
3. 터미널에서 폴더를 옮겨 다니며 파이썬 파일 하나를 실행한다.
4. 로컬 설치가 막히면 Colab으로 같은 실습을 수행한다.
5. GitHub 저장소를 만들고 파일을 올린다.
6. AI 코딩 도우미에게 넣어도 되는 것과 넣으면 안 되는 것을 구분한다.
7. 오류 메시지를 맨 아랫줄부터 읽고, 파일 이름과 줄 번호를 찾아 그 줄을 연다.

## 4. 2차시 실습 설계

실습은 두 개다. 두 실습 모두 노트북에서 몇 초 안에 끝나고, 딥러닝 프레임워크를 쓰지 않는다.

### 실습 2.1 — 내 컴퓨터에서 파이썬이 도는지 확인한다

- 파일: `practice/chapter2/code/2-1-hello-ai.py`
- 하는 일: 학생이 적은 세 값으로 자기소개 문장을 만들고, 실행 환경(파이썬 버전·운영체제·처리장치)을 함께 출력한다
- 학생 조작 지점: 파일 상단의 `MY_NAME`, `MY_INTEREST`, `MY_GOAL`
- 성취 지점: 그림 파일 한 장이 생기면 "내 컴퓨터에서 파이썬이 끝까지 돌았다"가 증명된다
- 설계 제약: `input()`을 쓰지 않는다. 자동 실행 게이트가 입력을 기다리다 멈추기 때문이다
- 산출물: `results/hello_ai_card.png`

### 실습 2.2 — 오류 메시지 읽기 연습

- 파일: `practice/chapter2/code/2-2-read-error.py`
- 하는 일: 오류를 일부러 네 번 낸다(`NameError`, `TypeError`, `IndexError`, `ZeroDivisionError`). 파이썬이 준 메시지·파일 이름·줄 번호를 그대로 꺼내 읽는다
- 학생 조작 지점: 파일 상단의 `SHOW_FULL_TRACEBACK`
- 교훈 지점: `try/except`는 오류를 숨기려고 쓰는 것이 아니라 읽으려고 쓴다. `except: pass`는 이 수업에서 쓰지 않는다
- 산출물: `results/error_guide_table.png`

### 개념 그림 생성

- 파일: `practice/chapter2/code/2-0-concept-figures.py`
- 산출물: `results/fig2-1-code-to-result.png`, `results/fig2-2-error-reading.png`, `results/fig2-3-ai-boundary.png`
- 한글 폰트 도우미: `practice/chapter2/code/_krfont.py` (폰트가 없으면 영어 라벨로 자동 전환)
