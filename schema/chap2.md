# 2주차 계획서 — AI 코딩 작업실 만들기

## 1. 장의 역할

2주차는 이후 모든 실습의 기반을 만든다. 목표는 학생을 전문 개발자로 만드는 것이 아니라, 딥러닝 실습을 수행할 수 있는 최소 작업실을 만드는 것이다. 학생은 VS Code에서 Python 파일을 실행하고, GitHub 저장소를 만들고, AI 코딩 도구에게 코드 설명과 오류 수정을 요청한 뒤, 그 결과를 직접 검증한다.

이 장은 다음 원칙을 보여주는 시범 장이다.

- 추상적 설명보다 화면, 파일, 명령어, 오류 메시지 중심으로 설명한다.
- AI 코딩 도구를 쓰되, AI가 만든 코드의 최종 책임은 학생에게 있음을 반복한다.
- 개인정보, 비밀번호, API 키를 AI 도구에 입력하지 않는 습관을 2주차부터 형성한다.
- 설치 실패 학생을 위해 Colab 대체 경로를 둔다.

## 2. 학습 목표

학생은 수업 후 다음을 할 수 있어야 한다.

1. VS Code에서 폴더를 열고 Python 파일을 실행한다.
2. GitHub 계정으로 저장소를 만들고 파일을 올린다.
3. GitHub Copilot 또는 유사 AI 코딩 도우미에게 코드 설명을 요청한다.
4. 일부러 만든 오류를 AI에게 설명시키고, 수정된 코드를 직접 실행한다.
5. AI에게 입력하면 안 되는 정보와 실행 전 확인해야 하는 코드를 구분한다.
6. AI 협업 로그를 과제 형식으로 남긴다.

## 4. 실습 설계

### 필수 실습: `hello_ai.py`

학생 이름, 관심 분야, 오늘의 목표를 입력받아 한 문장으로 출력한다. 프로그램은 복잡하지 않아야 한다. 목적은 문법보다 "파일을 만들고 실행하고 결과를 확인하는 경험"이다.

### 오류 실습

학생은 의도적으로 다음 중 하나의 오류를 만든다.

- 따옴표 하나 지우기
- 변수 이름 하나 틀리게 쓰기
- 괄호 하나 지우기

이후 오류 메시지를 AI에게 붙여넣고 수정 요청을 한다. 단, AI 수정안을 바로 제출하지 않고 직접 실행해 확인한다.

## 5. 제출물

1. GitHub 저장소 링크 또는 Colab 링크
2. `hello_ai.py`
3. 실행 결과 화면 또는 로그
4. AI 협업 로그
5. 오류 수정 기록
6. 안전 점검표

## 6. 책임 있는 AI 체크

학생은 제출 전 다음 항목을 확인한다.

| 항목 | 확인 |
|---|---|
| 개인정보를 AI에게 입력하지 않았다 |  |
| 비밀번호, API 키, 학교 계정을 코드에 쓰지 않았다 |  |
| AI가 만든 코드를 직접 실행했다 |  |
| 오류 메시지를 숨기지 않고 기록했다 |  |
| 이해하지 못한 코드는 이해하지 못했다고 표시했다 |  |
| 코드가 파일 삭제나 외부 전송을 하지 않는지 확인했다 |  |
