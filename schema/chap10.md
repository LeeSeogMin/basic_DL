# 10주차 계획서 — 텍스트와 임베딩: 문장을 숫자로 바꾸기

## 1. 장의 역할

10주차는 9주차와 짝을 이룬다. 9주차에서 "이미지는 숫자다"를 픽셀값 64개로 확인했다면, 10주차에서는 "문장도 숫자다"를 단어 가방 표로 확인한다. 문장 한 줄이 벡터 한 줄이 되는 과정을 학생이 눈으로 따라가게 만드는 것이 이 장의 목표다.

말로 넘어가지 않는다. 토큰으로 쪼갠 결과를 그대로 찍고, 단어 가방 표를 찍고, 0인 칸이 몇 %인지 센다. TF-IDF로 잰 유사도가 0이 나오는 짝을 찾아, 뜻이 같아도 단어가 다르면 0이 된다는 것을 숫자로 본다. 임베딩이 왜 필요한지는 이 0에서 나온다.

임베딩 모델을 학습시키지 않는다. 내려받지도 않는다. `TruncatedSVD`로 TF-IDF 벡터를 2차원까지 줄여 "차원을 줄여 뜻을 요약한다"는 생각만 손으로 확인한다. 진짜 임베딩과 무엇이 다른지는 본문에 명시한다.

`torch`, `tensorflow`, `transformers`를 쓰지 않는다. 형태소 분석기도 설치하지 않는다. 조사와 어미가 단어에 붙은 채로 남는 것을 그대로 두고, 그래서 무슨 일이 생기는지 실습 10.2의 "모르는 단어" 목록에서 확인한다.

대상은 학부 2학년이다. 1차시 이론 강의, 2차시 실습으로 나눠 진행한다.

## 2. 학습 목표

1. 컴퓨터가 글자를 직접 다루지 못하는 이유를 설명한다.
2. 문장을 토큰으로 쪼개고, 한국어에서 이 작업이 왜 까다로운지 말한다.
3. 단어 가방 표의 행과 열이 무엇인지 읽고, 이 표가 무엇을 버리는지 설명한다.
4. 뜻이 같은 두 문장의 유사도가 0이 되는 경우를 직접 만든다.
5. 임베딩이 단어 가방의 어떤 한계를 겨냥하는지 설명한다.
6. 감성 분류기의 정확도와 혼동행렬을 읽는다.
7. 학습 문장이 치우치면 어떤 단어가 판단을 좌우하는지 가중치로 확인한다.

## 3. 1차시 이론 절 구성

| 절 | 제목 | 핵심 내용 | 시각 자료 |
|---|---|---|---|
| 1 | 컴퓨터는 글자를 모른다 | 글자도 숫자로 저장되지만 그 숫자는 뜻과 무관하다 | 그림 10.1 문장에서 벡터까지 |
| 2 | 토큰으로 쪼개기 | 토큰의 정의, 한국어의 조사·어미 문제, 형태소 분석기를 안 쓰는 이유 | 실습 10.1의 1단계 출력 |
| 3 | 단어 가방과 그 한계 | 행은 문장, 열은 단어, 순서를 버린다, 0의 비율 | 그림 10.2 단어 가방 표 |
| 4 | 임베딩이 무엇을 바꾸는가 | 뜻이 가까우면 벡터도 가깝게, 차원을 줄인다, 이 수업에서 하는 것과 안 하는 것 | 그림 10.3 문장 공간 |
| 5 | 텍스트 분류와 감성 분석 | 라벨이 붙은 문장으로 학습, 단어마다 가중치가 붙는다 | 실습 10.2의 단어 가중치 |
| 6 | 학습 문장이 치우치면 생기는 일 | 한쪽 라벨에만 나온 단어, 못 본 단어는 판단에 끼지 못한다 | 실습 10.2의 `word_weights.png` |
| 7 | 직접 움직여 보는 웹 자료 | 외부 시각 자료 4건 | 링크 표 |

4절에는 "이 수업에서 임베딩 모델을 학습시키지 않는다"를 명시한다. `TruncatedSVD`로 차원을 줄이는 것과 word2vec 같은 임베딩을 학습하는 것이 어떻게 다른지 한 문단으로 구분한다.

2절의 한국어 문단은 한 문단으로 짧게 쓴다. "배송이"와 "배송은"이 다른 단어로 잡힌다는 사실 하나만 남기고, 형태소 분석 이론으로 넘어가지 않는다.

## 4. 2차시 실습 설계

실습은 두 개다. 각각 노트북에서 몇 초 안에 끝난다. GPU가 필요 없다.

두 실습의 문장은 모두 수업용으로 직접 쓴 **합성 한국어 문장**이다. 실제 리뷰를 긁어오지 않는다. 인터넷에서 데이터나 모델을 내려받지 않는다.

### 실습 10.1 — 문장이 숫자로 바뀌는 과정

- 파일: `practice/chapter10/code/10-1-text-to-numbers.py`
- 데이터: 합성 한국어 문장 8개. 같은 단어를 공유하는 짝과 뜻만 같은 짝을 섞어 뒀다
- 학생 조작 지점: 파일 맨 위의 `MY_SENTENCES`, `MEANING_PAIRS`
- 하는 일 넷
  1. 문장을 토큰으로 쪼개 그대로 찍는다
  2. 단어 가방 표를 만들고 0인 칸의 비율을 센다
  3. TF-IDF로 바꾼 뒤 코사인 유사도 표를 찍고, 유사도가 0인 짝의 수를 센다
  4. `TruncatedSVD`로 2차원으로 줄여 평면에 점으로 찍는다
- 성취 지점: `MY_SENTENCES`를 자기 문장으로 바꾸면 지도의 점 배치가 바로 달라진다
- 겹침 처리: 2차원 좌표가 같은 문장은 한 점에 번호를 묶어 적고, 로그에 어느 문장이 겹쳤는지 남긴다
- 산출물: `results/sentence_map.png`, `results/bag_of_words.csv`, `results/sentence_similarity.csv`

### 실습 10.2 — 리뷰 긍정/부정 분류기와 헷갈리는 문장

- 파일: `practice/chapter10/code/10-2-sentiment.py`
- 데이터: 합성 리뷰 64개(긍정 32 + 부정 32). 같은 물건 이야기를 양쪽에 넣어, 감정을 나타내는 단어에서만 두 무리가 갈리게 만들었다
- 모델: `CountVectorizer(binary=True)` + `LogisticRegression`. 기준선은 `DummyClassifier`
- 학생 조작 지점: `MY_TRICKY_SENTENCES`, `TEST_RATIO`, `NEAR_BAND`
- 하는 일 다섯
  1. 훈련 44개와 테스트 20개로 나눈다
  2. 학습하고 기준선·훈련·테스트 정확도와 혼동행렬을 낸다
  3. 일부러 어렵게 만든 문장 8개(반어·부정어·섞인 감정·에두른 칭찬)를 넣어 예측 확률을 본다
  4. 확률이 0.5 근처인 문장을 모아 그림으로 남긴다
  5. 단어마다 붙은 가중치를 꺼내, 한쪽 라벨에만 나온 단어가 판단을 좌우한다는 것을 그림으로 본다
- 교훈 지점 셋
  - 훈련 정확도 1.000, 테스트 정확도 0.650. 단어 수가 적으면 훈련 문장을 외운다
  - 어려운 문장을 맞혀도 이유가 맞는 것은 아니다. 아는 단어의 가중치를 더한 결과가 0.5를 가까스로 넘거나 못 넘었을 뿐이다
  - 조사와 어미가 바뀌면 아는 단어가 모르는 단어가 된다("화면이"는 알고 "화면은"은 모른다)
- 산출물: `results/sentiment_confusion.png`, `results/confusing_sentences.png`, `results/word_weights.png`, `results/sentiment_results.csv`, `results/confusing_sentences.csv`, `results/word_weights.csv`
